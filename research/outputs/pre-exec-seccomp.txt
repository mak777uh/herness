# F-0024 — pre_exec не работает в нашем ядре, инструмент запускается только без него
# Снято прогонами: core-rs\run.ps1 -Mode spawn-check, ядро vmlinuz-own-rng, WHPX
без песочницы: код Some(1)
с песочницей: ошибка Function not implemented (os error 38)
литеральный /init seal: код Some(0)

# Что это значит:
#   * обычный spawn и spawn по литеральному пути работают (статус получен);
#   * тот же spawn с Command::pre_exec падает ENOSYS, причём замыкание НЕ запускается:
#     метки, которые оно писало в /pe.log через open/write/close, в файле не появились;
#   * прямой fork() в гостевой системе работает (fork: ok, статус 0), поэтому дело не в fork,
#     а в том, как именно std строит запуск с замыканием. Причина не установлена.
#
# Решение: фильтр ставит сам процесс инструмента первой строкой (harden_self), а не родитель
# через pre_exec. Отсутствие фильтра видно в журнале как часть результата инструмента.
#
# После правки (core-rs\run.ps1 -Mode loop):
инструмент: ok d105fb5d1c0ce17b09f25aba9e07bb8bdf9c404158e993e6d615f855f2072bef [песочница: фильтра нет, ядро без seccomp]
# и в stderr самого инструмента:
sandbox: фильтр UDP не поставлен (ядро без seccomp: seccomp: Invalid argument (os error 22))
