# Гейт «решения»: механизм нельзя внедрить без источника и контроля

Правило из docs/TOP-REVIEW.md §5 стало исполняемым.

| проверка | что ловит |
|---|---|
| нет источника | «правило по памяти» — механизм, которого в источнике может не быть |
| нет отрицательного контроля | внедрение, эффект которого ничем не проверен |
| внедрено без утверждения | изменение без записи в CLAIMS.md |
| утверждение не существует | ссылка на несуществующий C-xxxx |
| статус вне {adopted,planned,rejected} | нерешённое решение, замаскированное под решение |
| повтор id | два решения под одним номером |

## Отрицательный контроль самого гейта

`
python bin/check_adoptions.py --self-test
[ok] self-test: 5 отказов на 5 подложенных дефектов
`

Склад решений: lab/adoptions.json — 7 записей, 5 внедрено (A-0001…A-0005), 1 отклонено (A-0006,
подсказка о тупике), 1 отложено (A-0007, clarify). У каждой внедрённой записи есть утверждение и
контроль, поэтому гейт проходит: [ok] решения: 0 проблем.

Врезка: python bin/hs.py gates -> «[ok] решения: 0 проблем».
