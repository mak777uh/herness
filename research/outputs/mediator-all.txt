# Посредник: все шесть инструментов

## Что сделано

Решение о доступе принимает политика, а не код инструмента. У каждого инструмента
проверка стоит в одном месте и формулирует отказ словами политики.

| инструмент | что спрашивает политику | ресурс |
|---|---|---|
| read | `policy_allows("read", "read", …)` | `file:<путь>` |
| write | `policy_allows("write", "write", …)` | `file:<путь>` |
| search | `policy_allows("search", "read", …)` | `file:<каталог>` |
| list | `policy_allows("list", "list", …)` | `dir:<каталог>` |
| seal | `policy_allows("seal", "seal", …)` | `file:<путь>` |
| netprobe | `policy_allows("netprobe", "net", …)` | `net:<адрес>` |

## Проверки

| проверка | результат |
|---|---|
| политика согласована | 17 правил |
| политика в коде = политика в файле | 12 правил совпадают |
| код не выходит за замыкание | 0 нарушений |
| тесты Rust | 51 проходит |
| прогон в комнате на закалённом ядре | PASS |

## Граница

Посредник проверяет, что действие разрешено политикой. Он **не доказывает**, что код
инструмента реализует политику правильно — это следующий шаг (формальная верификация).
