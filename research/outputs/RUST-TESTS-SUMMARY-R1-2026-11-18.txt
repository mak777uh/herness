# RUST-TESTS-SUMMARY-R1 — сводка не путает зелёный бинарник с красным

Дата: 2026-11-18. Найдено при красном репро `ROOM-EXTERNAL-TAINT-R1`.
Изменение: `bin/rust_tests.py`, `tests/test_rust_tests_summary.py`.

## Наблюдение

В красном прогоне cargo печатает несколько строк `test result`, сначала зелёный
lib-бинарник, затем красный интеграционный:

```text
test result: ok. 133 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
test result: FAILED. 0 passed; 2 failed; 0 ignored; 0 measured; 0 filtered out
```

Старый разбор брал **первое** вхождение `(\d+) failed`:

```text
$ grep -oE '[0-9]+ failed' <сохранённый вывод> | head -1
0 failed
```

и печатал `[FAIL] провалов: 0` при rc=1. Гейт не был ложно зелёным (rc=1),
но объяснение было ложным: агент читает «0» и ищет причину не там.

## Исправление

`bin/rust_tests.py`: `parse_results(out)` суммирует:
- `passed` по всем строкам `test result: ok. N passed`;
- `failed` по всем строкам `test result: FAILED. N passed; M failed`.

Если ни одной строки `test result` нет (ошибка сборки), печатается
`провалов: неизвестно`, а не `0`.

## Проверка

Команда: `python tests/test_rust_tests_summary.py`
rc=0
```text
[ok] зелёный вывод: (136, 0)
[ok] lib зелёный, интеграционный красный: (133, 2)
[ok] два красных бинарника суммируются: (0, 7)
[ok] ошибка сборки не выдаёт себя за ноль: (0, 0)
провалов: 0
ВЕРДИКТ: PASS — провалы суммируются по всем тестовым бинарникам
```

Красный прогон после исправления: `[FAIL] провалов: 2`, rc=1.
Зелёный прогон: `[ok] тестов пройдено: 141, провалов 0`, rc=0.

## Граница

Это исправление сообщения и разбора, а не ослабление гейта: rc и раньше был 1.
Оно не доказывает, что тесты полны, и не заменяет полный прогон на машине с WSL:
в быстром профиле `rust_tests.py` остаётся SLOW-командой.
