[HIGH] metadata-only критерий может дать PASS без содержательной проверки
bin/accept.py:363 добавляет integrity-строку всегда, а bin/accept.py:382 считает PASS по всем
строкам. Поэтому criterion без содержательных строк получает PASS от одной integrity-строки.
Воспроизведение: accept.check({"task":"x","host_match":True}, parse_journal(empty_valid_hsj2)[0])
вернул True и только ('журнал прочитан полностью', True, ...). HEAD на том же критерии
возвращал False []. CLI с пустым корректным HSJ2 и {"task":"x","host_match":true} также
напечатал PASS, rc=0. Среди текущих accept/**/*.json таких критериев не найдено, но публичный
API/CLI regression остаётся. Требуется regression test для task-only/comment-only/
host_match-only и пустого чистого журнала; integrity-строка не должна создавать PASS при
отсутствии содержательных проверок.

[MEDIUM] direct-callers fixture не изолирует заявленный UTF-8 tail
tests/test_host_journal_accept_integrity.py:113 добавляет frame(seq=7) после data_journal(LINES),
который уже содержит семь записей и commit seq=7. Parser останавливается на нарушении seq до
UTF-8 decode. Для fixture получено problems=['оборванный хвост 24 байт']; при следующем seq=8
получено ['invalid UTF-8 в записи 8', 'оборванный хвост 24 байт']. Контроль доказывает generic
damaged-tail отказ прямых callers, но не заявленный однофакторный invalid UTF-8 из prereg.
Требуется отдельная correction-попытка с seq=8 и явной проверкой invalid UTF-8, без изменения
sealed E-0056 corpus.
