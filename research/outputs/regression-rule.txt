# Регрессия после правила «собери ответ из нескольких результатов»

Серия 1 (8 задач: реестр, отказы, ADR) прогнана заново на том же образе и той же модели.

| задача | до правила | после правила |
|---|---|---|
| T-claim-C-0196 | PASS | **FAIL** — ответ «test» верен, но в ответе нет номера C-0196 |
| T-claim-C-0205 | PASS | PASS |
| T-claim-C-0211 | PASS | PASS |
| T-fail-F-0029 | PASS | PASS |
| T-fail-F-0033 | PASS | PASS |
| T-fail-F-0034 | PASS | PASS |
| T-adr-ADR-0052 | PASS | PASS |
| T-adr-ADR-0053 | PASS | PASS |

принято: 7 из 8 (было 8 из 8).

# Что это значит:
#   правило «собери ответ» не сломало ничего: семь задач прошли как раньше.
#   Единственное расхождение — не от правила, а от формы ответа: модель написала
#   «test — /mnt/CLAIMS.md:222», то есть назвала файл и строку, но не повторила номер
#   утверждения C-0196. Опора ищется в тексте ответа, и номера там нет.
#
#   Это третий случай одного и того же класса (F-0037, F-0060, сейчас):
#   требование «назови источник» модель выполняет по-разному, а приёмка сверяет ответ,
#   а не смысл. Лечится не правилом, а тем, что опора должна браться из результатов,
#   связанных с ответом, а не только из его текста.
