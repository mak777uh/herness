## Как это ложится на нас

**Наш интерфейс сейчас — CLI и markdown-отчёты** (`docs/DEPTH.md`, класс «Интерфейс», ступень D0).
Веб-приложения у нас нет, и никто им не пользуется: внешних пользователей ноль.

Отсюда по первым принципам:

1. **Потребность сейчас — «прочитать журнал и утверждения», а не «интерактивное приложение».** Для
   этого дешевле статическая генерация HTML из markdown на Python (у нас уже есть все данные), чем
   React-приложение с состоянием.
2. **React + shadcn оправданы, когда появится интерактив:** фильтры по прогонам, сравнение ревизий,
   просмотр рецензий в браузере. Пока этого нет — это второй тулчейн (у нас уже node ради
   `@playwright/mcp`) без выигрыша.
3. **Python для бэкенда совпадает с нашим ADR-0012** (Python для L2/L3). Расхождений нет.
4. **NestJS/Hono** к нам не относятся: у нас нет ни веб-бэкенда, ни нагрузки. Это совет для продуктовой
   работы, а не для прибора.

## Что меняется

**Сейчас — ничего.** Записал как кандидата на момент, когда понадобится веб-просмотр: React + shadcn +
tanstack, и только если статического HTML окажется мало.

**Условие, при котором совет применяется:** появляется задача показать журнал/утверждения/рецензии
не в терминале, с фильтрами и переходами. Тогда порядок: (1) статический HTML-отчёт из наших данных;
(2) если нужен интерактив — React + shadcn по совету; (3) бэкенд остаётся на Python.
