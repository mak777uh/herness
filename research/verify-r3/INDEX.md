а не про код. Отчёты — рядом (`<имя>.md`, `.json`, `.receipt.json`).

Репозиториев с ≥3 строгих: **2 из 5** (порог был 3). С хотя бы одной командой: **1 из 5** (порог был 2).
Повторный прогон на simdjson дал тот же json кроме `generated_at` — да.

## Что это значит

Порог гипотезы **не пройден**: поверхность нашлась у двух репозиториев из пяти, а команда рядом —
только у duckdb. Но суммарный счёт говорит другое: 17 утверждений против 2 на «обычных» README.
То есть числа в прозе есть там, где проект меряется скоростью (11 у simdjson), а вот команды
воспроизведения в README не стоят — они живут в `docs/`, `benchmark/` и CI.

Отсюда практический вывод: прибор показывает не «плохой README», а разрыв между заявленным числом
и местом, где его можно проверить. Для simdjson это 11 чисел и 0 команд — материал для разговора,
а не приговор.
