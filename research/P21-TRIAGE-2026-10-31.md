# P21: разбор ответов агентов и что из этого проверено у нас (31.10.2026)

Пришли три независимых прохода по шести блокам. Ниже: что я принял, что отверг, и что проверил
локально за десять минут — потому что три источника согласны между собой, но не заменяют замер.

## Три факта, проверенные у нас (и они меняют решения)

### 1. KVM в WSL2 есть — microVM не заблокированы

```
$ wsl -e bash -lc "ls -l /dev/kvm; grep -c -E 'vmx|svm' /proc/cpuinfo"
crw-rw---- 1 root kvm 10, 232 /dev/kvm
32
```

Все три отчёта спорили: «Firecracker работает через WSL2, цена — один вложенный хоп» / «только
сторонняя инструкция» / «совместимость не установлена». Локальная проверка снимает главную половину
вопроса: **устройство `/dev/kvm` присутствует**, значит «на Windows нет KVM» — неверно; верно
«KVM появляется внутри WSL2».

Остаётся вторая половина — запустить Firecracker и посмотреть. Это не проверено.

### 2. В ядре 6.18.60 прав на UDP у Landlock нет — подтверждено исходником

```
$ grep -n 'LANDLOCK_ACCESS_NET' include/uapi/linux/landlock.h
342:#define LANDLOCK_ACCESS_NET_BIND_TCP		(1ULL << 0)
343:#define LANDLOCK_ACCESS_NET_CONNECT_TCP		(1ULL << 1)
```

Это первичный источник, а не мнение: в нашем дереве ядра есть **только TCP**-права. Отчёты
утверждают, что UDP появляется в ABI 10 (Linux 7.2) — с нашим исходником это сходится. Значит:

- на нашем ядре UDP закрывается **не Landlock**, а seccomp-запретом `socket(AF_INET, SOCK_DGRAM)`;
- в фильтре обязательна маска типа: `(type & 0xF) == SOCK_DGRAM`, иначе `SOCK_CLOEXEC`/`SOCK_NONBLOCK`
  проходят мимо правила (это же независимо отметили два отчёта — и это правда, флаги лежат в `type`).

### 3. Аппаратное ускорение есть, и наши числа загрузки были пессимистичны

```
qemu-system-x86_64 -accel whpx ... (ядро C, initramfs тот же)
```

| ядро | TCG (было) | WHPX (сейчас, 3 прогона) |
|---|---:|---|
| C, до init | 1,30 / 1,33 с | 0,78 / **0,53** / 0,54 с |
| D (с сетью), до init | 1,95 / 1,93 с | 0,67 / 0,71 / 0,69 с |
| цена сети | +0,6 с | **+0,15 с** |

То есть **+0,6 с** — это цена сети *при программной эмуляции*. С ускорением она вчетверо меньше.
Утверждение C-0127 остаётся верным только с указанием условия; я его поправил, а не оставил
обобщением.

## Что из отчётов принято как факт

| факт | откуда | почему принят |
|---|---|---|
| UDP в Landlock — только ABI 10 (Linux 7.2); ABI 7 — TCP | три отчёта + наш исходник | первичный источник у нас, отчёты согласны |
| Нет стандартного `spawn` в WASI; wasmtime не запускает внешний ELF | три отчёта согласны | согласие независимых проходов; отрицание не закрыто полностью |
| Firecracker требует KVM; официально — только Linux | три отчёта | согласие, ссылка на документацию проекта |
| Вложенная виртуализация WSL2 документирована; `/dev/kvm` есть | два отчёта + наш замер | проверено у нас |
| Нет стандарта, где «команда перевывода + ожидаемый дайджест + подпись» обязательны в одном объекте | три отчёта | ближайший — in-toto (`COMMAND` в link-метаданных); подпись и включение в лог ≠ истина |
| SWHID — intrinsic-идентификатор содержимого; WARC — формат, а не модель доверия; 404 ≠ «не существовало» | два отчёта | согласуется с нашей практикой «отсутствие — отдельный тип» |
| Четыре разных статуса отсутствия: `not_found` / `access_error` / `archive_not_found` / `absence_unproven` | один отчёт | полезная таксономия, лучше нашего бинарного `absence` |

## Что отвергнуто или отложено

- **«AgentDojo: 949 stateful multi-turn эпизодов»** — противоречит другому отчёту того же круга
  («97 задач, 629 тестовых случаев») и известной публикации. Принимаю 97/629, а 949 — как
  непроверенное. Это ровно тот случай, когда три отчёта врут по-разному и прав тот, кто сошёлся с
  первичным источником.
- **Числа ASR нельзя складывать**: 24 % (ReAct + GPT-4), «< 25 % у лучших агентов», 8,09 % / 11,96 %
  (pooled FP16), 0,2 → 43 % (смена системного промпта), 0,2 % / 0,0 % / 12,9 % (CaMeL individual /
  multi / без защиты), 77 % против 84 % (польза). Это разные эксперименты с разными наборами и
  метриками. В реестр они пойдут по отдельности, с условиями, и **никогда** как «инъекции работают
  в N % случаев».
- **«Rule-only ~30 %, decode+classify ~92 %»** — вендорский блог с числами, помечен как заявление
  вендора. В решение не идёт.
- **Firecracker реально работает в WSL2** — не проверено; `/dev/kvm` есть, запуска не было.

## Что это меняет в решениях

1. **UDP:** правило — seccomp на `socket()` с маской типа; Landlock ABI 10 — когда перейдём на 7.2+.
   Без этого «сеть в ядре» = неограниченный UDP, и это не гипотеза, а следствие нашего же исходника.
2. **Формат свидетельства:** свой тонкий формат, не in-toto. Поля: `source_url`, `fetched_at`,
   `http_status`, `body_sha256` на стороне источника; `command`, `expected_digest` на стороне
   утверждения. Подпись и inclusion proof — опционально и **не** заменяют истину.
3. **`absence`:** четыре статуса вместо одного; «404» и «не открылось» перестают сливаться в «нет».
4. **WASI:** альтернатива не проходит по нашему списку примитивов (нет `fork/exec`, нет внешних
   процессов). Отрицание не закрыто полностью — решающий опыт: собрать `hs-core` под
   `wasm32-wasip1`. Это не сделано.
5. **microVM:** блокер снят локально (KVM есть). Но у нас уже есть WHPX, то есть аппаратное
   ускорение без WSL — вопрос «нужен ли microVM» стал вопросом цены изоляции, а не доступности.
6. **Все наши прошлые числа про загрузку и цену сети** получили условие: «без ускорения (TCG)».
   С ускорением: 0,54 с и +0,15 с.

## Что осталось открытым (и это нормально)

- Запуск Firecracker в WSL2 — 30 минут работы.
- `hs-core` под wasm32-wasip1 — 2–4 часа.
- Полная таблица Landlock ABI → версия ядра — не нужна для решения: нам хватает «UDP с ABI 10».
- Юридическая сила WARC/HAR — вне нашей задачи.

## Границы

- Локальные проверки: `/dev/kvm` (одна машина), исходник ядра (наше дерево 6.18.60), WHPX (три
  прогона на ядро, один хост). Это замер, а не бенчмарк.
- Ответы агентов приняты как **указатели**, а не как доказательства: в реестр они войдут записями
  `evidence/` с URL и отпечатком, когда этот механизм появится. Пока — этот файл, и он
  самоссылочный, как и 38 предыдущих.
