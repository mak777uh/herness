# P36 — разбор: программный вызов инструментов и цена композиции

**Дата:** 07.11.2026. **Материал:** четыре независимых прохода по заданию P36.
**Правило:** чужие числа — вторичны; в `CLAIMS.md` идут только наши измерения.

## 1. Главное: композиция имеет измеренную границу

Все четыре ответа приводят один и тот же отрицательный результат Anthropic, и это самое ценное
из всего разбора:

| задача | стоимость | точность |
|---|---|---|
| 75 инструментов, project management | **−38 %** входных токенов | без изменений |
| τ²-bench (1–2 последовательных вызова за ход) | **+8 %** | без изменений |

**То есть композиция окупается не всегда, а только когда за шаг нужно много обращений или
большие промежуточные данные.** Это измеренный, а не предположенный факт.

## 2. Что сходится во всех четырёх

| утверждение | подтверждение |
|---|---|
| композиция экономит токены на многошаговых задачах | −24 % (BrowseComp), −38 % (75 инструментов), −77 % (Amazon, 26 528 вызовов) |
| на коротких задачах она **дороже** | τ²-bench: +8 % без выигрыша |
| CodeAct выигрывает на многошаговых, но **не на атомарных** | атомарные: CodeAct 76,7 % против JSON 82,7 % — **JSON лучше** |
| качество описания инструмента влияет измеримо | удаление краткого описания: **−5,7 п.п.**; типов: −3,1; описания аргументов: −2,0 |
| готовой среды «композиция с изоляцией и проверкой» нет | все четыре |
| доля отказов именно из-за отсутствия композиции не измерена | все четыре |

## 3. Что противоречит нашему плану

**Атомарные вызовы: CodeAct 76,7 % против JSON 82,7 %.** То есть **для простых задач код хуже**.

Это прямо говорит: **вводить композицию как замену пошаговому протоколу — ошибка**. Её место —
отдельный режим для задач, где за шаг нужно много обращений.

## 4. Что берём в план

| механизм | источник | отрицательный контроль |
|---|---|---|
| **условная композиция**: пошаговый `TOOL` остаётся по умолчанию, композиция — только для задач с ≥3 зависимыми обращениями | Anthropic PTC (−38 % против +8 %), CodeAct | те же задачи в пошаговом режиме: если выигрыша нет — механизм не работает |
| **контракт инструмента с примерами**: схема, типы, границы, 1–5 примеров вызова | ToolSandbox (−5,7 п.п. без описания), Anthropic (72 % → 90 % с примерами) | те же задачи до и после добавления примеров, без изменения промпта и модели |
| **разложение молчаний до композиции** | наш собственный пробел | 17 молчаний разделить на причины до того, как приписывать их отсутствию композиции |

## 5. Что меняет порядок

Было: программный вызов → исполнение → реестр → синтез.

Стало: **контракт инструмента с примерами** → разложение молчаний → и только потом композиция.

Причина: контракт дешевле (не нужен исполнитель) и уже измерен (−5,7 п.п. без описания). А
композиция требует исполнителя и окупается только на длинных задачах, которых у нас пока нет.
