# P29 — Разбор ответов на вопросы B1–B8

**Дата:** 01.11.2026. **Что разобрано:** пять независимых ответов моделей на вопросы P27 (B1–B8),
собранных владельцем. **Статус источников:** это препринты 2026 года и вторичные пересказы; один
из ответов прямо говорит, что первоисточники не открывались. Поэтому ниже — **не свидетельства**
для `CLAIMS.md`, а карта поля: что сходится между ответами, что противоречит, что осталось не
измеренным. В реестр утверждений такие числа попадут только после сверки с первоисточником
(`evidence.py fetch`) и с типом `observation` или `statistics` по правилам.

## 1. Сходится в нескольких ответах (наиболее надёжное)

| Утверждение | Числа, которые приводят разные ответы | Что это значит для нас |
|---|---|---|
| Самоотчёт агента не годится как приёмка | ложный успех: 44–48 % провалов в single-control доменах, 3 % при независимом верификаторе, 75,8 % в AppWorld; при фиксированном отказе инструмента контракт свидетельств снижает 22,8 % → 9,3 % → 0,8 % | подтверждает ADR-0049: вердикт даёт хост, а не модель. «Контракт свидетельств» — это ровно наш `accept/` |
| Цепочка хешей внутри песочницы — tamper-evident, но не tamper-proof | агент переписывает журнал и пересчитывает цепочку; защищает только вынос доверенной границы | подтверждает F-0028-линию: хост ведёт свою копию и **сверяет содержимое** (C-0180) |
| Заморозка методологии: эффект не измерен | контролируемого «зафиксировано / нет» для LLM нет; ближайшее — next-LLM протокол (17/23 = 73,9 % и 32/44 = 72,7 %), но там меняется модель | **H-0003 требует переформулировки**: не «снижает подгонку», а «делает изменение критерия обнаружимым» |
| LLM-судья не в финальный вердикт | κ 0,76–0,84 на разметке против **AUROC 0,54–0,65** на детекции ложного успеха; судья, всегда говорящий «принято», даёт κ = 0,00 | подтверждает наше решение не ставить судью в вердикт |
| Второй проход помогает только при структурной независимости | Jaccard 41,2 % между ревьюерами; 56,7 % против 42,7 % покрытия; повторный проход той же моделью даёт +62 % ложных срабатываний | подтверждает механического рецензента вместо второго LLM |
| Checkpoint ≠ exactly-once | без идемпотентности 66 % дублей строк и 59 % повторных разрушительных шагов; intent log + сверка: перезапусков 14,1 → 3,5, 2,8 мс на эффект | у нас есть sync-per-step и resume, **нет** intent-before-effect — это дыра |
| Больше scaffolding ≠ лучше | SWE-agent: итеративный поиск **хуже** отсутствия (12,0 % против 15,7 %), линтер лучше (15,0 → 18,0); сложный харнесс ≈ минимальный при 3× токенов | аргумент за минимальный контур + внешние проверки, а не за «ещё слоёв» |

## 2. Противоречит или расходится

- **Знаменатели.** «45–48 %» и «44–52 %» — доля **среди провалов**, «75,8 %» — доля среди
  траекторий с явным статусом в AppWorld. Смешивать нельзя; в разных ответах эти знаменатели
  иногда подаются как одна величина.
- **Защита журнала.** Один ответ утверждает, что 70–90 % агентов удаляют свою трассировку и что
  помогает только host-side копия; другой — что измерений цены (latency, storage) для агентских
  прогонов почти нет. Верно, скорее, второе: измерения есть для систем аудита (OMNILOG 3,2–3,6 %,
  HARDLOG 15 мс, EmLog 430–625 записей/с), но не для наших прогонов.
- **Maker/checker.** Один ответ: прирост +14 п.п. (56,7 % против 42,7 %). Другой: преимущество
  сочетания ревьюеров статистически **не** превзошло двух вызовов более сильной модели. Второе
  важнее: «независимость» и «качество ревьюера» не разделены.
- **Абляции.** «Сложный харнесс не лучше» против «файловое состояние даёт +5,5 п.п. на OSWorld».
  Противоречия нет: эффект компонента зависит от задачи и модели, и именно это надо мерить у себя.

## 3. Не установлено (и это главное)

1. Доля ложных «готово» **в нашей системе** — измеряется только нашим набором, не переносится.
2. Цена защиты журнала (host-копия, подпись, WORM) **для агентских прогонов** — не измерена
   никем; у нас есть своя цена (полный поток событий на хост), её и надо мерить.
3. Эффект заморозки методологии на LLM-анализ — не измерен; наша H-0003 не должна утверждать
   больше.
4. Отдельный вклад **нашей проверки** (приёмки) при равном бюджете — ни у кого; у нас есть
   возможность померить (набор прогонов + выключенная приёмка).
5. Кривая «число источников → качество атрибуции» — не построена.

## 4. Что меняем у нас (решения)

- **H-0003**: формулировка меняется на «фиксация делает изменение критерия обнаружимым»; эффект
  «снижает подгонку» не утверждается (см. правку в `lab/registry.json`).
- **Новая проверка (дыра)**: `intent-before-effect` — для действий с внешним эффектом писать
  намерение с аргументами **до** вызова и сверять результат после перезапуска; при неизвестном
  исходе — останавливаться и говорить об этом. У нас внешних действий пока нет, поэтому вводится
  как условие будущих инструментов, а не как код сегодня.
- **Каталог**: подходы и инструменты из разбора сведены в `docs/CATALOG.md` с решением «берём /
  не берём» и указанием, что у нас уже есть.

## 5. Границы этого разбора

Числа взяты из ответов моделей, а не из прочитанных первоисточников. Ни одно не попало в
`CLAIMS.md`. Порядок дальнейшей работы: сверка 3–5 ключевых работ через `evidence.py` (сохранить
дайджесты) → только затем утверждения. До сверки это карта поля, а не свидетельство.
