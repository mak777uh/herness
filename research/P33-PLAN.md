# План экспериментов P33: конвейер доверия к инструментам

**Дата:** 07.11.2026. **Основание:** P31-TRIAGE, P32-TRIAGE, `research/INSIGHTS.md` (F-10…F-12).
**Правило:** каждый эксперимент имеет отрицательный контроль и артефакт; порядок меняется по результатам.

## Что проверяем и зачем

Гипотеза, которую надо проверить до всякой генерации инструментов:

> **Конвейер доверия (реестр → pre-flight → canary → рабочий набор → отказ) можно построить и
> проверить на СУЩЕСТВУЮЩИХ инструментах, не имея исполнения кода.**

Если это так, к моменту появления синтеза у него уже будет проверенная приёмка. Если нет — узнаем
это до того, как потратим работу на генерацию.

## Эксперименты

### E1. Реестр инструментов append-only

**Что строим.** `lab/tools/registry.jsonl`: одна запись на инструмент — имя, версия, контракт
(что делает, что возвращает), хеш среды (манифест комнаты), происхождение, статус.

**Что проверяем.**
- каждая запись имеет хеш среды и происхождение;
- агент не может писать в реестр (только хост);
- запись неизменяема: правка — новая запись со ссылкой на предыдущую.

**Отрицательный контроль.** Подложить запись без хеша среды и запись без происхождения — гейт
обязан отвергнуть обе.

**Артефакт.** `research/outputs/registry-check.txt`.

### E2. Pre-flight: поиск по имени И контракту

**Что строим.** `bin/preflight.py`: по описанию нужной возможности возвращает подходящие
инструменты из реестра — сначала по имени, потом по контракту.

**Что проверяем.** Находит ли поиск нужный инструмент там, где поиск по имени не находит.

**Отрицательный контроль.** Запрос, для которого подходящего инструмента нет — pre-flight обязан
вернуть пусто, а не «ближайшее похожее».

**Почему имя остаётся.** CRAFT: удаление имени функции из поиска роняет точность на 6,6 п.п.
Контракт — второй канал, не замена.

**Артефакт.** `research/outputs/preflight-check.txt`.

### E3. Canary и протухание по событию

**Что строим.** Для каждого инструмента реестра — короткая канарейка (детерминированная проверка
поведения). При смене хеша среды все инструменты становятся `stale` до прохождения канарейки.

**Что проверяем.** Подменить образ комнаты → инструменты становятся `stale`; вернуть образ →
канарейка проходит, статус возвращается.

**Отрицательный контроль.** Изменить образ, не влияющий на инструмент (например, добавить
неиспользуемый файл) — инструмент **не должен** становиться `stale`.

**Артефакт.** `research/outputs/canary-check.txt`.

### E4. Ограниченный рабочий набор и архив

**Что строим.** Рабочий набор — не больше N инструментов; вытесненный уходит в `archived`,
остаётся искомым.

**Что проверяем.** Вытеснение не удаляет; архивный инструмент находится pre-flight и
воскрешается.

**Отрицательный контроль.** Запросить инструмент, которого нет ни в рабочем наборе, ни в архиве —
должен быть отказ, а не «взяли что было».

**Артефакт.** `research/outputs/workset-check.txt`.

### E5. Отказ как протокол на невыполнимых задачах

**Что строим.** Серия задач, которые **невозможно** решить в комнате (искомого нет). Верный
исход — `BLOCKED`, а «готово» считается обходом.

**Что проверяем.** Доля отказов на невыполнимых задачах. По литературе (ImpossibleBench) опция
отказа снижает обход с 54 % до 9 %.

**Отрицательный контроль.** Та же серия, но с выполнимой задачей — там отказ **неверен**.

**Артефакт.** `research/outputs/refusal-series.txt`.

### E6. Регрессия: конвейер не ломает существующее

**Что проверяем.** Серия 1 (8 задач) после всех правок — 8 из 8.

**Отрицательный контроль.** Если стало меньше — правка сломала, а не улучшила.

**Артефакт.** `research/outputs/pipeline-regression.txt`.

## Порядок и правила смены

1. E1 → E2 → E3 → E4 (зависимость по данным).
2. E5 можно делать параллельно: он не зависит от реестра.
3. E6 — после каждого изменения, затрагивающего цикл.
4. **Смена порядка:** если E2 покажет, что поиск по контракту не даёт ничего сверх имени, E3 и E4
   всё равно делаются (они про протухание и раздувание, не про поиск), но F-12 пересматривается.
5. **Стоп-условие:** если E1 не даёт проверяемого гейта (реестр нельзя проверить машинно), дальше
   не идём — сначала чиним проверку.

## Что этот план НЕ делает

- не генерирует инструменты (нет исполнения кода);
- не трогает сеть;
- не меняет протокол цикла.
