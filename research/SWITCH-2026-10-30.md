## Что это

> «switch is a harness framework for decision models like Jev. It gives a decision model an agent loop for
> **finite choices**. Your code turns the state of a task into **typed questions**… and the model picks
> the answers… A decision model answers typed questions with probabilities and **writes no text**, so it
> cannot generate the tool calls that a coding agent harness such as Pi relies on. switch **generates the
> tool calls for it in code**, and the model only picks one from that finite set.»

То есть: не «модель пишет JSON-вызов», а «код перечисляет варианты, модель выбирает». Вызов формирует
программа.

## Чем это интересно именно нам

| наш пункт | что даёт switch |
|---|---|
| **ADR-0029 (ядро)** | второй полноценный кандидат в ядро: не «свободный цикл с инструментами», а «цикл конечных выборов» |
| **Т-1.1/Т-1.2 (сколько инструментов)** | вопрос снимается структурно: модель не видит 25 инструментов, она видит **короткий список следующих шагов**, который код строит из состояния |
| **Т-0.3, Т-2.6 (мусорный вызов)** | decision-модель **не пишет текст** — она физически не может выдать битый вызов или «спам в вызове», как в разобранном случае с `functions.exec_command` |
| **Т-2.1 (схема)** | вопросы типизированы, ответы — вероятности; синтаксических ошибок в вызове не бывает |
| **Т-5.3 (цена контекста)** | пример rubric-judge: вместо «200 страниц в контекст» модель **навигирует** по документам и берёт нужное. Это довод про цену, а не про качество |
| **наш `reply.py`** | у нас уже есть тип `OPTIONS`; switch обобщает его до «каждый шаг — выбор из конечного набора» |

## Цена, которую видно сразу

1. **Интеллект переезжает в программу.** «Your code turns the state into questions» — значит под каждую
   задачу нужен код, который перечисляет осмысленные варианты. Меньше токенов — больше нашего времени.
2. **Decision-модели слабее там, где нужно рассуждение.** В разборе Jev (`[197746]` в чате) прямо
   сказано: на coding и reasoning паттерн-модели проседают. Наш домен — анализ и проверка, не только
   выбор из списка.
3. **244 звезды за 5 дней** — это волна, а не проверка. Заявления README не воспроизводились.

## Что из этого следует

Не менять ядро. Но **добавить в ADR-0029 второй альтернативный кандидат с внятным описанием** — до сих
пор альтернативы были «loop / routing / measurement», а тут другой принцип: **ограничить выбор, а не
обогащать контекст**.

И один дешёвый эксперимент, который можно поставить на нашем же стенде: одна задача, два режима —
(а) свободные вызовы инструментов, (б) конечный список шагов, который строит наш код. Мерить: битые
вызовы, шаги, токены. Если (б) не хуже по качеству и дешевле — это довод в сторону «выборов».
