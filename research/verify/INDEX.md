# verify: пять чужих репозиториев

Клоны `--depth 1` на 15.11.2026, отчёты рядом (`<имя>.md`, `<имя>.json`, `<имя>.receipt.json`).
Счёт по README: широкий — любая строка с числом вне кода/таблиц/бейджей; строгий — где у числа
есть единица измерения (тесты, звёзды, загрузки, мс, проценты); «с командой» — рядом (±2 строки)
есть исполняемая команда.

|---|---|---|---|---|
| ironclaw | 4 | 0 | 2 | — |
| markitdown | 5 | 2 | 3 | 0.5 |

| python-sdk | 4 | 0 | 1 | — |

Воспроизводимость: повторный прогон на `markitdown` дал тот же json (кроме `generated_at`) — да.

## Что показал прогон (и чего он не показывает)

- В прозе README числа почти не встречаются: у четырёх репозиториев из пяти их 0–2. Числа живут
  в таблицах, бейджах, коде и `docs/` — эти области инструмент **не** читает и говорит об этом
  в каждом отчёте.
- Поэтому «доля 0.00» здесь означает не «репозиторий плохой», а «в прозе README нечего проверять».
  Это ограничение инструмента, а не приговор проекту.
- `humanlayer`: в README нет ни одной строки с числом вне кода/таблиц — широкий счёт 0.

## Как воспроизвести

```
python bin/verify_repo.py https://github.com/microsoft/markitdown --out research/verify
python bin/verify_repo.py https://github.com/microsoft/markitdown --json  # сверить с .json
```

Коммиты клонов не фиксируются: `--depth 1` берёт HEAD на момент прогона. Для сверки квитанция
хранит sha256 прочитанного README — этого достаточно, чтобы понять, тот ли это файл.
