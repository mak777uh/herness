Прогнал на вашем репозитории (клон `--depth 1`, HEAD на 15.11.2026, `input_sha256` README

Отчёт целиком — `research/verify/markitdown.md`; машинная версия — `markitdown.json`; квитанция —
`markitdown.receipt.json` (там sha256 прочитанного README, чтобы было видно, тот ли это файл).

В прозе нашлось ровно одно число, строка 361:

> `` `max_retries` controls the OpenAI client's automatic retries for retryable errors

Команды рядом нет — и, честно говоря, ей там и не место: это описание параметра, а не метрика
проекта. Так что «доля 0.00» здесь означает не «у вас нечего проверять», а «в прозе README нет
утверждений о работе, которые стоит воспроизводить». Для README этого достаточно.

Сверка одной командой:

```
python bin/verify_repo.py https://github.com/microsoft/markitdown --json
```

`json` должен совпасть с `markitdown.json` во всём, кроме поля `generated_at`
(сейчас это может не сойтись, если README успел измениться — тогда другим будет и `input_sha256`).

## Чего этот прогон не делает — и почему это важно

- **Это не «у вас плохой README».** Прибор читает только прозу: таблицы, бейджи, блоки кода и
  `docs/` он не разбирает. Числа в бейджах — счётчики загрузок и звёзд, а не утверждения о работе.
- **Наличие команды не значит, что она проверяет это число.** Прибор видит соседство, а не смысл;
  поэтому он не засчитывает `max_retries` как команду, хотя строка в бэктиках выглядит похоже.
- **Выборка маленькая.** Из пяти репозиториев, на которых я прогонял прибор, в четырёх в прозе
  README чисел нет вовсе. «0.00» — свойство текста, а не приговор проекту; сводка —
  `research/verify/INDEX.md`.

Если метрика где-то читает вас неправильно — скажите как, и я поправлю прибор, а не отчёт.

## Почему выбран именно этот репозиторий

Из пяти прогонов `markitdown` — единственный, где число в прозе есть и его можно показать пальцем
(строка 361). На письме «у вас ноль» без примера читалось бы как обвинение; здесь пример есть,
и на нём же видно границу прибора: число описательное, команды нет, и это нормально.

1. Имя автора и адрес — не выдумывать: взять из `git log`/профиля репозитория на момент отправки.

   иметь возможность сверить, а не поверить.
4. Не отправлять в issue: это личное письмо с измерением, а не публичное заявление о проекте.
