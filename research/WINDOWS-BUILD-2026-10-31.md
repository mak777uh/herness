# Сборка на Windows без WSL: проверено (31.10.2026)

Вопрос был: можно ли собирать харнесс в Windows, чтобы не держать WSL? Ответ: **да, и полный путь
пройден** — сборка, упаковка, загрузка в эмуляторе, сверка хеша.

## Что понадобилось

| компонент | что даёт | размер |
|---|---|---|
| rustup (windows-gnu) | `cargo`, `rustc`, `rust-lld` | уже был в системе |
| mingw-w64 **WinLibs 16.2** | линкер для хоста | ~500 МБ |
| QEMU for Windows | загрузка нашего образа | ~250 МБ |
| Python 3.13 | упаковка initramfs, эталонные хеши | был |

## Ошибка, которую пришлось пройти

Первый кросс-билд упал на линковке build-скриптов:

```
undefined reference to `GetHostNameW'
```

Причина: mingw из **miniconda** старый (нет `GetHostNameW` в импорт-библиотеках `ws2_32`). Лечение:
свежий **WinLibs 16.2 (UCRT)**. Это не про наш код — про окружение Windows.

## Проверка

```
pwsh core-rs\build.ps1
```

Вывод:

```
бинарник: 715272 байт, сигнатура 7F 45 4C 46
ядро: 10961920 байт
initramfs: 311031 байт | init: 715272 | method: 88
--- загрузка в QEMU (30 с) ---
hs-core: я инициализировал систему сам, PID 1
архитектура: x86_64
печать /method.md: d105fb5d1c0ce17b09f25aba9e07bb8bdf9c404158e993e6d615f855f2072bef
```

**Хеш совпал с эталоном Python байт в байт.** Ядро — `6.6.134-0-lts` (Alpine).

## Что это значит для WSL

WSL больше **не нужен** ни для сборки, ни для загрузки, ни для сверки: всё делает Windows.

Что теряется при удалении Ubuntu:

- Linux-шелл для ручных проб (но песочницу всё равно проверяем на **целевом** ядре в QEMU);
- `gcc` для мелких C-проб (можно вернуть точечно);
- ~5,45 ГБ образа `ext4.vhdx` — **освобождаются**.

Что не теряется: репозиторий, Rust, Python-эталон, QEMU, ядро (лежит в `core-rs/boot/`, в git не
коммитится).

## Как это сочетается с «только ядро»

Теперь путь целиком выглядит так: **Windows — мастерская** (сборка, Python-эталон, git, QEMU) →
**ядро + hs-core — изделие** (305 КБ образа, работает на любом Linux). Дистрибутив не участвует нигде.
