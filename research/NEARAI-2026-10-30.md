## 1. `nearai/putnambench-deepseek` — 44 ★, лицензии нет, push 2026-08-27

> «An autonomous DeepSeek-driven agent that solved PutnamBench in Lean 4: **672 problems solved and
> machine-validated**… The agent harness provides… access to a **single tool: bash** (plus tools to
> report that the work is done). All other operations, such as reading and writing files or invoking
> Lean, must be done via the bash tool… all that the harness does is the **classic agent loop** of
> „call LLM, execute tools, repeat". The `completed` tool verifies that the problem is solved, and if
> so, reports to the outer system, which then **re-verifies** the solution and records it.»

Что это значит для наших пунктов:

| пункт | вывод |
|---|---|
| **Т-1.1/Т-1.4** «сколько инструментов нужно» | **одного `bash` хватило** на 672 формальные задачи. Сильный довод, что минимальный набор не мешает, если домен узкий |
| **Т-1.3** «код как действие» | здесь код-как-действие реализовано на уровне оболочки: чтение, запись и вызов Lean — всё через `bash` |
| **Т-3.3** «что считать доказательством» | **двухступенчатая проверка**: инструмент `completed` проверяет, внешняя система перепроверяет и записывает. Это ровно наша схема «артефакт → проверка → утверждение» |
| **Т-0.2** «вид результата» | сильнейший оракул — компилятор Lean: результат машинно проверяем, а не «модель сказала» |
| ядро (D3) | «классический цикл, никакой оркестрации» — независимое подтверждение выбранной ступени |

Оговорки: 44 звезды, лицензии нет, README — заявление автора; мы не воспроизводили ни одну из 672
задач. Домен узкий: один файл, одна задача, один инструмент.

## 2. `nearai/ironclaw` — 12 690 ★, MIT OR Apache-2.0, Rust, push 2026-10-29

> «**WASM Sandbox** — Untrusted tools run in isolated WebAssembly containers with capability-based
> permissions… **Credential Protection** — Secrets are never exposed to tools; **injected at the host
> boundary with leak detection**… **Prompt Injection Defense** — Pattern detection, content
> sanitization, and policy enforcement… **Endpoint Allowlisting** — HTTP requests only to explicitly
> approved hosts and paths… **Dynamic Tool Building** — describe what you need, and IronClaw builds it
> as a WASM tool… **MCP Protocol**.»

| пункт | вывод |
|---|---|
| **Т-4.3** «изоляция» | WASM-песочница с правами по возможностям + Docker с токенами на задачу. Мы сидим на локальном процессе — это верхняя планка, к которой можно идти |
| **Т-4.4** «секреты» | **третий вариант**, которого у нас не было: не запрещать и не маскировать, а **не давать инструменту секрет вообще** — подставлять на границе хоста, с детекцией утечки |
| **Т-4.5** «allowlist доменов» | у нас `fetch` ходит куда угодно; у IronClaw — только явно разрешённые хосты и пути |
| **Т-7.3** «инъекция» | заявлена защита: паттерны, санитайзинг, политики. По нашему же выводу из чата (`Т-7.2`), паттерны обходятся — их заявление требует проверки, а не доверия |
| **Т-6.1/Т-6.2** | MCP поддержан; как у них чужой вызов попадает в аудит — не проверено |
| **Т-5.5** «полезность инструмента» | «dynamic tool building»: инструмент создаётся под задачу как WASM — альтернатива нашему «сначала напиши код, потом запусти» |

Оговорки: 12.7 тыс. звёзд — популярность, не проверка. Заявления README не воспроизводились.
Темы репозитория: `codeact`, `openclaw`, `rlm`, `rust`, `wasm`.
