## 2. Противоречит или расходится

- **Shell лучше / хуже.** SWE-agent: специализированный интерфейс лучше shell (18 % против 11 %).
  «Is Bash All You Need?»: shell лучше набора типизированных инструментов (+24,6 п.п.). Оба верны для
  своих задач: интерфейс помогает в кодинге, shell — в кросс-приложенческих workflow. **Простое
  правило «дать shell» не обосновано.**
- **Сколько шагов оптимально.** Ни один ответ не даёт измеренного «порога повтора для файла».
  Есть только «тот же вызов + тот же результат» без порога и калибровки ложных срабатываний.
- **Цена самоулучшения.** DGM: один прогон на SWE-bench ≈ $22 000, SICA ≈ $7 000 за 15 итераций.
  Это на порядки больше наших прогонов (0.01 за принятый) — self-hosting у нас будет другим по цене.

## 3. Что не измерено (и это важно)

- порог «N бесплодных обращений» и цена ложных срабатываний — ни у кого;
- «impact per step» как переносимая метрика — не установлена;
- held-out-гейн самоулучшения именно для харнесса (не для бенчмарка) — не измерен;
- calibration кривой отказа в агентных задачах — только точечные числа;
- цена изоляции именно для «QEMU-комната + toolchain» — не измерена.

## 4. Что мы сделали прямо сейчас

**Пересчитали свои петли по определению DeLoop** (`bin/loop_audit.py`, 77 журналов, 775 шагов):

| показатель | значение |
|---|---|
| шагов-петель | **227 из 775 = 29,3 %** |
| прогонов хотя бы с одной петлёй | 43 из 77 |
| без терминального исхода среди прогонов с петлями | **36 из 43 = 84 %** |
| без терминального исхода среди прогонов без петель | **5 из 34 = 15 %** |

Это резкое подтверждение: петля по информации — почти приговор прогону (84 % против 15 %), и
метрика по вызову+результату гораздо точнее нашей прежней «зацикливание на одном файле».

## 5. Что внедряем (по приоритету)

1. **Детектор петли по (вызов + результат)** — уже считаем задним числом; следующий шаг — в цикле,
   с реакцией «смени гипотезу или BLOCKED». Отрицательный контроль: прогоны без петель не должны
   затрагиваться, а доля молчаний должна упасть.
2. **Напоминание об остатке шагов** в промпте (дешёвая правка; по литературе даёт больший эффект,
   чем сам лимит).
3. **Отказ как отдельный исход** с разделением «молчание / отказ / DONE без опоры» — у нас уже есть
   `unverified`, нужно считать implicit abstention отдельно (17,8 % в чужом бенчмарке — это наша
   основная масса).
4. **Замороженный held-out набор** до начала self-hosting — обязательное условие, иначе повторяем
   objective hacking из DGM.

## 6. Чего сознательно не делаем

- не запрещаем повторные обращения к объекту (AgentQuest: в LTP повторы — часть стратегии, 81 %);
- не переносим чужие пороги (75-й перцентиль) как свои: у нас другая база распределения;
- не добавляем shell «ради shell» и не открываем toolchain, пока не решён вопрос модели угроз;
- не считаем self-hosting доказанным: чужие числа — про бенчмарк, не про качество харнесса.
