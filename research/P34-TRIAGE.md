# P34 — разбор четырёх ответов: где живёт исполнение кода

**Дата:** 07.11.2026. **Материал:** четыре независимых прохода по заданию P34.
**Правило:** чужие числа — вторичны; в `CLAIMS.md` идут только наши измерения.

## 1. Что сходится во всех четырёх ответах

| утверждение | подтверждение |
|---|---|
| **Wasm внутри минимальной ВМ не измерен ни в одной работе** | все четыре ответа независимо; есть только близкие: Mewz (unikernel + Wasm, 1.3× против WasmEdge, но 2.5× медленнее native), WaSC (15 мс старт, 8.4 МБ накладных) |
| **Starlark не ограничивает память потока** | starlark-go прямо: «нет способа ограничить память потока», нужен отдельный процесс с ulimit/cgroup |
| **eBPF verifier — не граница для произвольного кода** | все четыре; SEV нашёл **15 логических ошибок за месяц**, две эксплуатируемы для повышения привилегий; CVE-2023-2163 — container escape |
| **Wasmtime — не абсолютная граница** | апрельские advisories: **12 исправлений, 2 Critical** (sandbox escape через Winch и aarch64 Cranelift) |
| **готовой среды со всеми слоями нет** | все четыре |
| **прямого сравнения «исполнение против выбора инструментов» при равном бюджете нет** | все четыре |

## 3. Что противоречит нашим планам

**CodeAct и Hyperlight показывают, что главный выигрыш — не в новых инструментах, а в
композиции вызовов кодом.** Это прямо поддерживает наш вывод «правила протокола дают больше, чем
инструменты» — но с другой стороны: они получают выигрыш **исполнением кода**, а не подсказками.

**То есть наш следующий рычаг — не «научить модель лучше выбирать», а дать ей один вызов,
который делает многое.** Это меняет порядок: программный вызов инструментов (F-04) поднимается
выше, чем реестр и pre-flight.

## 4. Что берём в план (с отрицательным контролем)

| механизм | источник | отрицательный контроль |
|---|---|---|
| **Wasm-исполнитель внутри комнаты, отдельным процессом** | Mewz, WaSC, Hyperlight | модуль с запрещённым импортом и выходом за линейную память обязан упасть, не получив доступа |
| **жёсткий ресурсный контур процесса** (cgroup/RLIMIT/timeout) | starlark-go, Buck2 (2 ГБ на файл) | программа с малыми аллокациями в цикле должна остановиться по памяти процесса, а не по лимиту шагов |
| **узкие host-примитивы вместо универсального доступа** | Hyperlight `call_tool`, MCPGuard | попытка передать запрещённый путь через легальный вызов не должна проходить |

## 5. Что меняется в порядке

Было: реестр → pre-flight → canary → рабочий набор → синтез.

Стало: **сначала программный вызов инструментов** (F-04), потому что именно он даёт измеренный
выигрыш (74.4 % против 53.7 %, вдвое меньше токенов), и только потом синтез. Реестр и pre-flight
не отменяются — они нужны, когда инструментов станет много.

## 6. Границы

Все четыре ответа — обзоры, не наши замеры. Наши числа (pass@1 0.71, pass^2 0.49, ложных «готово»
0.03) — единственное, что проверено исполнением. Ни одно чужое число не идёт в `CLAIMS.md`.
