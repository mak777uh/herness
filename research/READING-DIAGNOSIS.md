# Почему чтение проваливается: диагноз

**Дата:** 08.11.2026. **Основание:** серия из 20 задач после правки лимитов.

## Что сделал

**Шаг 1 плана:** увеличил `MAX_READ` с 8 до 24 КиБ, `LAST_RESULT` с 4000 до 12000 символов,
обрезка теперь называет размер.

**Результат: не помогло.** Чтение: **3 из 10** против 4 из 10 до правки.

## Что показал журнал

Взял прогон S20: «Прочитай `research/P38-FLOWGUARD-DOCS.md` и назови, сколько документов
разобрано».

**Что делал агент:**

```
TOOL read research/P38-FLOWGUARD-DOCS.md   ← прочитал файл
TOOL list /mnt                              ← зачем?
TOOL search /mnt P38-FLOWGUARD              ← зачем?
TOOL list /mnt/docs                         ← зачем?
TOOL search /mnt FLOWGUARD                  ← зачем?
TOOL list /mnt/research                     ← зачем?
TOOL search /mnt/docs FLOWGUARD             ← зачем?
TOOL search /mnt P38                        ← зачем?
TOOL list /mnt                              ← зачем?
```

**Файл прочитан на первом шаге.** Дальше — **восемь шагов поиска** того, что уже прочитано.

## Настоящая причина

**Не лимиты. Агент не доверяет прочитанному.**

Он прочитал файл, но не «увидел» в нём ответ — и пошёл искать в другом месте. Это ровно то, о чём
книга:

> **«Образ создаётся при невнимательности»** (стр. 257). Когда ум невнимателен к факту, он создаёт
> образ — и потом ищет подтверждение образа.

> **«Мысль ищет безопасности»** (стр. 394). Агент ищет подтверждение, а не ответ.

## Что это значит

**Проблема не в инструменте `read`, а в том, как агент обрабатывает прочитанное.**

Три гипотезы, по порядку проверки:

### Гипотеза 1: ответ есть, но агент его не распознал

Файл начинается с заголовка «Разбор **трёх** документов». Число «три» есть в первой строке.
Агент прочитал — и не связал «три» с вопросом «сколько документов».

**Проверить:** дать задачу, где ответ — число в первой строке, и посмотреть, ответит ли агент сразу.

### Гипотеза 2: агент не знает, что файл прочитан целиком

`read` отдаёт 24 КиБ. Файл `P38-FLOWGUARD-DOCS.md` — 6 КБ. Значит файл прочитан **целиком**.
Но агент мог не понять, что это весь файл.

**Проверить:** добавить в конец результата `read` явную строку «(файл прочитан целиком, N строк)».

### Гипотеза 3: задача сформулирована неоднозначно

«Сколько документов разобрано» — в файле три документа, но ещё есть разделы. Агент мог считать
разделы.

**Проверить:** переформулировать задачи чтения так, чтобы ответ был однозначным.

## Что делать

**1. Добавить в `read` явное указание, что файл прочитан целиком.**

Сейчас: если `next > total`, ничего не пишется. Надо писать: «(файл прочитан целиком, N строк)».

**2. Проверить гипотезу 1 на одной задаче.**

Дать задачу, где ответ в первой строке, и посмотреть, ответит ли агент сразу.

**3. Переформулировать задачи чтения.**

Вместо «сколько документов разобрано» — «назови число из первой строки файла».

## Граница

Это **диагноз по одному прогону**, а не по всем семи. Чтобы утверждать, надо посмотреть журналы
всех провалов. Но картина одинаковая: агент читает, потом ищет.
