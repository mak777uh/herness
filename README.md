# herness — прибор границ истины

Харнесс нужен не для того, чтобы «быстрее писать код». Он нужен, чтобы **точнее очерчивать
границы истины**: какое утверждение чем подтверждено, где кончается проверенное и начинается
предположение, что именно мы не утверждаем.

Отсюда главное следствие: выход харнесса — не строчки кода, а **утверждения с типом
свидетельства** и явными границами. Код — побочный продукт.

## Что это не

- **Не работающий продукт.** Нет релиза, нет опубликованного бинаря, нет ни одного выполненного
  внешнего задания владельца. Всё, что есть, — прибор и его проверки.
- **Не доказательство, что «плоскость свидетельств» — верное ядро.** Это выбранная предпосылка
  (ADR-0029); пилот на трёх задачах дал слабое подтверждение, не доказательство.
- **Не харнесс, который «умнее».** Замер: по правильности ответов он не отличается от свободной
  руки; разница — в честности изложения и в том, что на длинной задаче остаётся, чем проверить.
- **Не изоляция.** Модель исполняет команды на этой машине; песочницы нет.
- **Не безопасность против целенаправленного обхода.** Журнал защищён хеш-цепочкой, но модель
  по-прежнему может создавать файлы и менять состояние среды.

Подробные границы — `NOT-CLAIMED.md`; отброшенные варианты — `docs/eliminations.md`; отказы —
`lab/failures/`.

## Что это технически

Не форк и не переписывание DSH. Своя **композиция**: изолированный `DSH_HOME`, свой профиль,
свои плагины на seam'ах DSH, и слой истины (гейты, реестры утверждений, журнал прогонов)
поверх. Установленный `DeepSeek Harness` не модифицируется.

Проверено 29.10.2026:

```
dsh --version                      -> 0.2.1-rc.3
DSH_HOME=<свой> dsh --profile headless --dump-config   -> профиль собирается
```

## Структура

```
bin/hs.py          инструмент: факты среды, прогоны, доктор
docs/              решения (ADR) и реестр исключённого
lab/               гипотезы, эксперименты, шаблоны
profile/           планируется в M3: package.json + cordis.patch.yml + plugins/ (сейчас каталога нет)
home/              изолированный DSH_HOME (в git не едет)
runs/              журнал прогонов: stdout/stderr/meta/дайджесты (в git не едет)
```

## Быстрый старт

```
python bin/hs.py doctor        # проверка: CLI, дом, пороги диска и памяти
python bin/hs.py facts         # факты среды (JSON)
python bin/hs.py facts --md    # то же таблицей
python bin/hs.py refs sync     # подтянуть первоисточники портфеля в локальный кэш
python bin/hs.py refs add https://github.com/nearai/ironclaw   # внешний источник
python bin/hs.py refs search "wasm sandbox credentials allowlist"   # прецеденты
```

Справочник принимает два вида источников: репозитории владельца (`portfolio.json`) и внешние —
GitHub-репозитории или произвольные страницы (`sources.json`, добавляются командой `refs add`).

## Принципы и справочник

- [docs/PRINCIPLES.md](docs/PRINCIPLES.md) — 25 принципов портфеля: что запрещают, чем
  принуждаются, каким негативным тестом проверяются.
- `refs` — механизм «репозитории как постоянный справочник»: ключевые документы 25 репозиториев
  (AGENTS, CLAIMS, interop) синхронизируются в `refs-cache/` с дайджестами, поиск идёт локально и
  воспроизводимо. Состояние читается из первоисточника, а не из памяти (принцип P20).

## Как мы выбираем

Заимствования проверяются на соответствие задаче, а не на репутацию: [docs/FIT-CHECK.md](docs/FIT-CHECK.md).

## Что это за софт

Единица продукта — не задача, а **граница**: что человек готов делать, с кем и на каких условиях.
Полное определение — [docs/PRODUCT.md](docs/PRODUCT.md).

## Куда это ведёт

Дальняя цель — записана в [docs/VISION.md](docs/VISION.md): узлы, которые договариваются о правилах
и объявляют **свои** границы заранее, а взаимодействие опирается на проверяемые утверждения. Не
«правила для всех», а границы каждого, видимые до взаимодействия.

Проверка каждого решения: приближает ли оно границу, которую можно показать до взаимодействия, и
свидетельство, которое можно проверить после.

## Три закона этого репозитория

1. **Число без команды — не результат.** Любая цифра в доке имеет рядом команду и дайджест.
2. **Отрицательный результат остаётся.** `docs/eliminations.md` — первоклассный документ.
3. **Каждый отчёт содержит раздел «что это не доказывает».**

Подробнее — `AGENTS.md`. Реестр утверждений — `CLAIMS.md`. Границы — `NOT-CLAIMED.md`.



**О названии.** `herness` — от «her» и «harness»: то, что впрягает в работу не вообще, а под конкретного
человека, с его границами. На слух остаётся прежнее «harness», поэтому старое имя не потеряно.
