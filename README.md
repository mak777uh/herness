# herness

Харнесс для автономной работы: агент должен выполнять задачи **сам, долго и с проверяемым
результатом** — так, чтобы человеку не приходилось перепроверять всё руками.

Проверка здесь не самоцель, а рабочий метод. Без неё длинная автономная работа вырождается в
правдоподобный текст: на короткой задаче «объявил готово, а не готово» раздражает, на суточной —
обнуляет результат. Если итог всё равно перепроверяют вручную, автономии нет — есть дорогой черновик.

## Что это такое

Свой контур, собранный с нуля, без обёрток вокруг чужих агентов:

| слой | что это |
|---|---|
| **ядро** | Linux 6.18.60, `tinyconfig`, без модулей и SMP; namespaces, cgroups, Landlock |
| **комната** | QEMU + `init` на Rust; **нет shell и coreutils**; инструменты не выходят из каталога |
| **цикл** | модель отвечает одной строкой: `TOOL <имя> <аргумент>`, `DONE <итог>`, `BLOCKED <почему>` |
| **инструменты** | `search`, `list`, `read`, `write`, `seal`, `netprobe`; выдача по критерию |
| **журнал** | append-only с CRC и границами коммита; хвост после обрыва не чинится |
| **приёмка** | на хосте; критерий объявлен **до** прогона; проверяет вынесенный журнал |
| **мост** | единственное место с ключом провайдера; TLS и ключ остаются на хосте |

## Как проверяется результат

Три слоя, каждый ловит своё:

1. **Форма** — порядок событий в журнале: `run/start → tool/call → tool/result → step → … → run/end`.
2. **Опора** — ответ обязан делить с журналом конкретное имя: номер утверждения, путь к файлу или
   ссылку `файл:строка`. Ответ без опоры не считается результатом.
3. **Приёмка** — критерий объявлен до прогона и лежит на хосте: статус, опора, число шагов, расход,
   выданные инструменты, совпадение с хостом.

Плюс **29 гейтов** (`python bin/hs.py gates`), и у каждого есть **проба**: во временную копию
подкладывается реалистичный дефект, и гейт обязан его заметить. Сейчас 30 проб из 30 ловят.

## Чего это не доказывает

- **Не работающий продукт.** Нет релиза и нет выполненного внешнего задания.
- **Не «умнее».** Разница не в правильности ответов, а в том, что остаётся, чем проверить.
- **Не полная изоляция.** Нет shell, инструменты не выходят из каталога, фильтр syscall ставится,
  если ядро умеет, — и это честно пишется в журнал. Это не защита от целевого обхода.
- **Не «задача решена».** Приёмка проверяет объявленные условия; если критерий неполон, `PASS`
  этого не покажет.
- **Не доказательство, что «плоскость свидетельств» — единственно верное ядро.** Это выбранная
  предпосылка (ADR-0029), оправданная целью, а не сама собой.

Границы — `NOT-CLAIMED.md`, отброшенное — `docs/eliminations.md`, отказы — `lab/failures/`.

## Как устроено

```
ядро 6.18.60 ──> init (Rust) ──> цикл ──> инструменты (search/list/read/write/seal)
                    │              │
                    │              └─ журнал HSJ1: CRC, границы коммита, хвост не чинится
                    └─ песочница: namespaces, Landlock, seccomp (если ядро умеет)
                                   │
   хост: мост (ключ, TLS) <── plain HTTP ── комната
         приёмка (accept/) <── журнал, вынесенный на диск
         метрики (judge_metrics) ← те же журналы
```

## Структура репозитория

```
bin/          гейты (hs.py), мост, приёмка, метрики, задачи из истории, пробы гейтов
core-rs/      ядро, init, цикл, песочница; сборка и прогоны в QEMU
accept/       критерии приёмки — в комнату не попадают
docs/         ADR, журнал решений, спецификация режимов, реестр исключённого
lab/          отказы, склад решений, правила автономии, манифест комнаты
research/     склады источников и данных, артефакты прогонов, задания на ресёрч
CLAIMS.md     реестр утверждений: тип свидетельства, команда проверки, граница
```

## Быстрый старт

```
python bin/hs.py gates            # 29 гейтов + быстрые пробы
python bin/gate_probe.py          # полный набор проб: подложить дефект и потребовать находки
python bin/judge_metrics.py       # ложное «готово», pass@1, pass^2, цена принятого
python bin/readme_numbers.py      # числа этого README против артефактов
python bin/build_room.py --check  # комната совпадает с манифестом
python bin/hs.py selftest         # негативные тесты самого инструмента
```

Прогон в своём ядре:

```
pwsh core-rs/run.ps1
pwsh core-rs/accept-run.ps1 -Mode loop-bridge -Kernel vmlinuz-own-net -Net -Task "..."
```

## Задачи берутся из собственной истории

Не придумываются: утверждения, отказы, журналы прогонов, коммиты, решения — с машинными ключами,
которые нельзя подогнать. Генераторы: `bin/history_tasks.py`, `bin/baseline_history*.py`,
`bin/chain_task.py`.

## Как встроено исследование источников

Чтение без решения бесполезно, поэтому цикл из шести шагов, и каждый оставляет артефакт:

1. **Склад** — источник попадает в `research/REFS-INDEX.md` в тот же день со статусом чтения:
   `[Ч]` читал, `[А]` только описание, `[?]` не открывал.
2. **Вопрос, а не тема** — «как у них решён выход из тупика», а не «посмотрим, что есть».
3. **Разбор** — `research/<NAME>-REVIEW.md`: что механизм делает, какая цена, где доверенная граница.
4. **Решение** — строка в `lab/adoptions.json`: берём / не берём / отложить, с причиной.
5. **Гипотеза** — в `lab/registry.json`, с ожидаемым исходом и отрицательным контролем.
6. **Внедрение и проверка** — код, тест, прогон; нет эффекта → пишется отказ.

Правило исполняется гейтом **«решения»**: механизм нельзя внедрить без источника и отрицательного
контроля. Гейт проверен сам на себе (`--self-test`).

## Куда движемся

Порядок выведен из цели, а не из интереса:

1. **Три режима работы** — план, автономное выполнение, долгосрочная цель (`docs/MODE-SPEC.md`).
   Режим «план» уже проверен на живой задаче.
2. **Запуск без человека** — закладка на источник вместо окна времени, журнал против повторов,
   «нечитаемо» как отдельный исход (`research/INSIGHTS.md`, F-07).
3. **Реестр инструментов и pre-flight** — поиск по контракту до действия, ограниченный рабочий
   набор, архив вместо удаления (F-10…F-12).
4. **Свои инструменты и сеть** — агент пишет себе инструменты (F-05) и сам ищет в сети (F-06);
   обе требуют решения, где живёт исполнение кода.
5. **Программный вызов инструментов** — один шаг вместо десятка вызовов (F-04).

Список идей и статусы — `research/INSIGHTS.md`; каждое решение — `lab/adoptions.json`.

## Три правила этого репозитория

1. **Число без команды — не результат.** У каждой цифры рядом команда и артефакт.
2. **Отрицательный результат остаётся.** `docs/eliminations.md`, `lab/failures/`, отклонённые
   решения в складе — не свалка.
3. **Каждый отчёт содержит раздел «что это не доказывает».**

Подробнее — `AGENTS.md`. Реестр утверждений — `CLAIMS.md`. Границы — `NOT-CLAIMED.md`.
