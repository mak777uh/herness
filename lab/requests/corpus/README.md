# corpus — регрессия протокола разбора

Набор запросов с ожидаемой разметкой. Изменение `REQUEST-PROTOCOL.md` не принимается, если
ухудшает разметку этих случаев.

## Формат

```json
{
  "request": "текст запроса владельца",
  "expected": {
    "defined": ["что должно быть понято однозначно"],
    "undefined": ["что обязано быть названо неопределённым"],
    "must_ask": ["вопрос, который обязан возникнуть"],
    "must_experiment": ["эксперимент, который обязан быть предложен"],
    "contradictions": ["конфликт с принципами, если есть"]
  },
  "note": "почему этот случай важен"
}
```

## Правила пополнения

1. Случай добавляется **после** дефекта, а не вместо него: сначала эпизод в `lab/notes/`, потом здесь.
2. Ожидание формулируется так, чтобы его можно было проверить глазами: не «понять лучше», а
   «назвать неопределённым X».
3. Случаи не удаляются — только уточняются новой версией файла с датой в имени.

## Как пользоваться

```
python bin/hs.py request lab/requests/corpus/<случай>.json
```

Это проверяет структуру разбора, а не качество классификации: качество проверяет человек или
ревьюер по ADR-0017.
