# H-0001 — Минимальная база и системный слой: какая ОС дешевле всего для нашего тулчейна

Боль: харнесс должен быть системным слоем (ADR-0009), но неизвестно, на какой базе это дешевле
всего и с каким числом ручных шагов.

Проверка: один и тот же сценарий на четырёх базах. Сценарий — «с нуля до работающих тулчейнов»:

```
1. поднять чистую машину (VM с 8 ГБ RAM, 100 ГБ диск)
2. поставить python 3.12+, git
3. поставить elan + Lean + Mathlib, собрать тестовый файл
4. поставить foundry, прогнать forge test на тестовом проекте
5. поставить rustup + toolchain, прогнать cargo test
6. поставить супервизор харнесса, запустить две тестовые службы
7. снять снапшот, сломать службу, откатиться
```

Метрики (фиксируются до прогона):
- время до всех зелёных, минуты;
- число ручных шагов (не считая одной команды установки);
- размер образа/диска после установки, ГБ;
- число падений, требующих ручного вмешательства;
- работает ли откат из шага 7 без ручного восстановления.

Опровержение: гипотеза неверна, если какая-то база одновременно быстрее на ≥30 % и даёт меньше
ручных шагов и меньше падений, чем остальные. Тогда выбор меняется в её пользу, а не по симпатии.

Статус: open. Эксперимент: E-0001.
