# lab/reviews — рецензии на утверждения

Отдельный проход, который **ищет, что убьёт утверждение**, а не подтверждает его. Взят по образцу
роли reviewer из Morphogenesis: рецензент не запускает прогоны, не правит утверждения, не меняет
статусы — он пишет только сюда.

## Формат файла

Имя: `<claim_id>-<yyyy-mm-dd>.md`.

```
id: C-0069
date: 2026-10-30
claim: <текст утверждения, как в CLAIMS.md>
verdict: upheld | killed | unclear
artifact_checked: <путь файла, который открывал>
method: <чем проверял: чтение файла, сравнение, запуск команды — если запускал, то какой>
reasons:
  - <почему такой вердикт, по пунктам>
what_would_kill_it: <что должно было бы быть в артефакте, чтобы утверждение упало>
```

## Индекс

`lab/reviews/index.json` собирается скриптом `bin/build_reviews_index.py`; руками не правится.
Гейт «рецензии» падает, если файл не разбирается или индекс разошёлся с файлами.

## Правила рецензента

1. **Verifier не доверяет утверждению**, пока не открыл артефакт.
2. **`upheld` ставится только если артефакт действительно содержит ожидание.** Нет — `unclear`.
3. **`killed`** — если артефакт противоречит утверждению или утверждение шире, чем артефакт
   подтверждает.
4. Рецензент **не правит** `CLAIMS.md`: он пишет вердикт, правка — отдельное решение.
