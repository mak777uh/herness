id: F-0075
date: 10.11.2026
title: подсчёт по каталогу — модель получает полный список и не считает его, отвечая done без числа
what: две задачи одного семейства провалились одинаково. M05 («Сколько файлов .md в docs?») — 1 шаг, TOOL list docs, полный список из 112 записей пришёл, модель ответила done без числа, статус done-без-опоры. N05 в серии new10 (прежняя версия) — та же картина. Инструмент отдал данные, модель их не посчитала.
class: loop-design
principle: если задача требует операции над результатом (счёт, сравнение, выбор максимума), подсказка цикла обязана назвать эту операцию; иначе модель достраивает ответ вместо вычисления
detect: дать задачу «сколько файлов в каталоге», где list возвращает полный список; правильный ответ проверять anchor_regex. Провал виден как done-без-опоры при одном шаге
test: M05-count-docs: 1 шаг, опора пустая, итог FAIL. Контроль: M01 и M04 (поиск конкретного файла) проходят за 1-2 шага с опорой — значит дело не в инструменте list, а в операции счёта
symptom: задача про подсчёт выглядит как провал модели, хотя инструмент отдал всё нужное; в подсказке цикла есть указание для «разные (N)» от search, но нет указания, как считать элементы списка от list
cause: в подсказке цикла (core-rs/src/loopmod.rs, compose_prompt) есть правило «если в результате есть строка «разные (N)» — отвечай N», но нет правила для list: «если спрашивают, сколько файлов в каталоге, посчитай строки списка». Обрезки вывода нет: LAST_RESULT = 12000 символов, вывод list docs = 3019 символов, лимит list = 200 записей при 112 файлах
fix: не исправлено. Кандидат — одна строка в подсказке про подсчёт списка; но это смена поведения цикла, её надо мерить отдельно (до/после на M05 и N05), а не вставлять по ходу
caught_by: серия M, задача M05: прогон дал done-без-опоры за один шаг при полном списке в результате; проверено, что обрезки нет (сравнение размера вывода с LAST_RESULT и лимитом list)
