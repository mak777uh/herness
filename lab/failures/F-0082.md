id: F-0082
date: 11.11.2026
title: на этой машине DNS отдаёт 198.18.0.0/15 для всех доменов — проверка SSRF по IP блокирует весь интернет
what: example.com, github.com и tokio.rs резолвятся в 198.19.0.x, то есть в диапазон 198.18.0.0/15 (RFC 2544, benchmarking). Python помечает его is_private=True. Первая версия фильтра bin/net_policy.py отклоняла всё по признаку is_private, и положительный контроль (public URL) провалился: вместо «разрешён» фильтр ответил «ОТКАЗ private: 198.19.0.202». При этом настоящий внешний адрес машины — 188.162.201.143, то есть резолв подменён перехватчиком (sing-box или профиль VPN).
class: unstable-measurement
principle: проверка, чей ответ зависит от окружения, обязана назвать это окружение; иначе один и тот же вход даёт разный вердикт на разных машинах, и порог меряет не свойство кода, а настройку сети
detect: резолвить несколько заведомо внешних доменов и сравнить с фактическим внешним адресом машины; расхождение означает перехват DNS
test: socket.getaddrinfo('example.com') -> 198.19.0.202, ('github.com') -> 198.19.0.38, ('tokio.rs') -> 198.19.0.204; внешний адрес по api.ipify.org -> 188.162.201.143. Фильтр по is_private отклоняет все три
symptom: SSRF-фильтр, который на машине с перехватом DNS блокирует весь интернет, а на машине без перехвата работает; порог «9 из 9 и положительный контроль» проваливается не из-за кода, а из-за сети
cause: проверка по резолву предполагает, что резолв говорит правду о том, куда пойдёт соединение. При перехвате DNS это не так: адрес подменён, соединение идёт через прокси
fix: не исправлено. Направление: проверять ИМЯ (loopback-имена, литеральные IP, запрещённые домены) как основное, а резолв — как дополнительную проверку, которая срабатывает только когда даёт настоящий внешний адрес; диапазон 198.18.0.0/15 при этом называется перехватчиком, а не целью
caught_by: первый прогон положительного контроля SSRF-R1: public URL отклонён с кодом private
