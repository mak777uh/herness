id: F-0080
date: 11.11.2026
title: Policy.lean и PartBridge.lean объявляют Effect в корне — вместе не собираются, а поодиночке собираются
what: `Proofs/Policy.lean` и `Proofs/PartBridge.lean` оба объявляют `public inductive Effect` в корневом пространстве имён (у Policy — allow/deny, у PartBridge — allow/deny/duty). `Proofs.lean` импортирует оба, поэтому `lake build Proofs` падает: «import Proofs.PartBridge failed, environment already contains 'Effect.rec' from Proofs.Policy». По отдельности каждый модуль собирается: `lake build Proofs.Policy` и `lake build Proofs.PartBridge` — зелёные.
class: false-green
principle: проверка, которая собирает часть, ничего не говорит о сборке целого; зелёный по частям не означает зелёного вместе
detect: собрать не отдельные модули, а корневой `Proofs.lean`, который импортирует все; конфликт имён виден только там
test: `lake build Proofs` -> error про Effect.rec; `lake build Proofs.Policy` -> ✔; `lake build Proofs.PartBridge` -> ✔. При этом bin/lean_check.py собирает только Proofs.Policy, а bin/bridge_parts.py — только Proofs.PartBridge, поэтому конфликт не проявлялся ни разу
symptom: README заявляет «6 теорем в Lean» и «3 теоремы о мосте между частями», каждый скрипт отчитывается зелёным, а полная сборка доказательств не проходит
cause: два модуля писались независимо и оба объявили тип Effect в корне; namespace нет ни в одном. Корневой Proofs.lean добавлен, но не собирался ни одним прибором
fix: не исправлено. Кандидат — развести по namespace (namespace Policy / namespace PartBridge), это смена контракта моделей и требует ADR
caught_by: первая сборка `lake build Proofs` в WSL после переноса proofs/ в репозиторий: error про Effect.rec
