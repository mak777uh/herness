id: F-0087
date: 11.11.2026
title: musl-бинарник ядра в комнате остался HSJ1 после правки формата до HSJ2 (этап 2.1) — комната писала журнал, который хост-приёмка отвергает; смежно N7 (crash-resume) затирал свежий образ устаревшим share.img
what: После этапа 2.1 (HSJ2-KIND-R1, ADR-0056) исходник core-rs/src/journal.rs и хост-парсер bin/accept.py перешли на формат HSJ2 (magic HSJ2, version 2, kind внутри CRC), но развёрнутый musl-бинарник ядра core-rs/target/x86_64-unknown-linux-musl/release/hs-core пересобран не был. Замер 11.11.2026 ДО: бинарник mtime 12:41, grep -a -o HSJ[12] -> 4 HSJ1 / 0 HSJ2; journal.rs (HSJ2) mtime 19:09 (ПОЗЖЕ бинарника); initramfs.cpio.gz mtime 17:42 упакован из HSJ1-бинарника. Комната писала HSJ1, accept.py после 2.1 требует version 2 -> живая приёмка отвергала журнал комнаты. Смежный дефект N7 (остаток F-0073): core-rs/crash-resume.ps1:33 делал Copy-Item share.img -> acc.img -Force без проверки манифеста — путь отката затирал свежий канонический образ устаревшим share.img (от 10.11).
class: broken-by-change
principle: изменение формата журнала не развёрнуто, пока не пересобран бинарник, который его пишет; гость и хост обязаны говорить на одной версии кадра. Быстрые гейты не пересобирают musl-бинарник (ADR-0055) — дрейф «исходник ↔ развёрнутый артефакт» живёт вне их и ловится только явной сверкой версии или живым прогоном. Второй источник пути к образу (Copy-Item share.img) воспроизводит класс F-0073 на пути отката, даже когда основной путь сведён к манифесту.
detect: grep -a -o 'HSJ[12]' по musl-бинарнику и по initramfs (ожидается HSJ2, 0 HSJ1); mtime бинарника >= mtime journal.rs; accept.py на журнале комнаты требует version 2 (HSJ1 -> «нет заголовка HSJ2», записей 0). Статически: crash-resume.ps1 читает образ из lab/room.json (поле image) и пересобирает build_room.py --build с проверкой rc, не содержит Copy-Item share.img (кроме комментария).
test: NC1 (дрейф бинарника) — accept.py на сохранённом HSJ1-журнале runs/accept/*.bin -> FAIL (версия 1, записей 0, «нет заголовка HSJ2», rc=1), КРАСНЫЙ до пересборки. NC2 (N7) — Copy-Item share.img -> acc.img -Force затем build_room.py --check -> FAIL (6 docs / 8 failures назад, rc=1), КРАСНЫЙ до фикса. ЗЕЛЁНЫЙ после: бинарник HSJ2 (4 HSJ2 / 0 HSJ1, mtime 20:07), initramfs переупакован (578056 байт, HSJ2=4/0); живой accept-run (команда C-0284/85) -> итог PASS, журнал HSJ2 version 2, 2 шага, ответ 30 из журнала; живой crash-resume@30 -> продолжение шагов 1, итог PASS, опора C-0004, журнал HSJ2 v2. Отрицательный результат crash-resume@12 -> FAIL (тайминг обрыва до первого sync шага, F-0027) сохранён дословно, порог prereg не ослаблен. Артефакты: research/outputs/room-live-red-before.txt, research/outputs/room-live-green-after.txt. Пре-регистрация ROOM-HSJ2-LIVE-R1 (порог ДО прогона), утверждение C-0298, реестр E-0019.
symptom: живая приёмка комнаты после 2.1 отвергала журнал комнаты (версия 1 не поддерживается), хотя ядро «работало» и писала журнал; crash-resume отбрасывал комнату на 6 docs / 8 failures назад устаревшим share.img — класс F-0073 («приёмка брала не тот образ») воспроизводился на пути отката, провал задачи списывался на модель/комнату, а не на дрейф артефакта
cause: musl cross-build (core-rs/build.ps1) — отдельный ручной шаг, не покрытый быстрыми гейтами (ADR-0055: тяжёлые живые операции вне быстрого контура); после правки journal.rs до HSJ2 бинарник не пересобран, initramfs упакован из старого HSJ1. crash-resume.ps1 имел второй, независимый источник пути к образу (Copy-Item share.img поверх acc.img), не сведённый к манифесту lab/room.json — остаток N7 от F-0073, который закрыл только основной путь accept-run.ps1.
fix: (1) пересобран musl hs-core до HSJ2 на Windows (cargo build --release --target x86_64-unknown-linux-musl, линкер rust-lld, mingw WinLibs; Finished in 12.74s, rc=0), initramfs переупакован bin/make_initramfs.py (578056 байт, внутри gzip HSJ2=4 / HSJ1=0). (2) N7: crash-resume.ps1 берёт $image из lab/room.json (поле image, F-0073), вместо Copy-Item share.img вызывает build_room.py --build с проверкой rc (fail-closed, exit 3 если образ не пересобран); Copy-Item share.img убран (остался только в комментарии). PARSE_ERRORS=0. Сквозно подтверждено живым crash-resume: скрипт сам собрал свежий образ (364 файла, «образ совпадает с манифестом», rc=0) и продолжил прогон. Живой accept-run + crash-resume@30 PASS. Формат HSJ1->HSJ2 и судьба старых HSJ1 решены в ADR-0056 ДО кода; этот цикл — развёртывание 2.1 в бинарнике комнаты + закрытие N7 по всем путям.
caught_by: цикл живой приёмки ROOM-HSJ2-LIVE-R1 — дрейф бинарника найден сверкой grep HSJ[12] + mtime ДО прогона (не после провала задачи); NC1/NC2 красные до фикса; N7 — остаток F-0073, закрыт по всем путям (accept-run.ps1 ранее, crash-resume.ps1 теперь). Порог (criterion/sensitivity) объявлен и запечатан ДО прогона (sha256 4e00d95a5b90a49a…), во время прогонов не менялся; после закрытия prereg перепечатан (2378a5125e02e3b4…).
not_proven: один живой обрыв в одном месте (kill во время работы, не посреди записи события): продолжение после обрыва ПОСЛЕ первого шага проверено; обрыв ДО первого шага даёт «без задачи» -> blocked (тайминг, F-0027, не дефект HSJ2/N7). Расход — оценка провайдера, не факт биллинга. Ответ 30 / опора C-0004 — один прогон, не exhaustive. whpx/QEMU/мост средо-зависимы: на другой платформе/без моста прогон не воспроизводится. Пересборка бинарника и образа — живые тяжёлые операции, в быстрые гейты не входят (ADR-0055): дрейф «исходник↔бинарник» может повториться при следующей правке формата, пока нет явной сверки версии развёрнутого бинарника в CI. HSJ2-кадр: CRC 32 бита — подделку с пересчётом CRC ловит хеш-цепочка событий, не кадр (ADR-0056). Документарный дрейф C-0284 (ответ «29» при текущих 30 строках NOT-CLAIMED.md) отмечен отдельно, критерий room-smoke.json число не фиксирует.
