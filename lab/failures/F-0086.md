id: F-0086
date: 11.11.2026
title: kind вне CRC записи журнала — переворот Data↔Commit проходил с зелёной CRC; durable-open дописывал поверх оборванного хвоста
what: core-rs/src/journal.rs считал crc = SHA256(len ++ seq ++ payload)[0..4], а байт kind дописывал ПОСЛЕ хеша (зеркало bin/accept.py). Переворот kind Data(1)↔Commit(2) не менял CRC и проходил walk/parse_journal с зелёной проверкой: маркер коммита отделяет «заявлено» от «подтверждено», битый kind меняет смысл записи (данные становятся коммитом, коммит — данными), приёмка этого не видела. Смежное: Journal::open с существующим файлом делал seek(End(0)) и дописывал поверх оборванного хвоста — новые записи оказывались после разрыва и никогда не читались (run_task_resume обрезал хвост корректно, durable-open — нет). Замер 11.11.2026 (красный ДО): Rust kind_flip_is_detected FAILED (переворот принят, entries=2), Python «переворот kind ПРОШЁЛ при зелёной CRC».
class: check-too-weak
principle: проверка целостности обязана покрывать все поля, меняющие смысл записи; CRC, не включающий kind, — слабая проверка, которая зелёным светом пропускает подмену смысла; прибор, дописывающий поверх оборванного хвоста, теряет свидетельства молча
detect: переворот байта kind Data→Commit БЕЗ пересчёта CRC — walk/parse_journal обязан отвергнуть (entries уменьшаются, tail_bytes>0); положительный контроль: неперевёрнутый журнал разбирается полностью. Кросс-сверка байтов Rust↔Python на замороженном векторе кадра. Статически — grep порядка hasher.update в journal.rs (kind должен входить до finalize)
test: Rust юнит-тесты kind_flip_is_detected + open_quarantines_torn_tail_without_losing_prefix + hsj2_frame_cross_vector_matches_python (journal.rs, --lib); Python tests/test_frame_vector.py + контроль в test_forgery.py. Красный ДО фикса (Rust rc=101, Python rc=1), зелёный ПОСЛЕ (Rust 75/0 чистой сборкой bin/rust_tests.py, Python test_accept 24/24, test_forgery, test_false_done 3/3, test_frame_vector). Артефакты: research/outputs/hsj2-red-before.txt, research/outputs/hsj2-green-after.txt, tests/vectors/journal_frame.json
symptom: журнал с перевёрнутым kind читался как честный: данные могли стать коммитом (ложное «подтверждено»), коммит — данными (ложное «не подтверждено»); durable-open на оборванном хвосте ломал журнал навсегда — продолжение не читалось, валидный префикс терялся для нового чтения
cause: kind исключён из хеша кадра (порядок len+seq+payload, kind после); open() не зеркалил run_task_resume (seek End без обрезки хвоста). Формат HSJ1 не различал переворот kind по CRC
fix: формат HSJ2 (ADR-0056, принят до кода): magic HSJ2, version 2, раскладка записи та же (RECORD_HEADER=17); crc = SHA256(len ++ seq ++ kind ++ payload)[0..4] (порядок: 12 байт len+seq, 1 байт kind, payload) в journal.rs append/walk и accept.py parse_journal. open() при torn_tail: quarantine + set_len(len-tail_bytes) до валидного префикса, затем продолжение (зеркально run_task_resume). Старые HSJ1 отвергаются fail-closed по версии, НЕ мигрируются (миграция перезаписывает улику — против ADR-0049). Кросс-вектор кадра tests/vectors/journal_frame.json заморожен эталонной Python-формулой, читается Rust (--lib) и Python. Пре-регистрация HSJ2-KIND-R1 (порог ДО кода), утверждение C-0297, реестр E-0018
caught_by: этап 2.1 аудита (docs/AUDIT-PLAN.md §3): дефект подтверждён построчно до кода, формат и судьба HSJ1 решены в ADR-0056 ДО кода, порог объявлен ДО прогона (HSJ2-KIND-R1), отрицательный контроль красный до / зелёный после
not_proven: CRC кадра — 4 байта (32 бита) от SHA256, детектор случайной порчи и переворота kind БЕЗ пересчёта CRC, не криптостойкость. Намеренная подмена с пересчётом CRC возможна (CRC не секрет) — её ловит хеш-цепочка событий (event_hash) и опора утверждения, не кадр; 2.1 это не закрывает. Node-плагин (answerFromJournal) — ленивый текстовый сканер, целостность кадра не проверяет (вне 2.1). Отказ HSJ1: 135 исторических runs/**/*.bin новым парсером не читаются (journal_dump выгрузит 0) — сознательный fail-closed, не тихая потеря. Кросс-вектор — один кадр из двух записей, не exhaustive-сверка всех длин/видов
