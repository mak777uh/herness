# E-0007 — Обвязка против работы без обвязки

Гипотеза (H-0006): обвязка (журнал, утверждения, границы, отчёт) ускоряет и улучшает не все задачи,
а только те, где цена ошибки высока.

## Зачем

Сейчас все утверждения о пользе харнесса не имеют контрольной группы. Это делает их верой. Нужен
базовый уровень, с которым можно сравнивать.

## Пре-регистрация (объявлено до прогона)

**Задачи:** 6 штук из журналов, по два класса:

| класс | примеры |
|---|---|
| простые | переименовать файл; собрать список файлов по шаблону |
| средние | проверить документ на числа без команд; найти расхождение между README и кодом |
| сложные | аудит утверждений репозитория; подготовка отчёта с границами |

**Условия:**

| | A: без обвязки | B: с обвязкой |
|---|---|---|
| разбор | нет | 3 строки |
| журнал и артефакты | нет | есть |
| утверждения и границы | фраза, если вспомнит | обязательны |
| отчёт | свободная форма | report.md |

**Метрики:** время до результата; число шагов; число ошибок, замеченных проверкой; наличие границ в
результате; воспроизводимость (повтор даёт тот же вывод).

**Порог (объявлен сейчас):** обвязка оправдана для класса, если она даёт **меньше ошибок** или
**больше границ** при времени не более чем в 1,5 раза. Иначе класс переводится в режим без обвязки.

## Команда

```
python bin/hs.py execute "<задача из списка>"
```




## Три группы, а не две

Сравнение «с обвязкой против без обвязки» смешивает два разных вклада: наличие инструментов и
наличие протокола. Поэтому групп три.

| группа | что есть у исполнителя | что измеряет |
|---|---|---|
| **A0. чистая модель** | только задача. Ни файлов, ни оболочки, ни поиска | сколько стоит отсутствие свидетельств: как часто ответ выдуман |
| **A. инструменты без обвязки** | оболочка, чтение, запись, сеть (если нужно задаче) | вклад инструментов |
| **B. инструменты и обвязка** | то же, что A, плюс журнал, артефакты, отчёт, границы | вклад протокола |

Правило: **A и B имеют одинаковые возможности**, различие только в протоколе. A0 отличается
намеренно — это и есть измеряемая величина «что бывает без инструментов».

Ожидание, объявленное заранее: на задачах про файлы A0 будет **выдумывать числа** (их неоткуда
взять). Это не провал эксперимента, а его главный результат: он показывает, зачем нужны
свидетельства.
## Правило честного сравнения

Обе группы имеют **одинаковые возможности**. Различие только одно — протокол обвязки.

| | A без обвязки | B с обвязкой |
|---|---|---|
| модель | та же | та же |
| оболочка, чтение, запись | есть | есть |
| поиск в сети | есть **или** нет у обеих | там же, где у A |
| журнал, артефакты, отчёт | нет | есть |

Если какая-то возможность отнимается у контроля (например, поиск в сети, чтобы базовая линия была
«чистой»), она отнимается **и у группы с обвязкой**. Иначе замер меряет доступ к инструментам, а не
обвязку.

Отдельно фиксируется: пользовался ли контроль внешними источниками. Если да — это часть базовой
линии, а не преимущество.
## Первая пара (29.10.2026)

**Задача:** посчитать в репозитории число `.md` файлов, отслеживаемых git, и сколько из них содержат
слово «критери».

**Истина (вычислена независимо):** 77 файлов; 21 содержит «критери».
Команда: `git ls-files '*.md'` + `Select-String -Pattern 'критери'`.

**Группа A (без обвязки):** обычный исполнитель, ответ в свободной форме.
**Группа B (с обвязкой):** тот же вопрос, но каждый шаг через `hs step`, в конце `hs report`.

Сравниваем: совпадение чисел с истиной, наличие команды в ответе, наличие границ, число шагов.

**Что это покажет:** цену обвязки на простой задаче — там, где её польза минимальна. Если на таком
классе она не даёт выигрыша, это ожидаемо; важно, сколько она стоит.
## Результат — группа A (без обвязки)

Ответил за ~1 минуту: **77 и 21** — совпало с независимо посчитанной истиной. Привёл две команды
(`git ls-files` и `git grep -i -l`), перекрёстно проверил, `git status` чист.

Важное: компетентный исполнитель **и так** даёт команды и проверку. Значит польза обвязки не в
«привести команду», а в том, что команда и артефакт остаются на диске после разговора.

## Результат — группа B (с обвязкой, первая попытка)

**Провал по трению:** исполнитель не смог выполнить протокол с пятью флагами и за несколько минут
не создал даже каталог прогона. Записано как F-0009. Интерфейс упрощён: `hs step --run X "<команда>"`
(команда позиционно, прогон открывается сам), протокол — два правила вместо пяти флагов.
