# E-0002 — Язык цикла: проверка чувствительности (ОТЛОЖЕН)

> Решение по языку принято в ADR-0012 (29.10.2026): L2 — Python, L1 — Rust. Эксперимент больше не решает выбор,
> а проверяет, не ошиблись ли мы: если Python даст >3× памяти или минуты на итерацию — вернёмся.

Гипотеза: язык слоя L2 (цикл и журнал) определяется ценой итерации при самоизменении (A10), а не
производительностью на микроуровне.

## Пре-регистрация (объявлено до прогона)

**Кандидаты:** Python 3.13, Rust 1.99 (tokio), Go (последний стабильный), TypeScript (Node 24).

**Задача:** один и тот же минимальный цикл в каждом языке:

```
прочитать задачу → вызвать "инструмент" (запуск процесса, запись артефакта)
→ дописать событие в журнал (fsync) → прочитать ответ (mock) → повторить 20 шагов
```

**Сценарий изменения:** добавить в цикл новое поле события и новую проверку бюджета. Это локальная
правка на 10–20 строк.

**Метрики:**
1. время «правка → зелёный тест» (10 повторов, медиана);
2. p50 / p95 задержки вызова инструмента (включая запуск процесса);
3. память на один прогон (RSS);
4. число строк на правку (включая изменения схемы);
5. холодный старт до первого шага.

## Правило решения (объявлено сейчас)

- L2 = Python, **если** медиана «правка → зелёный тест» у него ≤50 % от Rust/Go **и** память на
  прогон ≤2× от лучшего.
- L2 = Rust/Go, **если** память на прогон ≥3× меньше, чем у Python, при цене итерации ≤2× хуже.
- Иначе `inconclusive` — остаёмся на текущем и фиксируем, чего не хватает.

## Команда

```
python bin/hs.py run "E-0002: прогнать сценарий на <язык>"
```

## Что это не доказывает

- Что 20 шагов с mock-моделью эквивалентны реальному длинному прогону.
- Что цена итерации не изменится, когда появятся вложенные агенты (A6).
- Что удобство языка измеряется числом строк.
