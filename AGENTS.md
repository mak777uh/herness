# AGENTS.md — контракт для агентов, работающих в этом репозитории

Этот репозиторий строит инструмент, который сам проверяет утверждения. Поэтому к нему
применяются те же правила, что и к остальному портфелю `mak777uh/*`, но с одним усилением:
**инструмент обязан показывать собственную погрешность**.

## Порядок чтения

1. `README.md` — что стоит и какие границы честные.
2. `docs/DECISION-0001-base-os-language.md` — принятые решения и почему.
3. `CLAIMS.md` — что мы уже утверждаем и чем это подтверждено.
4. `NOT-CLAIMED.md` — что мы сознательно не утверждаем.
5. `docs/eliminations.md` — что проверено и отброшено.
6. Только потом — код.

## Правила

0. **Сначала справочник, потом изобретение.** Перед любым новым механизмом —
   `python bin/hs.py refs search "<боль>"`. Если прецедент есть в портфеле, ссылайся на него
   (`repo/doc`), а не переизобретай. Пустой поиск — тоже результат: записать в `lab/`.
1. **Не трогать установленный `DeepSeek Harness`.** Ни `app.asar`, ни его `~/.dsh`. Работаем
   только в собственном `DSH_HOME` (`home/`); собственный профиль `profile/` появится в M3 и сейчас
   отсутствует — не ссылайтесь на него как на существующий.
1c. **Незаданное условие — это неопределённость, а не допущение.** Не выводи ограничения из общих соображений («мобильный интернет → значит лимит»): это выдумка посылки, и на ней потом строится всё остальное. Спроси владельца — цена вопроса одна реплика. (Прецедент: лимит трафика, E-0002.)

1b. **Не заполняй пробел правдоподобным числом.** Если значение неизвестно — это неопределённость, и у неё есть тип закрытия: вопрос, эксперимент, допущение (с пометкой) или отказ. Придуманное «разумное» число — худший вариант: оно выглядит как результат. (Прецедент: параметры сети в удалённом NETWORK-MODE, E-0002.)

1a. **Предпосылки — тоже решение.** Выбирая технологию, язык или формат, перечисли кандидата «своё» и его цену. Если не перечислил — решение помечается «предпосылка не проверена» (P24).

2. **Публикация — только после гейтов.** `python bin/hs.py gates` должен быть зелёным; гейт не
   ослабляется, чтобы «стало зелёным». Смена порога — отдельный ADR.
3. **Один вопрос — одно изменение.** Новый инструмент или сеam — сначала гипотеза в `lab/`,
   потом код.
4. **Секреты не попадают в контекст и в git.** В отчётах — имена файлов и отпечатки, никогда
   значения.
5. **Ничего наружу** (репозитории, форумы, баунти) без явного «да» владельца. Перед публикацией —
   `docs/PUBLICATION-POLICY.md`: зона A публикуется, зоны B и C — нет. Сомневаешься — зона B.
6. **Не объявлять находку без воспроизводимого доказательства.** Прогон, команда, дайджест.
7. **Чужой код не «оптимизировать»** без бэкапа и отката.
8. **Скорость — измеряемая величина.** Утверждение «быстрее» допустимо только с командой
   замера и числом (`python bin/hs.py bench`).

## Что считается проверкой

```
python bin/hs.py doctor                     # среда: CLI, дом, пороги
python bin/hs.py selftest                   # негативные тесты самого инструмента
python bin/hs.py gates                      # секреты, утверждения, ссылки
python bin/hs.py refs search "<боль>"       # прецеденты в портфеле (перед новым механизмом)
```

Локально зелёное ≠ проверенное: если гейт не запускался в этом окружении, он «не проверялся
здесь», а не «пройден».




## Модель

По умолчанию и постоянно — `deepseek-v4.1-flash` (решение владельца, 29.10.2026). Другая модель
допустима только как явный эксперимент с записью в `lab/`; гейт `модели` не даст подменить её молча.

## Ресурсные числа — только исполнением

Утверждение про время, шаги или байты проверяется командой `bin/assert_bound.py`, а не подстрокой в
отчёте: она запускает цель, берёт метрику и падает, если граница нарушена.

```
python bin/assert_bound.py --metric time --max 300 --runs 1 -- python bin/hs.py selftest
python bin/assert_bound.py --metric json --path steps --max 6 --runs 2 -- <команда с JSON>
```

Тип такого утверждения в `CLAIMS.md` — `measurement`. Число, взятое из текста отчёта, — `observation`,
и оно не считается проверенным.
