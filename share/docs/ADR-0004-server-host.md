# ADR-0004 — Харнесс живёт на отдельной машине

Дата: 29.10.2026. Статус: принято владельцем. Дополняет ADR-0003.

## Решение

Харнесс — **серверный процесс на выделенном хосте**, а не приложение на рабочем ноутбуке.
ОС хоста выбирается отдельно и может быть любой; клиент (этот ноутбук) подключается к нему.

## Что это меняет

| было | стало |
|---|---|
| харнесс в той же среде, что и данные | харнесс на своей машине, данные — по явному контракту |
| выбор ОС = «где удобнее владельцу» | выбор ОС = «где живёт сервер»: тулчейны, супервизия, песочница, простой |
| Electron-окно как поверхность | клиент-сервер: хост ничего не рисует |
| рабочая зона = `<рабочий каталог>` целиком (975k файлов) | рабочая зона = git-репозитории, клонированные хостом |
| один процесс на всё | долгоживущий демон + разовые прогоны |

## Следствия, которые уже можно зафиксировать

1. **Протокол на границе обязателен.** Клиент и хост — разные машины, значит между ними нужен
   контракт, а не «общий каталог». Кандидаты: ACP, HTTP+SSE, JSON-RPC. Решение — после B12.
2. **Хост клонирует репозитории сам.** `<рабочий каталог>` с 975 871 файлом не монтируется: любой рекурсивный
   скан — минуты. Workspace = явный список git-репозиториев + рабочие каталоги прогонов.
3. **Аутентификация — часть архитектуры, а не галочка.** У хоста есть доступ к репозиториям и,
   возможно, к деньгам; токен клиента — первичный объект.
4. **ОС хоста не обязана совпадать с клиентом.** Windows остаётся клиентом; сервер, скорее всего,
   Linux — но это решается замером (E-0001), а не симпатией.
5. **Песочница становится обязательной, а не желательной:** хост исполняет код из чужих
   репозиториев круглосуточно.

## Требования к хосту (черновые, до B11)

| параметр | минимум | почему |
|---|---|---|
| RAM | 32 ГБ | параллельные прогоны + Lean/Foundry + кэши |
| диск | 1 ТБ NVMe | Lean-кэш Mathlib ~6 ГБ на версию, node_modules, артефакты |
| CPU | 8 ядер / 16 потоков | сборки и компиляции, не модель |
| сеть | стабильная, с прокси | цепочка до провайдеров моделей |
| питание | всегда включён | ночные прогоны (A15) |

## Что это не доказывает

- Что Linux обязательно лучше: у нас нет ни одного замера на целевом железе (E-0001).
- Что удалённое исполнение не добавит латентности, заметной для владельца.
- Что хост переживёт отключение питания без потери журнала (зависит от ФС и fsync-политики).
