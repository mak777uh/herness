# ADR-0005 — Ядро и оболочки: безопасное ядро, которое запускается всегда

Дата: 29.10.2026. Статус: принято владельцем. Дополняет ADR-0003 и ADR-0004.

## Решение

Харнесс строится как **одно ядро и две оболочки**. Ядро не знает о существовании UI. Оболочки
могут ломаться, переписываться и перезагружаться на ходу — прогон при этом продолжается.

```
        ┌──────────────────────────────┐
        │  Оболочка B: приложение с UI │  богатый, правится на ходу
        │  (может падать, жить отдельно)│
        └──────────────┬───────────────┘
                       │ API ядра (версионированный контракт)
        ┌──────────────▼───────────────┐
        │  Оболочка A: минимальный веб │  всегда запускается, для отладки
        └──────────────┬───────────────┘
                       │
        ┌──────────────▼───────────────┐
        │  ЯДРО                        │  цикл, инструменты, журнал,
        │  stdlib-only, без UI         │  политика, бюджеты, гейты
        └──────────────────────────────┘
```

## Почему так, а не «одно приложение целиком»

1. **UI правится часто, ядро — редко.** Если это один процесс, каждая правка кнопки — риск для
   исполняемого прогона. Разделение делает риск локальным.
2. **«Запустится при любом раскладе»** — это свойство ядра, а не UI. Богатое приложение зависит от
   фреймворка, сборки, GPU; минимальный веб зависит только от стандартной библиотеки.
3. **Отладка на хосте без графики.** Хост может быть без монитора; веб-оболочка — единственный
   способ посмотреть, что происходит.

## Инварианты

| id | инвариант | как проверяется |
|---|---|---|
| U1 | Ядро не импортирует ничего из оболочек | тест: `grep` импортов в `core/` не находит `ui/`, `web/` |
| U2 | Падение оболочки не прерывает прогон | тест: убить UI-процесс посреди прогона → журнал дописан до конца |
| U3 | Минимальный веб стартует при битом конфиге | тест: испортить конфиг → веб поднимается в safe-mode и показывает ошибку |
| U4 | API ядра версионирован; оболочка не ломается от добавления поля | тест: схема ответа — только добавления, без удалений |
| U5 | Ядро стартует без сети, без GPU, без базы данных | тест: запуск в пустом окружении |

## Политика зависимостей

| слой | зависимости | правило |
|---|---|---|
| ядро | только stdlib | новая зависимость — ADR с обоснованием и ценой аудита |
| минимальный веб | stdlib + один шаблонизатор максимум | должен собираться без node/npm |
| богатое приложение | свободно | может тянуть любые фреймворки, живёт отдельно |

## Safe mode

Если конфиг невалиден, ядро всё равно поднимается: берёт значения по умолчанию, **отключает
инструменты, которые пишут** (файлы, shell, публикация), пишет предупреждение в журнал и ждёт
явного исправления. Отказ стартовать — хуже, чем старт в урезанном режиме: владелец не увидит,
что именно сломалось.

## Правка на ходу

- Оболочка B перезагружает собственный код без перезапуска ядра.
- Ядро перезапускается только явной командой; незавершённый прогон либо продолжается, либо
  закрывается с записью в журнал — молча не исчезает.
- Горячая правка ядра во время прогона запрещена: это тот самый случай, когда «на ходу» стоит
  дороже, чем перезапуск.

## Что это не доказывает

- Что богатый UI не потребует собственного сервера и не потянет за собой второе ядро.
- Что «stdlib-only» выдержит нагрузку (профилирование не делали).
- Что safe-mode не превратится в тихий режим, где ошибки копятся незамеченными.
