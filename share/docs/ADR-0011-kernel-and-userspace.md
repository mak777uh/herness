# ADR-0011 — Ядро: Linux LTS с минимальной конфигурацией, а не «минимальное ядро»

Дата: 29.10.2026. Статус: предложено владельцем («минимальное оптимальное ядро, сохраняя драйверы
и приложения»). Дополняет ADR-0009 и ADR-0010.

## Формулировка решения

Ядро — **Linux** (LTS-ветка). Минимальность достигается **конфигурацией и userspace**, а не сменой
ядра. Своё пишем вокруг: init, супервизор, менеджер среды, поколения. Драйверы и совместимость
приложений сохраняются, потому что это и есть ядро Linux, а не его урезанная замена.

## Почему не другое ядро

| кандидат | драйверы | приложения (glibc) | cgroups/namespaces | цена | вердикт |
|---|---|---|---|---|---|
| **Linux** | полное покрытие | полная | есть | низкая | **выбрано** |
| seL4 | почти нет, драйверы — исследование | нет | нет | годы | отсекается |
| Unikraft / MirageOS | только virtio | нет | нет | средняя | отсекается |
| FreeBSD | хорошее, но уже | через linuxulator | частично | средняя | отсекается: ABI-прослойка |
| Windows | полное | да | Job Objects | — | отсекается: нет поколений (ADR-0009) |
| своё ядро | нет | нет | нет | десятилетия | отсекается |

Требование «сохранить драйверы и приложения» оставляет ровно одного кандидата. Это не выбор по
симпатии — это следствие двух жёстких требований.

## Что значит «минимально»

| делаем | не делаем |
|---|---|
| `make localmodconfig` — только модули этого железа | не выкидываем подсистемы, от которых зависят драйверы |
| модули вместо встроенного, где возможно | не собираем ядро «под один ноутбук» без запаса |
| initramfs только с нужными модулями | не отключаем storage/net/usb «для экономии» |
| без debug-символов в проде | не отключаем BTF, если нужна трассировка |
| прошивки только для имеющегося железа | не тащим firmware для всего мира |

Цель по размеру: **ядро+модули ≈ 150–250 МБ**, загрузка до userspace ≤ 3 с. Это гипотеза, не факт.

## Что обязаны сохранить

| что | почему |
|---|---|
| storage: nvme, ahci, btrfs, ext4 | без этого не грузимся |
| net: ethernet, wifi (если нужен), virtio | связь |
| usb/hid | клавиатура, флешка как аварийный носитель |
| gpu: базовый (framebuffer), опционально | консоль и диагностика |
| ABI: glibc, `/proc`, `/sys`, `/dev` | Lean, forge, python — чужие бинарники |
| udev **или** mdev | устройства — это ядро плюс userspace; без менеджера устройств не будет `/dev` |

Важно: **udev мы не заменяем**. Соблазн «всё своё» здесь стоит дорого: правила устройств — это
тысячи строк, которые никто не хочет переписывать.

## Что заменяем вокруг ядра

| было | станет |
|---|---|
| init/systemd | супервизор харнесса (с осторожностью, ADR-0009) |
| apt/dpkg | менеджер поколений |
| journald | журнал событий |
| cron | планировщик прогонов |
| cloud-init | наш первый запуск |

## Обновления и профили железа

- Ядро — часть поколения: обновление ядра = новое поколение, откат = переключение.
- Конфиг ядра привязан к **профилю оборудования** (`hwprofile`): новая машина — новый профиль, а не
  пересборка всего.
- LTS предпочтительнее mainline: реже сюрпризы, дольше поддержка.

## Риски

1. **Вырезали модуль — железо не работает.** Проверка только одна: загрузка на целевом железе.
2. **Прошивки с несвободными лицензиями.** Часть железа без них не работает; решение принимается
   явно, с записью в поколение.
3. **Secure Boot.** Своё ядро требует подписи (MOK) или отключения SB; это выбор владельца, не
   техническая мелочь.
4. **Регрессии LTS** случаются; поэтому ядро версионируется как поколение, а не «обновляется на месте».

## Проверка

| что | как |
|---|---|
| грузится на целевом железе | загрузка, `hs doctor` зелёный |
| приложения работают | `lean --version`, `forge --version`, `python -V`, сборка тестового проекта |
| размер и время | `hs facts` + замер загрузки (3 повтора) |
| новая железка | добавить модуль в `hwprofile`, пересобрать поколение, не трогая остальное |

## Что это не доказывает

Что урезанная конфигурация не выстрелит на новом железе. Что 150–250 МБ достижимо с драйверами.
Что LTS-ядро не сломает `forge` или Lean при обновлении.
