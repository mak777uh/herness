# ADR-0013 — Резервные маршруты и входящие соединения

Дата: 29.10.2026. Статус: рассмотрено, внедряется частично. Дополняет ADR-0008.

## Три разные задачи, которые нельзя смешивать

| задача | что нужно технически | чем не решается |
|---|---|---|
| **доступность** | связь при недоступности основного маршрута | входящий адрес не помогает, если узел за NAT |
| **внешний адрес** | узел не публикует постоянный адрес | не влияет на пропускную способность |
| **устойчивость к фильтрации** | прохождение через сети с ограничениями | не даёт анонимности |

Один транспорт редко закрывает все три. Нужен набор с независимыми режимами отказа.

## Варианты

| вариант | доступность | внешний адрес | устойчивость к фильтрации | задержка | цена | роль |
|---|---|---|---|---|---|---|
| прямой HTTPS | зависит от сети | открыт | низкая | низкая | нет | базовый |
| релей у владельца | да | открыт адрес релея | средняя | низкая | сервер | T0, сейчас |
| прикладной TLS/QUIC | да | открыт | средняя | низкая | средняя | T0b |
| **onion-сервис** | **да, без проброса портов** | **не публикуется** | средняя | высокая | низкая | **T1** |
| I2P | да | не публикуется | средняя | высокая | средняя | T2, альтернатива |
| WebRTC-релеи | да | не публикуется | высокая | очень высокая | зависит от посредников | T3 |
| **P2P-оверлей (VecDHT)** | да | частично | высокая | средняя | сложность | **T2**, рендеву |
| libp2p / BEP44 | да | частично | высокая | средняя | сложность | T2, альтернатива |
| Nostr-релеи | store-and-forward | открыт | низкая | средняя | низкая | T2, обмен |
| носитель (USB/QR) | да | не требуется | полная | ручная | ручная | T4 |

## Что берём сейчас

**T0 — релей и политика выхода** (ADR-0007).

**T1 — onion-сервис.** Причина техническая: узел за NAT не принимает входящее соединение без
проброса портов. onion-адрес даёт входящий канал без портов и без публичного адреса. Стоимость —
один сервис; обратимо.

**T2 — рендеву через VecDHT**, когда выйдет из «85 % готовности». Роль строго одна: найти пира и
его актуальный адрес. Передача сообщений — выбранным транспортом, не через DHT.

**T3/T4** — записаны как резерв, внедрение по необходимости.

## Инварианты

1. Конверт один для всех транспортов: подпись, id, run_id, seq, lease.
2. Маршрут фиксируется на прогон; смена транспорта — отдельный прогон.
3. Нет молчаливого переключения (E4): недоступность маршрута — ошибка с кодом.
4. Дедупликация по id сообщения, а не по транспорту: одно сообщение может прийти двумя путями.
5. Офлайн-режим существует: при недоступности всех путей работа продолжается локально.

## Порядок и критерии

| этап | что | критерий |
|---|---|---|
| T0 | релей и политика | внешний запрос идёт только через релей, журнал полон |
| T1 | onion-сервис | клиент подключается к узлу за NAT без проброса портов; задержка измерена |
| T2 | рендеву VecDHT | пир найден, адрес получен, сообщение доставлено другим транспортом |
| T3 | WebRTC-релеи | соединение установлено, задержка и надёжность измерены |
| T4 | носитель | сообщение доставлено без сети, подпись проверена |

## Границы

- Задержка onion-канала — секунды: годится для синхронизации, не для интерактива.
- Оверлей без участников бесполезен.
- Каждый транспорт — отдельная поверхность риска и отдельная строка эксплуатации.
- Доступность любого канала зависит от сети и оператора; гарантий нет.

## Что это не доказывает

Что onion-сервис доступен из нашей сети. Что VecDHT выйдет из беты в обозримом времени. Что
резервный путь окажется не медленнее отсутствия связи.
