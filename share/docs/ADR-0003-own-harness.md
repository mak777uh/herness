# ADR-0003 — Свой харнесс целиком: что это значит на практике

Дата: 29.10.2026. Статус: принято владельцем. Заменяет ADR-0002 в части «плоскость сбоку».

## Решение

Строим собственный харнесс с нуля. Не обвязку вокруг DSH и не форк. Харнесс и есть плоскость
свидетельств: единственный путь исполнения инструмента проходит через журнал и материализацию
артефакта.

## Что это меняет

| было (ADR-0002) | стало |
|---|---|
| плоскость сбоку, движок сменный | плоскость внутри, цикл свой |
| Python судит, TS исполняет | один язык — Python, весь путь аудируем |
| границы «если не забыть» | границы «другого пути нет» |
| зависимость от версии DSH | ноль зависимостей от чужих релизов |

Уроки ландшафта при этом сохраняются, потому что они про свойства, а не про владельца кода:

1. **Цикл — линейный.** История только дописывается; никаких скрытых состояний между шагами.
2. **Действия — stateless.** Каждый вызов инструмента — отдельный процесс. Никакой «живой
   оболочки», которую надо чинить после падения.
3. **Модель видит дайджесты**, а не тела артефактов. Это и дешевле, и честнее.
4. **Траектория = артефакт.** Журнал прогона можно переиграть и прочитать без модели.

## Чего мы сознательно НЕ повторяем

- Плагинного дерева и динамической композиции: для аудита важнее один линейный код.
- Electron и веб-UI в v1: интерфейс — CLI; UI появится, когда ядро доказано.
- Формата сессий с версионированием: формат журнала наш и плоский.
- Автоматического «продолжай, пока не получится» без бюджета.

## Архитектура

```
bin/hc.py            CLI: run, replay, gates, facts
core/config.py       конфиг: провайдер, модель, бюджеты, allowlist
core/provider.py    模型: OpenAI-совместимый и Anthropic-совместимый, SSE
core/journal.py      журнал: append-only JSONL + fsync + артефакты с дайджестами
core/tools.py        инструменты: shell, read, write, http(allowlist)
core/loop.py         цикл: шаг → инструмент → журнал → следующий шаг
core/report.py       отчёт: утверждения + границы («что это не доказывает»)
```

### Данные прогона

```
runs/<run-id>/
  meta.json            задача, бюджет, отпечаток среды, модель, версии
  events.jsonl         append-only, fsync после каждой записи
  artifacts/<sha>.<ext> тело артефакта, имя = sha256
  report.md            что сделано, какие утверждения, чего не доказывает
```

### Инварианты

- **I1.** Инструмент возвращает `ArtifactRef`, а не текст. Тело ложится на диск до того, как
  модель что-либо увидит.
- **I2.** Модель не пишет в рабочую зону напрямую: `write_file` — тоже инструмент, его
  результат — артефакт с дайджестом.
- **I3.** Журнал дописывается и синхронизируется до возврата управления; падение процесса не
  теряет уже записанное.
- **I4.** Бюджет обязателен: шаги, время, байты артефактов. Исчерпан — остановка с отчётом.
- **I5.** Отчёт без раздела «что это не доказывает» не создаётся.

## Порядок сборки

| этап | содержание | критерий готовности |
|---|---|---|
| V0 | цикл + mock-провайдер + один инструмент + журнал | тест: артефакт на диске раньше, чем записан ответ модели |
| V1 | реальный провайдер (SSE), shell/read/write, бюджеты | прогон на живой модели, артефакты и журнал сходятся |
| V2 | гейты публикации, отчёт с границами | посаженное нарушение отбивается |
| V3 | HTTP с allowlist, секреты не в контексте | отказ на запрещённый домен |
| V4 | песочница (WSL / job-объекты), лимит тяжёлых задач | две сборки одновременно не ломают друг друга |
| V5 | UI и мультиагентность | флот ролей на одном журнале |

## Язык

Python. Причины: гейты портфеля уже на нём, один язык на весь путь = читаемый аудит, стандартная
библиотека закрывает HTTP/SSE/JSON без зависимостей. Цена: латентность старта и GIL — не узкие
места для нашей задачи (прогон измеряется секундами и минутами, не миллисекундами).

## Что это не доказывает

- Что свой цикл не будет отставать от чужих по качеству на длинных задачах (E-0003).
- Что Python-провайдер выдержит стриминг так же ровно, как DSH (не мерили).
- Что одной машины хватит для флота ролей (V5 — гипотеза).
