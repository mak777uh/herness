# ADR-0012 — Язык ядра: решение по слоям, а не «весь проект на одном языке»

Дата: 29.10.2026. Статус: **принято** (решение ниже, 29.10.2026). Уточняет ADR-0003 (D3) и критерий K10.

## Почему прежняя постановка была неверной

«Выбрать язык харнесса» — вопрос без ответа, потому что харнесс состоит из слоёв с разными
требованиями. Супервизор должен переживать чужие падения; цикл должен меняться по десять раз в
день; гейты уже написаны на Python и работают. Один язык для всего — это компромисс, который
плох для всех трёх.

## Слои и требования

| слой | что делает | критично | не критично |
|---|---|---|---|
| **L1 привилегированный помощник** | пакеты, сервисы, снапшоты, поколения, устройства | безопасность, атомарность, отсутствие зависимостей | скорость разработки |
| **L2 цикл и журнал** | вызовы модели, инструменты, события, бюджеты | скорость итерации, читаемость, аудит | микросекунды |
| **L3 инструменты и гейты** | проверки, линтеры, замеры | существующий код, экосистема | всё остальное |
| **L4 оболочки** | UI, веб, CLI | скорость правок | системные гарантии |

## Кандидаты по слоям

| кандидат | L1 помощник | L2 цикл | L3 гейты | L4 UI |
|---|---|---|---|---|
| Rust | **сильный**: один бинарник, tokio, wasmtime, никаких рантаймов | возможен; цена — время сборки на каждую правку | слабо: экосистемы проверок нет | нет |
| Go | сильный: один бинарник, простые процессы | возможен; беден на типах для схем | слабо | нет |
| Python | слабый: нужен интерпретатор и зависимости | **сильный**: быстрые итерации, читаемость | **сильный**: уже есть | нет |
| TypeScript | слабый | сильный (DSH это доказал) | средне | **сильный** |

## Что уже доказано полем

| система | язык | вывод |
|---|---|---|
| IronClaw | Rust | цикл + WASM-песочница + инъекция ключей на Rust реальны в проде |
| DSH | TypeScript | цикл и плагины на TS реальны |
| OpenHands, mini-swe-agent | Python | цикл на Python реален, включая SOTA-результаты |
| systemd, runc, был и остаётся | C/Rust/Go | системный слой на скриптовом языке — исключение, а не правило |

Вывод: **консенсуса нет**, копировать нечего. Значит решает не мода, а наши критерии.

## Решение (провизорное, до E-0002)

| слой | язык | почему |
|---|---|---|
| L1 | **Rust** | один бинарник без рантайма, атомарные операции над поколениями, wasmtime для песочницы; падение помощника не должно зависеть от интерпретатора |
| L2 | **Python** (пока) | итерации важнее микросекунд: самоизменение (A10) — это частые правки, а не редкие релизы |
| L3 | **Python** | код уже есть; переписывание ради единообразия — чистая потеря |
| L4 | **TypeScript** | UI позже; выбор не влияет на ядро |

Граница между L1 и L2 — **процесс и версионированный API**, а не импорт. Именно поэтому смена
языка в одном слое не требует переписывать другие.

## Что решает спор по L2

Не «что быстрее в бенчмарке», а **сколько стоит одна итерация** изменения цикла:

```
правка кода → прогон теста → видно результат
```

Метрики E-0002 (пре-регистрация в `lab/experiments/E-0002-language-benchmark.md`):

| метрика | почему она |
|---|---|
| время «правка → зелёный тест» | прямое следствие A10 (самоизменение) |
| p50 и p95 задержки вызова инструмента | влияет на длинные прогоны |
| память на один прогон | вложенная параллельность (A6) |
| число строк на нетривиальную правку | цена аудита |
| время холодного старта | «всегда включён» vs «поднять по требованию» |

## Что бы изменило решение

- Если E-0002 покажет, что Python-цикл на порядок дороже по памяти при 10 параллельных агентах —
  L2 переезжает на Rust или Go.
- Если самоизменение окажется редким (раз в неделю), преимущество Python исчезает — тогда L2 на Rust.
- Если гейты переписать на Rust окажется дешевле, чем держать два языка, — L3 переезжает.

## Что это не доказывает

Что Python-цикл выдержит флот (K9). Что Rust-помощник не станет узким местом по скорости
разработки. Что граница «процесс + API» не окажется дороже прямого вызова.

## Решение (29.10.2026)

| слой | язык | статус |
|---|---|---|
| L1 привилегированный помощник | **Rust** | принято |
| L2 цикл и журнал | **Python** | принято |
| L3 инструменты и гейты | **Python** | принято (уже написано) |
| L4 оболочки | **TypeScript** | позже, не влияет на ядро |

### Почему это решается без бенчмарка

Из журналов (244 сессии): p95 вызова оболочки — 61,9 с, сети — 30 с, ожидания задачи — 600 с.
На этом фоне накладные расходы языка — доли процента. Спор о производительности не про наш случай.

Что действительно решает:

1. **Цена итерации при самоизменении** (A10): правка без компиляции важнее микросекунд.
2. **Слой L1 уже берёт на себя** супервизию и изоляцию — то, где Python слаб.
3. **Один язык для L2/L3** — меньше границ, меньше рассинхрона.
4. **Python есть на любом хосте** — «запустится при любом раскладе» (U3).

### Триггеры пересмотра (объявлены заранее)

- память на прогон превышает 3× от компилируемого варианта при 10 параллельных агентах;
- цена итерации вырастает так, что правка → тест занимает минуты;
- появляется требование одного бинарника для распространения.

E-0002 не отменяется, но перестаёт быть решающим: он становится проверкой чувствительности.
