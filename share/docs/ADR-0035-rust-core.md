# ADR-0035. Ядро харнесса — на Rust

**Статус:** принято владельцем 31.10.2026. Отменяет пункт «Rust/Go — не в v1» из
`DECISION-0001-base-os-language.md` и уточняет `ADR-0012-language-per-layer.md`.

## Контекст

К 31.10.2026 харнесс на Python накопил **семантику**, которую нельзя терять: журнал с хеш-цепочкой и
карантином оборванного хвоста, реестр утверждений с покрытием, гейты, протокол рецензии, пре-регистрация
с печатью, очередь работ с бюджетом. Эта семантика переживёт любую переписку, а вот реализация на Python
— нет:

1. **Инварианты долгоживущие, а рантайм — нет.** Хеш-цепочка и канонизация печати определяются
   поведением Python-словарей и `json.dumps`; смена версии или библиотеки меняет байты.
2. **Песочница.** Наша признанная дыра (C3): Python-обёртки над процессами не дают надёжного контроля.
   На Linux это Landlock/seccomp/namespaces — родная территория Rust.
3. **Один бинарник.** Rust не требует рантайма, ставится копированием, одинаково ведёт себя в WSL,
   контейнере и на железе.
4. **Воспроизводимость сборки.** `cargo` + lockfile + Nix дают то, чего Python-проект с
   `requirements.txt` не даёт.

При этом Python уже дал то, что дороже кода: **проверенные правила** (гейты, коды отказов, формат
утверждений, протокол рецензии) и **эталонное поведение**, с которым можно сверяться.

## Решение

1. **Ядро харнесса — Rust** (`hs-core`): журнал (append, хеш-цепочка, оборванный хвост как карантин),
   печать (канонизация и хеш), реестр утверждений и покрытие, движок гейтов, маршрутизатор инструментов
   с проверкой прав, бюджет прогона, CLI `hs`.
2. **Python остаётся эталонной реализацией и языком экспериментов**: драйверы прогонов, скореры,
   разовая аналитика. Это допустимо, потому что эксперимент одноразов, а инвариант — нет.
3. **Контракт между реализациями — байты.** Rust обязан давать те же хеши и те же решения гейтов на
   одних и тех же входах. Спор «кто прав» решается тест-векторами, а не мнением.
4. **Переход поэтапный, без «большого взрыва»**: каждая часть переносится, только когда её тест-векторы
   совпали; Python-путь продолжает работать до последнего шага.

## Тест-векторы (обязательное условие)

| вектор | что фиксирует |
|---|---|
| `journal` | событие → `prev` + `hash`; канонический JSON; цепочка из N событий |
| `seal` | канонический префикс: CRLF→LF, отсечение после маркера, `rstrip` + `\n`, SHA-256 |
| `coverage` | набор строк реестра → `total`, `closed`, `malformed`, вердикт |
| `gates` | вход → список проблем (порядок и текст) |

Правило: вектор, произведённый Python, **замораживается**; Rust обязан его воспроизвести. Расхождение —
дефект одной из реализаций, и разбирается как дефект, а не как «другая трактовка».

## Следствия

1. Появляется класс «Совместимость реализаций» и гейт, сверяющий векторы.
2. **WSL2 становится осмысленным**: сборка Rust под Linux и проверка песочницы — там, где она есть.
   Решение об ОС (D1) не блокирует ядро, но целевая платформа ядра — Linux.
3. Python-код перестаёт быть «продуктом» и становится спецификацией: его нельзя улучшать в ущерб
   совместимости.
4. Порядок переноса: журнал → печать → покрытие → гейты → инструменты и права → CLI.

## Цена и риск

- Первый срез (журнал + печать + тест-векторы) — дни, не часы.
- Риск: две реализации разойдутся. Лечение — векторы и гейт совместимости; без них перенос не начинается.
- Риск: соблазн переписать всё сразу. Запрещено: переносится то, у чего есть векторы.
