# ADR-0027 — Тип ответа как первый класс

Дата: 29.10.2026. Статус: предложено. Дополняет ADR-0026 (маршрутизация) и REQUEST-PROTOCOL.

## Идея

Мы решали «какой инструмент вызвать». Но более общий вопрос — **что вообще делать**:

| тип | когда | пример |
|---|---|---|
| `EXECUTE` | задача понятна, класс определён | «посчитай, сколько раз встречается слово» |
| `OPTIONS` | два класса близки, выбор меняет инструменты | «проверь документ» — на что смотреть? |
| `CLARIFY` | в задаче неоднозначный термин | «сделай красиво» |
| `SEARCH` | нужен внешний факт, а класс не определён | «что сейчас с курсом» |
| `ASK_PEER` | факт известен только собеседнику | «уточни у владельца» |
| `REFUSE` | действие необратимо без подтверждения | «опубликуй релиз» |

Это ровно те же типы, что в разборе запроса (вопрос / эксперимент / допущение / отказ), но на уровне
**задачи целиком**, а не отдельного фрагмента.

## Почему это важнее выбора инструмента

Оба собеседника могут заблуждаться: и я, и владелец. Когда задача неясна, **догадка — худший
вариант**: она выглядит как работа, но проверять её нечем. Вопрос, предложение вариантов или поиск
вовне — дешевле и честнее.

## Порядок решения

```
ASK_PEER → REFUSE → CLARIFY → SEARCH → OPTIONS → EXECUTE
```

Порядок не случаен: сверху то, что нельзя решить своими силами; ниже — то, что требует всё меньше
внешней информации.

Признаки:

| тип | что ищем в тексте |
|---|---|
| `ASK_PEER` | «что ты решил», «твоё мнение», «уточни у» |
| `REFUSE` | «опубликуй», «оплати», «удали» — без явного «да» |
| `CLARIFY` | «красиво», «оптимально», «быстро», «лучше» |
| `SEARCH` | «сегодня», «курс», «новости», «последний» при неясном классе |
| `OPTIONS` | два класса с разницей близости меньше 0.15 |

## Проверено

```
hs reply "сделай харнесс оптимальным"  → CLARIFY (неоднозначный термин), альтернатива OPTIONS
hs reply "опубликуй изменения"          → REFUSE (необратимо, нужно подтверждение)
```

Шесть тестов, все на посаженных случаях.

## Чего это не даёт

- **Признаки грубые.** Список «неоднозначных» слов — наш, не откалиброванный.
- **Опрос собеседника не гарантирует истины.** Он тоже может заблуждаться; поэтому `ASK_PEER` —
  не «получить истину», а «получить его представление».
- **Нет обратной связи.** Мы пока не измеряем, был ли выбранный тип правильным.

## Как замкнуть

1. Писать в журнал выбранный тип и что произошло дальше.
2. Считать долю `CLARIFY`, после которых задача решилась без дополнительных вопросов.
3. Если доля высока — порог неоднозначности занижен, люди спрашивают лишнее.

## Что это не доказывает

Что шесть типов достаточно. Что порядок приоритетов верен. Что `SEARCH` не подменяет `CLARIFY`:
внешний факт не заменяет понимание задачи.
