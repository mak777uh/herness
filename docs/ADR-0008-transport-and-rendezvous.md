# ADR-0008 — Связь между харнессами: рендеву, транспорт, очередь

Дата: 29.10.2026. Статус: предложено. Дополняет ADR-0007.

## Запрос владельца

«Продумать на будущее VecDHT как неблокируемую связь между харнессами и идеальный обход блокировок».

## Что уже есть (факты, не планы)

VecDHT — `README.md`, кэш справочника, 29.10.2026:

| факт | значение |
|---|---|
| что это | p2p семантическая рендеву-сеть: узел публикует намерение (эмбеддинг + подписанный текст), другой находит его по смыслу |
| устройство | Kademlia, 64 шарда по квантователю, подпись + малый PoW, admission-политика, denylist и отзыв ключей |
| записи | контентно-адресуемые: узел может показать, что ему отдали, третья сторона может проверить |
| зрелость | «≈85 % готовности», оценка; тег и бинарник не выпущены; два хоста ещё не прогонялись |
| измерено | 192 холодных resolve на своём стенде: p95 = 117…257 мс |
| границы | «traffic padding измерен как отсутствующий» — это **не** anonymity-сеть |

Отсюда сразу следует: VecDHT **не является** транспортом для сообщений и **не является** средством
обхода блокировок. Это служба обнаружения. Путать её с Tor — значит обещать то, чего нет.

## Решение: пять слоёв, связанных только контрактом

```
1. Идентичность     Ed25519-ключ узла; адрес = отпечаток ключа. Аккаунтов нет.
2. Рендеву          VecDHT: «кто умеет X» / «кто держит запись Y». Находит пира, не двигает данные.
3. Транспорт        сменный: релей → прямой TLS → обфускация → DHT-оверлей → физический носитель.
4. Очередь          durable outbox: сообщение живёт, пока не подтверждено (at-least-once + dedupe).
5. Содержимое       контентная адресация: артефакты и сообщения адресуются хешем, не потоком.
```

Правило: слои говорят только через контракт. Замена транспорта не должна менять ни рендеву, ни
очередь, ни формат сообщения.

## Почему именно так

1. **Очередь даёт непрерывность и без DHT.** A15 требует, чтобы при обрыве связи работа не терялась.
   Durable outbox решает это сегодня, а завтра тот же outbox уходит в DHT без переделки.
2. **Envelope фиксируется сейчас, транспорт — потом.** Конверт дешево описать и дорого менять позже:
   подпись, id сообщения, run_id, seq, lease — всё это уже нужно для журнала и «одного писателя».
3. **Рендеву и доставка — разные задачи.** Смешав их, получим систему, где смена транспорта
   ломает обнаружение пиров, а смена индекса ломает доставку.

## Лестница устойчивости к блокировкам

Не «идеальный обход», а уровни с ценой и пределом.

| уровень | что делает | когда помогает | что ломает | цена |
|---|---|---|---|---|
| 0. релей у владельца | трафик идёт через свой сервер | блокировки по IP-географии | блокировка IP сервера | низкая |
| 1. TLS + SNI-маскировка | выглядит как обычный сайт | простой DPI по SNI | активный зонд, TLS-fingerprint | низкая |
| 2. Reality / uTLS | заимствует чужой TLS-отпечаток | DPI с отпечатками | блокировка всего класса | средняя |
| 3. QUIC-транспорты (Hysteria/TUIC) | быстрый, устойчив к потерям | мобильные сети, потери | DPI по QUIC | средняя |
| 4. Snowflake / WebRTC | трафик через браузеры-добровольцы | блокировка адресов | мало волонтёров, медленно | высокая |
| 5. DHT-оверлей | сообщение идёт через пиров, без своего IP в контакте | блокировка одного узла | блокировка bootstrap, медленно | высокая |
| 6. Физический носитель | USB, QR, диск | полный шатдаун | не автоматизируется | ручная |

Ключевое: **bootstrap — узкое место любой DHT-схемы.** Если список стартовых узлов блокируется,
сеть мертва, сколько бы пиров ни было. Поэтому источников bootstrap должно быть несколько и они
должны быть разной природы: вшитый список, peer exchange, DNS TXT, QR, физический носитель.

## Что делаем сейчас, не тратя на будущее

| сейчас | зачем это будущее |
|---|---|
| конверт сообщения (подпись, id, run_id, seq, lease) | один и тот же для релея и для DHT |
| durable outbox с подтверждениями | непрерывность A15 сегодня, DHT завтра |
| идентичность = ключ | не нужна миграция аккаунтов при смене транспорта |
| интерфейс `Transport.send(envelope)` | добавление DHT — новый класс, а не правка ядра |
| контентная адресация артефактов | большие данные не должны идти через медленный DHT |

## Чего это не даёт

- **Неблокируемости не существует.** Любой канал можно замедлить, обнулить или заблокировать по
  классу трафика. Мы можем сделать блокировку дороже, а не невозможной.
- **Анонимности нет.** VecDHT прямо пишет, что padding отсутствует; узел-индексник читает то, что держит.
- **Низкой латентности нет.** DHT-маршрут — сотни миллисекунд на resolve, доставка через пиров — секунды.
- **Пустая сеть не защищает.** Сеть из одного узла не обходит блокировки — ей не через кого идти.

## Что это не доказывает

Что VecDHT выдержит цензуру в бою — не проверялось ни на одном хосте вне нашего. Что DHT-транспорт
даст приемлемую скорость для интерактивной работы — не мерили. Что связка «рендеву + outbox» не
создаст петель доставки — не проверяли.
