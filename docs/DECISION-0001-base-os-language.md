# ADR-0001 — База, ОС и язык

Дата: 29.10.2026. Статус: принято (обратимо; каждый пункт имеет условия пересмотра).

## Контекст

Требование владельца: харнесс — средство **точнее очерчивать границы истины**, как и всё
остальное в портфеле; и при этом **быстрее**. Форк установленного DSH запрещён; миграция
поэтапная, без остановки работы.

## D1. База: своя композиция, не форк

Берём установленный `dsh` (или пин `@deepseek-ai/dsh` из npm) как **движок**, а своё строим на
seam'ах: свой `DSH_HOME`, свой профиль, свои плагины.

Почему не форк:

- у cordis «нет привилегированного ядра» — `agent-loop`, `session`, `tools`, `llm` заменяются
  плагином; форк даёт то же самое, но с обязательством тащить 50 пакетов и их темп изменений;
- клон отстаёт от установки (0.1.1 vs 0.2.1) — форк немедленно создаёт дрейф;
- сборка Electron-монорепо на 17,5 ГБ свободного диска — отдельный риск.

Почему не «с нуля»: `llm`-стриминг, схема сообщений, персистентность сессий и песочница — самая
дорогая и самая скучная часть. Переписывать её значит откладывать слой истины, ради которого всё
и делается.

**Условие пересмотра:** если два и более требования из устава (durable-результат инструмента,
супервизия процессов, allowlist HTTP) нельзя закрыть плагином — только тогда обсуждаем форк.

## D2. ОС: Windows остаётся хостом, исполнение — за интерфейсом

Хозяин живёт в Windows-приложении; тулчейн (Lean, Foundry, Python-venv, Node) стоит на Windows.
При этом узкие места именно Windows: `lake build` падает на блокировках `.olean.private`, Rust в
VecDHT требует mingw-w64, а падения job-runner'а (0xE0000008) — Windows-специфичны.

Поэтому: `Executor` — интерфейс с двумя бэкендами с первого дня, `win32-local` и `wsl`. Выбор
бэкенда по умолчанию — **по замеру**, а не по вкусу: эксперимент `E-0001` (одна и та же сборка
Lean + прогон Foundry + `cargo test` на обеих сторонах, по 3 повтора, фиксируем время и долю
падений).

**Условие пересмотра:** если WSL даёт ≥2× меньше падений при сопоставимом времени — исполнение
уезжает в WSL, хост остаётся Windows.

## D3. Язык: TypeScript — рантайм, Python — истина

- **TypeScript** — для плагинов: они исполняются в процессе DSH (cordis), выбора нет.
- **Python** — для слоя истины и оркестратора: гейты `check-claims`, `leak_scan`, `cycle-gate`,
  `library.py` уже на Python, и именно они решают, что считать свидетельством. Дублировать их на
  TS — значит иметь две реализации одного закона.
- **Rust/Go — не в v1.** Супервизия процессов на Node слабее, но цена третьего языка выше
  выигрыша; вернёмся, если упрёмся в конкретный потолок (например, надёжный job-object control).

Граница: Python не вызывает модель и не владеет контекстом; он **судит** прогоны.

## D4. Скорость: что именно ускоряем

Скорость — не «ощущение», а четыре измеряемые величины, каждая со своей командой:

| величина | как мерим | цель v1 |
|---|---|---|
| холодный старт до готовности | `hs bench` (dump-config, без модели) | p50 ≤ 2 с |
| время до первого токена | `hs run` (meta.json) | регистрируем, без цели |
| токенов на задачу | из журнала сессии | −30 % против текущего |
| настенных секунд на задачу | `hs run` | регистрируем |

Механизмы, которые берём у DSH, а не пишем: `compaction-basic`, `compaction-tool-result-pruner`,
`token-meter`; плюс one-shot `headless` вместо Electron-окна для механических прогонов.
