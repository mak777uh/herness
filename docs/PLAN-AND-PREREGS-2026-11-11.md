## 0. Два класса работ и почему они различаются

| класс | что это | что нужно перед работой | пример |
|---|---|---|---|
| **правка записи** | документация приводит себя в соответствие с уже измеренным фактом | критерий приёмки (команда), **без** пре-регистрации | закрыть prereg, поле `fix` которого уже выполнено |
| **новый код / новое измерение** | меняется поведение прибора или появляется новое число | **пре-регистрация**: порог ДО прогона + отрицательный контроль + критерий приёмки |kind внутрь CRC, пиннинг сокета, гейт согласованности |

Отрицательный контроль обязателен для каждого нового кода: тест, который **красный до фикса и
зелёный после**, и посаженный дефект, который детектор обязан поймать. Гейт без отрицательного
контроля — украшение (это главный вывод старого `AUDIT-PLAN.md`: 25 из 27 гейтов проверены только
успехом).

## 3. P1 — плановые этапы (новый код → пре-регистрации)

### P1.1. Этап 1.6 — read-only приёмка (дефект §2.1 подтверждён построчно)
`accept-run.ps1:186` и `crash-resume.ps1:85`: `e2fsck -fy` (чинит улику на месте) + `mount -o loop`
без `ro` + код возврата e2fsck выброшен. ADR-0049:92–94 утверждает «не меняет свидетельство» —
текст противоречит реализации. Нюанс: QEMU убивается жёстко → ext4 грязная; наивный `ro,noload`
отдаст **устаревший** журнал (ресерч Q5: debugfs/ro,noload не накатывают транзакции). Правка:
SHA-256 оригинала до/после; извлечение **с копии** (cp → e2fsck/монтирование копии); либо чистый
экспорт из гостя до убийства; оба скрипта; текст ADR-0049 — отдельной записью.
**Пре-регистрация — §6.2.**

### P1.2. Этап 2.1 — kind внутрь CRC, HSJ1→HSJ2 (дефект §2.2)
`journal.rs:89–106`: crc = SHA256(len+seq ++ payload)[0..4], kind дописывается **после** хеша →
подмена Data(1)↔Commit(2) не детектируется при зелёной CRC. Смежное: `Journal::open` с `start=None`
дописывает поверх оборванного хвоста (run_task_resume обрезает корректно, durable-open — нет).
Перенос kind в хеш меняет формат → **версия HSJ2 через ADR** (судьба старых журналов: отвергать или
мигрировать — решить явно) + fail-closed открытие.
**Пре-регистрация — §6.3. ADR обязателен до кода.**

### P1.3. F-0074 шаг 1 — улики при падении (N8)
`new10_run.py::run_one` выбрасывает stdout/stderr (парсит только «итог:»), журнал при FAIL не
сохраняется → флак N04 (FAIL 190s vs PASS 4 шага) нечем расследовать. Гипотеза fsync правдоподобна
(в пути записи fsync нет), но по правилу это **гипотеза, не диагноз**: сначала улики, потом 3×N04,
потом фикс. Ресерч Q1: различать крах гостя и потерю питания.
**Пре-регистрация — §6.4.**

## 7. Находка C-0206: текст ↔ артефакт (деликатно, не править вслепую)

**Факт.** `CLAIMS.md` C-0206 текст: «по 20 журналам серии MuSiQue… false_completion_rate = 0.00…
принято 5 из 20, цена 0.0393». Якорь — `research/outputs/acceptance-metrics.txt`, колонка ожидания
`false_completion_rate: 0.03`. Артефакт (полная выборка): 60 задач, заявлений «готово» 68,
подтверждено 66, ложных 2 → **0.03 = 2/68** (строка 62). MuSiQue-подвыборка: 21 прогон / 6 принято
(строки T-musique-*).

**Диагноз.** Текст описывает **подвыборку** (0.00 = 0/5 или 0/6), а якорь ведёт на артефакт
**полной выборки** (0.03 = 2/68). `check_artifacts` зелёный, потому что колонка ожидания совпадает
с артефактом, а не с текстом → **зелёный по неверной причине**. Это не противоречие чисел (разные
знаменатели), это расхождение текст↔свидетельство: утверждение ссылается не на тот срез.

**Почему не править вслепую.** Неясно, какой срез владелец хотел утвердить: полную выборку (0.03)
или MuSiQue (0.00). Слепая правка текста под артефакт может уничтожить intended-утверждение о
подвыборке. Нужно решение владельца + отдельный артефакт подвыборки, если утверждается именно он.

**Пре-регистрация исправления (новый код/запись → порог ДО):**

## 9. Расшифровка меток (простыми словами)

| Метка | Что значит |
|---|---|
| **P0/P1/P2/P3** | Приоритет: P0 — целостность свидетельств (до нового кода), P1 — плановые этапы, P2 — оживление приборов, P3 — отложенное |
| **N1–N11** | Новые находки обзора (сверх передачи), с уликами |
| **F-xxxx** | Карточка зафиксированного дефекта или честного отказа; отрицательный результат хранится как результат |
| **E-xxxx** | Эксперимент: пре-регистрация (что меряем, порог) → прогон → вердикт |
| **H-xxxx** | Гипотеза с фальсификатором (чем опровергается) |
| **C-xxxx** | Утверждение в CLAIMS.md со свидетельством и командой; число без команды — не результат |
| **ADR-xxxx** | Запись решения: что решили, почему, какие альтернативы отвергли; смена порога/формата — только через ADR |
| **NC-xxx** | NOT-CLAIMED: явный список того, чего НЕ утверждаем |
| **R1** | Раунд 1 пре-регистрации |
| **HSJ1/HSJ2** | Формат журнала событий ядра; этап 2.1 требует версию HSJ2 (kind в хеше) |
| **tombstone** | Надгробная запись: «строка удалена тогда-то, причина, восстановлена оттуда-то» — защита от тихой потери свидетельства |
| **pass@k / pass^k** | pass@k = хотя бы один успех из k; pass^k = все k успешны; разные метрики, не смешивать |
| **CI (доверительный интервал)** | Границы, в которых лежит истинная вероятность при данном n; 3/3 не значит «100% надёжно» |
| **UNKNOWN** | Честный третий исход: данных недостаточно, не «почти PASS» |
