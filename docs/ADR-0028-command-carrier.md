# ADR-0028 — Носитель утверждения у нас — команда, а не документ

Дата: 29.10.2026. Статус: принято по замеру. Закрывает вопрос, висевший после разбора портфеля.

## Вопрос

Нужен ли нам механизм 2 из портфеля — реестр, где формулировка каждого утверждения дословно
привязана к документу-носителю (`VecDHT/lab/claims.tsv` + `check-claims.py`), — или наш носитель
(команда с ожидаемым значением) это осознанное отличие, и второго реестра не надо.

## Как решали

Не спором. `bin/statements.py` считает **утверждения о состоянии** в закрытых секциях документов и
проверяет, есть ли у каждого владелец: id утверждения, команда, карточка прогона или файл теста.

Ключевое различение, без которого замер врёт: строка «готово: …» в **незакрытом** этапе — это
критерий закрытия (обещание), а не утверждение о факте. Если считать их вместе, получается «50
утверждений без владельца» — и это неправда.

## Что измерено

| файл | утверждений о состоянии | с владельцем |
|---|---|---|
| `docs/STATUS.md` | 8 | 8 |
| `docs/ROADMAP.md` | 1 | 0 → **1 после правки** |
| `README.md`, `docs/VERIFIABILITY.md` | 0 (нет закрытых секций) | — |
| **итого** | **9** | **9 (100 %)** |

## Решение

**Документ-носитель как отдельный механизм не вводим.** Причина: утверждений о состоянии девять, и
все девять уже имеют исполняемого владельца. Второй реестр дублировал бы девять формулировок и добавил
бы обязанность синхронизировать два места — то есть новый класс расхождений, а не новую проверку.

Наш носитель — **команда с ожидаемым значением** (`bin/verify_claims.py`, K115), а для утверждений
без числа — **карточка прогона или файл теста**.

## Когда решение пересматривается

Любое из трёх — по замеру, а не по настроению:

1. утверждений о состоянии стало больше 30;
2. доля с владельцем упала ниже 80 %;
3. появился внешний читатель, которому нужен список утверждений отдельно от документов (например,
   для аудита третьей стороной).

Пересмотр — тем же `bin/statements.py` плюс, при необходимости, `bin/carriers.py`.

## Чего это решение не даёт

- Не ловит утверждение, которое **вообще** не сформулировано в документах (нет строки — нет проверки).
- Не проверяет, что формулировка в документе совпадает с формулировкой в реестре: второго места нет
  по построению.
- Не защищает от дрейфа: если утверждение устарело, его поймает команда, а не документ.
