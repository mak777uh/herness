# HARNESSES — реестр для сравнения подходов

Машинная часть — `harnesses.json`, просмотр — `python bin/harness.py`. Здесь: зачем он, что в нём
проверено и как им пользоваться, когда понадобится сравнить.

## Зачем

Мы не перенимаем чужие решения, а выводим своё. Но прежде чем выводить, полезно знать, где уже
кто-то упирался в ту же стену: тогда вопрос звучит «почему у них так», а не «а как бывает».

Реестр отвечает на три вопроса:

```
python bin/harness.py                    # кто есть и чем полезен для сравнения
python bin/harness.py "восстановление"   # у кого смотреть восстановление после падения
python bin/harness.py --stale            # кто давно не обновлялся (не путать активное с мёртвым)
```

## Что проверено, а что нет

| колонка | как получена |
|---|---|
| `stars`, `license`, `last_push` | **GitHub API, 29.10.2026** — проверено |
| `what`, `when` | наш вывод: зачем смотреть |
| `loop`, `state`, `tools`, `permissions`, `secrets`, `recovery`, `evidence`, `budget`, `multiagent` | из переписи P12, **по ответам моделей, не по коду** |

Свойства помечены только как `есть / частично / нет / нет данных`. Перед использованием в решении —
открыть репозиторий: одна из трёх моделей ошиблась в звёздах на порядок (`153 854` против `~10 000`),
значит и свойствам верить нельзя без проверки.

## Как пользоваться, когда понадобится

1. **Сформулировать свой вопрос как свойство**, а не как фичу: «модель должна знать, что уже
   сделала», а не «нужен state machine».
2. Найти в реестре 2–3 проекта с этим свойством `есть`.
3. Открыть у них **тот файл, где это реализовано**, и ответить: какая цена (сложность, зависимости,
   ограничения) и какая проблема была решена.
4. Сравнить со своей ценой. Если наша ниже — не берём; если выше — берём идею, не код.
5. Записать вывод в `lab/` или в ADR: что посмотрели, что решили, почему.

## Что в реестре уже видно (и пригодится)

- **Универсально:** цикл, инструменты, состояние, восстановление в смысле «resume сессии».
- **Редко:** денежный бюджет с остановкой; отчёт с границами «что не проверялось»; политика секретов
  на уровне содержимого; durable execution без внешнего движка.
- **Модно, но не доказано:** мультиагентность (есть у большинства, замера пользы нет ни у кого).
- **Мёртвое или полумёртвое:** MetaGPT (push 21.01.2026), aider (22.05.2026) — при выборе «на что
  смотреть» это важно, иначе будешь изучать то, что уже не поддерживают.

## Обновление

Числа стареют. Правило: при каждом использовании реестра — обновить `last_push` у тех проектов, на
которые смотришь, и записать дату в `checked_at`. Гейт «харнессы» проверяет обязательные поля,
уникальность id и формат дат, но **не** свежесть — это невозможно проверить без сети.
