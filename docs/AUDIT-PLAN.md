# План аудита — действующие этапы (11.11.2026)

**Заменяет** версию от 01.11.2026 (218 утверждений / 27 гейтов / 33 отказа, P0.1 `gate_probe`).
Та версия описывала аудит реестра; эта — действующий план этапов изоляции и целостности ядра.
**Основание:** `docs/WHERE-I-STOPPED.md` (11.11), находки `F-0081…F-0084`, обзор сессии 11.11
(находки N1–N11) и внешний ресерч (8 вопросов). Детальные пре-регистрации с отрицательными
контролями подготовлены в плане цикла; здесь — карта этапов, статусы и критерии приёмки.

**Правило работы:** пре-регистрация с порогом **ДО** прогона, потом код, потом вердикт.
Смена порога/формата — только через ADR. Отрицательный результат остаётся результатом.

## 2. Этап 1.6 — read-only приёмка (закрыт 11.11.2026)

**Дефект (подтверждён построчно).** `core-rs/accept-run.ps1:186` и `core-rs/crash-resume.ps1:85`:
`e2fsck -fy` (чинит улику на месте, флаг `-y` = «да» на все вопросы) + `mount -o loop` **без `ro`** +
код возврата e2fsck выброшен (`>/dev/null 2>&1`). `docs/ADR-0049:92–94` утверждает «проверка не меняет
свидетельство» — **текст ADR противоречит реализации**.

**Поправка к наивному плану (из ресерча, вопрос 5).** `WHERE-I-STOPPED` предлагал `mount -o ro,noload`.
Это **недостаточно**: QEMU убивается жёстко → ext4 «грязная»; `ro,noload` (и `debugfs`) **не накатывают**
журнал → читают устаревшее закоммиченное состояние. Приёмка начнёт читать вчерашние события и молча
врать. Правильная форма:

- SHA-256 исходного образа **до** и **после** всей процедуры; не совпало → `UNKNOWN`/`FAIL`;
- извлечение журнала — **с копии** образа (`cp` → e2fsck/монтирование уже копии; оригинал не трогаем);
- либо чистый экспорт журнала из гостя до убийства QEMU (гость делает sync и отдаёт файл через мост) —
  тогда e2fsck не нужен вовсе;
- применить к **обоим** скриптам; текст ADR-0049 поправить **отдельной записью**.

**Пре-регистрация (порог ДО прогона):** `READONLY-ACCEPT-R1`.
*Критерий:* SHA-256 оригинала до == после **И** журнал парсится **И** `grep e2fsck core-rs/*.ps1`
показывает только копию.
*Отрицательный контроль:* заведомо грязный образ — оригинал обязан остаться байт-в-байт неизменным;
тест **красный до фикса** (e2fsck -fy на оригинале меняет хеш), **зелёный после**.
*Приёмка:* негативный тест красный до / зелёный после; ADR-0049 поправлен; оба скрипта.

## 3. Этап 2.1 — kind в CRC журнала (закрыт 11.11.2026)

**Дефект.** `core-rs/src/journal.rs:89–106`: `crc = SHA256(len+seq ++ payload)[0..4]`, а `kind`
дописывается **после** хеша → подмена `Data(1)↔Commit(2)` не детектируется при зелёной CRC. Маркер
commit отделяет «заявлено» от «подтверждено» — битый kind меняет смысл записи. Смежное:
`Journal::open` с `start=None` дописывает поверх оборванного хвоста (run_task_resume обрезает
корректно, durable-open — нет) → fail-closed: обрезка с quarantine или отказ открытия.

**Формат меняется → версия HSJ1→HSJ2 через ADR.** Судьба старых журналов (отвергать или мигрировать)
решается **явно в ADR до кода**, а не случайно.

**Пре-регистрация:** `HSJ2-KIND-R1`.
*Отрицательный контроль:* перевернуть байт kind `Data→Commit` — `walk` обязан отвергнуть; до фикса
проходит (это и есть дефект), после — отказ.
*Критерий:* негативный тест переворота kind красный до / зелёный после; тест оборванного хвоста не
теряет записи; 72+ новых тестов зелёные принудительно чистой сборкой.
*Приёмка:* ADR HSJ2 записан; старые HSJ1 ведут себя по ADR; `rust_tests.py` чистит артефакты.

**Итог (11.11.2026).** ADR-0056 принят до кода; prereg `HSJ2-KIND-R1` закрыт. Красный до
(`research/outputs/hsj2-red-before.txt`: Rust rc=101, Python rc=1 «переворот kind ПРОШЁЛ») →
зелёный после (`research/outputs/hsj2-green-after.txt`: Rust 75/0 чистой сборкой, Python
`test_accept` 24/24, `test_forgery`, `test_false_done` 3/3, `test_frame_vector`). Кросс-вектор
кадра `tests/vectors/journal_frame.json` сходится Rust↔Python (CRC `5a81127b`/`1ef3f124`, kind).
`open()` на оборванном хвосте карантинит и обрезает до префикса, записи не теряются. Старые HSJ1
отвергаются fail-closed (не мигрируются). Карточка `F-0086`, утверждение `C-0297`, опыт `E-0018`.

## 6. Что этот план НЕ доказывает

- Что этап 2.1 делает журнал немодифицируемым: CRC кадра — 32 бита, детектор случайной порчи и
  переворота kind **без пересчёта** CRC. Намеренную подделку с пересчётом CRC ловит хеш-цепочка
  событий (`event_hash`) и опора утверждения, не кадр; Node-плагин целостность кадра не проверяет.
  Этап 1.6 закрыт 11.11.2026 (`READONLY-ACCEPT-R1` → `F-0085`, `C-0296`), но его отрицательный
  контроль идёт на чистом disposable-образе — верность чтения реального dirty-образа после kill -9
  отдельно не подтверждена.
- Что закрытые этапы надёжны: проба ловит **известный** дефект, не неизвестный (NC-005). 32 гейта +
  16 проб — не «дефектов нет».
- Что 813 тестов VecDHT актуальны на текущем HEAD: числа из коммита `505edd2`, не перепрогонялись.
- Что ресерч верен для нашего стека: открытые источники → факт только после локальной проверки.
- Что «серия M 9 из 10» была измерена: артефакта нет, число перенесено в NOT-CLAIMED (NC-015).
- Что план оптимален: выведен из текущих чисел и может измениться после оживления приборов.
