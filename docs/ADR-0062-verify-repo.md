# ADR-0062 — herness verify: измерять проверяемость чужого README

**Дата:** 15.11.2026. **Статус:** принято. **Связано:** `VERIFY-REPO-R1`, `E-0027`, `C-0306`, `F-0093`.

## Решение

Первый внешний инструмент харнесса — не комната, не ядро и не сеть. Это `bin/verify_repo.py`:
он отвечает на один вопрос о **чужом** репозитории — *какие числа в README можно воспроизвести,
а какие нет*, и печатает отчёт, квитанцию и границу.

## Почему так

1. **Нулевая установка.** Python + stdlib. Не нужны QEMU, WSL, Lean, ключи и модель.
2. **Результат за 30 секунд.** Один прогон — один отчёт; квитанция хранит sha256 прочитанного README.
3. **Не судит истинность.** «Нет команды» ≠ «ложь». Это различие — то же, что между `anchored` и
   `strict` внутри харнесса (ADR-0058).
4. **Не дублирует MethodSeal.** Тот замораживает методологию и запрещает правку; здесь — измерение
   формы утверждения.

## Две меры, а не одна

- **Широкий счёт** — любая строка с числом вне кода, таблиц и бейджей.
- **Строгий счёт** — где у числа есть единица измерения (тесты, звёзды, загрузки, мс, проценты).
- **Доля** считается по строгому счёту и печатается рядом с широким: иначе число льстило бы себе.

## Граница (объявлена в каждом отчёте)

- Читается только `README*`. `docs/`, `CLAIMS.md`, бенчмарки, CI, таблицы, бейджи и код — не читаются.
- Прогон на пяти репозиториях дал 0–5 строк с числами в прозе: числа живут в таблицах и бейджах.
  Значит «доля 0.00» — свойство текста, а не приговор проекту.
- Инструмент ничего не запускает из чужого репозитория: только читает файл. Это осознанно:
  запуск чужого кода — отдельное решение с отдельными границами.
