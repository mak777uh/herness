# P28 — Решения по серии и как она устроена

Владелец ответил: «эталон я соберу сам из истории, остальное реши оптимально». Здесь решения и
их основания. Всё, что можно было вывести из реестра, — выведено, а не назначено.

## Решения

| вопрос | решение | основание |
|---|---|---|
| эталон | **выведен из `CLAIMS.md`**, а не задан человеком | у каждого утверждения уже есть номер, тип и команда; это перепроверяемо, а мой вкус — нет |
| «другой верный номер» | **по контексту задачи**: `any_of` для «найди утверждение типа X», `exact` для «найди C-0004» | если задача просит любой носитель типа, любой верен; если назван номер — обязан совпасть |
| сколько задач | **9** (4 `any_of` + 5 `exact`) | больше задач при том же числе типов даёт не точность, а повторение; расширять буду по типам, не по количеству |
| вторая модель | **нет** | вторая модель нужна для H-0002, но дешёвая альтернатива отсутствует в закреплённом профиле; подмена модели без измерения её цены — худший вариант |
| публикация | **зона A** (метод, числа, артефакты) | ничего чувствительного: только наши прогоны и реестр |
| деньги | **без лимита**, но с записью расхода каждого прогона в журнал | качество приоритетно; расход и так виден в `step`-событиях |
| провал на задаче | **записываем провал**; задачу не переписываю | переписывание задачи под модель — подгонка (C-0090) |
| рецензент для H-0005 | **программа, не второй LLM** | второй LLM того же семейства наследует те же ошибки и склонен предпочитать свои ответы; механическая перепроверка (артефакт против утверждения) свободна от этого |

## Как устроен набор

`lab/p27/dataset.json` — 9 задач, у каждой: текст для комнаты, критерий приёмки (готовый, из
шаблона), правило судейства и эталонный ключ, плюс `source` — откуда ключ взялся.

Сборка: `python bin/p27_dataset.py` (пересобирает набор из реестра).
Судейство: `python bin/p27_judge.py <task-id> <журнал.bin>`.

Примеры ключей:

- `T-type-statistics`, `any_of`: 29 номеров — любой из них верен;
- `T-exact-C-0004`, `exact`: тип `statistics` и команда `python bin/hs.py bench -n 3` обязаны быть в ответе.

## Почему эталон из реестра, а не мой

Реестр — это то, что проект уже утверждает, с типом и командой проверки. Если я назначаю эталон
сам, я проверяю модель против своего мнения; если эталон выведен из реестра, я проверяю его против
артефакта, который можно перепроверить командой. Разница принципиальная: первое — самоотчёт,
второе — свидетельство.

Ограничение, которое это накладывает: задачи этого семейства проверяют **навигацию и цитирование**,
а не понимание. Для понимания нужен человек — и это записано как граница набора, а не спрятано.

## Рецензент без второго LLM

H-0005 требует «независимого рецензента». Второй LLM — не независимый: он делит с первым
предпочтения и ошибки (это измерено в P25: самопредпочтение исчезает только при слепом дизайне).
Поэтому рецензентом сделана **программа**: она берёт утверждение из отчёта и проверяет его против
артефакта независимо от того, как отчёт написан (`check_artifacts.py`, `verify_answers.py`).
Что она находит — видно; чего не находит (например, что артефакт сам неверен) — записано как граница.

Если понадобится именно второй человек, гипотеза закроется им; сейчас она закрывается как
«проверена механическим рецензентом, человеческий не участвовал» — и это честная формулировка.

## Порядок серии

1. Для каждой задачи: прогон в комнате, критерий объявлен до запуска (лежит в `dataset.json`).
2. Приёмка по журналу (форма, опора, пороги, подтверждение хостом — где включено).
3. Судейство по ключу (`p27_judge.py`).
4. Свод: сколько принято, сколько верно по ключу, где прибор ошибся (в обе стороны).
5. Отчёт в `research/`, утверждение с типом `test` и артефактом.

## Чего в наборе нет и почему

- **Задач на понимание** (объясни, сравни, найди противоречие) — их нельзя проверить ключом из
  реестра; для них нужен человек, и это отдельная серия.
- **Задач с записью** — `write` намеренно не выдан: проверяется чтение и цитирование.
- **Задач на несколько источников** (H-0002) — для них эталон должен быть человеческим: четыре
  файла дают несколько верных ответов, и реестр не говорит, какой из них имелся в виду. Это
  остаётся открытым и записано как открытое.
