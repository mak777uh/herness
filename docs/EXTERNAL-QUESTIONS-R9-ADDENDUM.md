## 1. Проверено по коду (FACT, не мнение)

Ответ A заявил три repro-кандидата. Проверка на снимке:

**FACT-1. `chain.py`: пустой список методов отключает проверку.** Строки 101–104: `methods = _methods(bridge)`; `if adjacent_methods and methods:` — если у downstream `allowed_methods` пуст (или поле отсутствует), цикл сравнения методов не выполняется вовсе. Мини-репро: adjacent `methods=["POST"]`, downstream `allowed_methods=[]` → текущий чекер не выдаёт `K9_DOWNSTREAM_MISSING_METHOD`. Это **не доказанный дефект**: сначала нужно решение владельца о семантике пустого списка — «ничего не разрешено» (тогда дефект) или «без ограничения» (тогда норма, но должна быть записана). См. V1.
Ссылка: [`bin/chain.py`](https://github.com/mak777uh/herness/blob/ce7c64d/bin/chain.py).

**FACT-2. `policy_diff.py` сверяет Lean с переносом Rust-функций, а не с настоящим Rust.** Докстринги `resource_matches` и `policy_allows` говорят прямо: «дословный перенос из `core-rs/src/loopmod.rs`». Мутация логики в `loopmod.rs` прибором не видна. **Уточнение к A:** дрейф 19-против-14 правил с R8 закрыт отдельным гейтом `check_policy_parity.py` — policy.json встроен в бинарь через `include_str!`, ручной копии правил в Rust нет, обязательные deny проверяются, `!` допускается только с deny. То есть класс «пять deny потерялись» закрыт; открыт зазор «сверка с транскрипцией vs исполнение настоящего Rust» (см. S3, X2).
Ссылки: [`bin/policy_diff.py`](https://github.com/mak777uh/herness/blob/ce7c64d/bin/policy_diff.py), [`bin/check_policy_parity.py`](https://github.com/mak777uh/herness/blob/ce7c64d/bin/check_policy_parity.py).

**FACT-3. Словарь K9 уже дрейфует.** `chain.py` содержит шесть кодов: `K9_ADJACENT_REQUIRED`, `K9_CHAIN_UNPROVEN`, `K9_DOWNSTREAM_MISSING_DEST`, `K9_DOWNSTREAM_MISSING_METHOD`, `K9_TAINT_ESCAPE`, `K9_SCHEMA`; в дано R9 перечислены пять. Подтверждает тезис H3 (отказы должны быть типом, не строками).

## 2. Позиции A (сжато; для развилок §3)

- **A1–A2.** Мост первичен как обязательство; уникальна *точка медиации*, а не число сокетов; аудит — read-only-тап того же журнала, не второй мост; «внешнее инициирует» отвергнуто.
- **A3.** Мост = декларативный контракт + один замороженный интерпретатор (~1k LOC); код-мост демонтируется до relay; невыразимое уходит в недоверенные плагины внутри комнаты.
- **A4.** Срез «прочитать→отфильтровать→посчитать» границу не пересекает — это инструмент, а не мост; настоящий мост v1: запиненный upstream, литеральный allowlist, taint `external`, лимиты, 20/20 пре-регистрированных вердиктов.
- **B1–B2.** Канонический JSON как сериализация + семантика в Lean + закрытый каталог законов; один Rust-интерпретатор IR вместо второго списка правил; конформность-гейт исполняет *настоящий* Rust, транскрипция удаляется.
- **B3.** Закон компонируем, iff предикат над join сводок в коммутативном моноиде; три формы: подмножества/аддитивные бюджеты/достижимость на рёбрах; по теореме на форму, не на пару мостов.
- **B4–B5.** Мутанты пяти групп (непустота языка, семантика, идентичность, привязка, мета); язык = total fold ≤3 форм, tripwire: >1500 LOC Rust / >800 строк Lean = редизайн.
- **C1.** Владелец подписывает *семантический конверт* (цель, замыкание, законы, лимиты, NC-выжимка, дельта), байты привязываются сборкой; подпись даёт accountability, не корректность.
- **C2–C3.** Актив — контракты и свидетельства, код — кэш; модель — стохастический компилятор без агентности, ответственность у харнесса за soundness вердикта.
- **C4.** Сплит моста: policy-половина (крошечный TCB, ключ) + relay-половина (недоверенная, изолированная); токен не покидает policy-half.
- **D1.** Стек без VM: uid+caps, pivot_root RO, Landlock *до* exec, инвентарь fd, seccomp, netns, токен через memfd, RESOLVE_* на writable-пути; остаток — 0-day ядра (закрывает только VM).
- **D2.** Таксономия 10 классов «декларация ≠ поведение»; классы 6–8 (side-каналы, семантическое отмывание, человек) не закрываются механически — бюджет/аудит/NC.
- **D3.** Taint 2×2: конфиденциальность {secret, ordinary} × целостность {trusted, external}; разные стоки — egress и control; выход наследует join входов.
- **D4.** K12 `no_untrusted_control` — поправка конституции: external-taint не может быть аргументом write/exec/admit без endorsement-закона; Biba на диспетчере, вне модели.
- **E1–E3.** Композиционная IFC: помеченный граф + одобренные деклассификаторы + достижимость; N-цепочка = один запрос достижимости; одна лемма-гомоморфизм `summary(comp a b) = summary a ⊔ summary b`.
- **E4.** «Доказывай посредника, ограничивай опосредуемое»; верифицировать policy-ядро, relay — confine.
- **F1–F2.** Уровни по неустранимости (A/B на точке решения, C на среде); эксперимент 30 реальных задач, r*=0.30, median(T_reuse) ≤ 0.5·median(T_new).
- **G1–G4.** Иерархия активов: законы > схемы свидетельств > журналы > доказательства ядра > код; 10-элементный минимальный механизм доверия; «строго лучше человека» — условно, при 6 инвариантах.
- **H1–H3.** Политика — проекция IR, законы как Rust-enum; один семантический объект = одно каноническое представление; отказы — перечислимый тип.

## 3. Вопросы независимым моделям (X)

Отвечать из первых принципов, не «голосовать»: по каждому пункту — согласен/не согласен + контрпример или цена.

**X1. «Контракт первичен, код — кэш».** Позиция A: долговечный актив — контракты/законы/свидетельства; пер-мостные доказательства — скоропортящийся дорогой актив. Приведите задачу персонального харнесса, где пер-мостный код с доказательством всё же необходим, и оцените, какая доля реальных задач это (порядок).

**X2. Три формы законов.** Подмножества / аддитивные бюджеты / достижимость на рёбрах. Полны ли они для вашего списка реальных задач? Контрпример закона, который нужен и не ложится ни в одну форму, — и что тогда: расширение форм (по A — редизайн) или отказ от задачи.

**X3. Taint 2×2 + control-сток.** Достаточен ли словарь {secret, ordinary} × {trusted, external}? Как в нём жить с «сессионной гранулярностью» (после любого внешнего чтения сессия заражена) без массовых ложных отказов: где деклассификация, кто её подписывает, что мешает модели её «выпросить».

**X4. K12 `no_untrusted_control` как поправка конституции.** Да/нет? Если нет — какой *обеспечиваемый* механизм заменяет (не «дисциплина модели»)? Если да — сформулируйте закон одной фразой и его негативный контроль.

**X5. Сплит моста policy/relay.** Кто держит токен, кто делает TLS, кто парсит враждебные байты? Не создаёт ли relay нового confused deputy? Сравните с provider-side scoped tokens (короткоживущий ключ на запрос) — что дешевле и что безопаснее.

**X6. HTTP → кадры (vsock/unix) на границе комната↔мост.** Цена 2–3 дня, выигрыш — минус парсер/методы/редиректы. Что теряется (curl-отладка, SSE/стриминг, совместимость инструментов)? Есть ли аргумент оставить HTTP, но канонизировать его жёстко?

**X7. Изоляция без VM.** uid+caps + pivot_root RO + Landlock *до* exec + инвентарь fd + seccomp + netns + memfd-токен + RESOLVE_*. Закрывает ли это NC-017/018-классы полностью? Какие два класса остаются и при каком условии VM становится обязательным, а не «потолком».

**X8. Веха `K9_kernel_proven`.** Критерий A: IR-исполнение вместо рукописного списка + конформность Lean≍настоящий Rust на корпусе с мутантами + мета-мутант краснит CI. Согласны? Постройте атаку, которая проходит между `K9_kernel_proven` и полным `K9_proven`.

**X9. Инварианты «ИИ-генерация строго лучше человека».** Шесть инвариантов A (полнота проверки, owner-спецификация, непустота, дешёвая проверка доказательств, нет ambient-полномочий, детерминированная привязка). Какой из них в herness нарушен уже сегодня — по фактам §1 — и что чинить первым?

**X10. Эксперимент F2.** 30 реальных задач, r*=0.30 точных совпадений канонической сигнатуры, median(T_reuse) ≤ 0.5·median(T_new). Корректны ли пороги? Что измерять, чтобы r не был мусором (канонизация сигнатуры, «похожие» контракты)? Предложите лучший дизайн, если этот плох.
