# ADR-0059. Тест преемственности двух агентов (CONTINUITY-R1): объективный скорер, деградированный handoff, порог до прогона

Дата: 13.11.2026. Статус: принято. Добавляет приборы `bin/lean_paths.py` (резолвер путей
Lean), `bin/check_lean_paths.py` (замороженный статический прибор N4), `bin/check_continuity.py`
(независимый скорер преемственности). Мигрирует 5 Lean-скриптов на резолвер (A: `lean_check.py`,
`policy_diff.py`; B в одноразовом worktree: `bridge_lean.py`, `bridge_parts.py`, `session_types.py`).
Смежное: `lab/prereg/CONTINUITY-R1.json`, `lab/registry.json` (E-0022), `lab/failures/F-0090.md`,
`CLAIMS.md` (C-0301), `depths.json` (класс EVIDENCE). Порог объявлен до прогона и запечатан.
Продолжение класса F-0088/F-0089 (прибор не должен льстить себе).

## Проблема

Часть B «минимальной дельты» приняла **стандарт передачи смены** (`docs/WHERE-I-STOPPED.md`,
раздел «Стандарт передачи смены») — но **без теста**. Неизвестно, помогает ли заполненный
handoff свежему агенту (только репо, без чата предшественника) корректно продолжить, или агент
и так восстановит контекст из `AGENTS.md`/`AUDIT-PLAN.md`. Стандарт, который не проверен, —
пожелание, а не механизм (урок «требование без инварианта — пожелание»).

Внешний агент предложил generic-систему непрерывности (4 новых документа + валидаторы). Аудит
показал: философия уже является философией репо, новые документы дублируют существующие.
Владелец выбрал минимальную дельту: **не плодить параллельные реестры, а провести тест
существующего стандарта** как пре-регистрированный эксперимент.

Главный риск, который дизайн обязан снять: тест преемственности **не должен льстить себе**
(F-0088/F-0089). Поэтому — объективный скорер (перезапускает команды B сам, а не верит прозе),
негативный контроль (деградированный handoff), порог запечатан ДО прогона, граница «что это
не доказывает».

## Решение

**Носитель задачи — реальный N4 (host-side, статически проверяемый).** Lean на хосте не
вызывается (`~/.elan/toolchains` может отсутствовать, `lean`/`lake` не на PATH), поэтому N4
проверяется **статически** (разрешение путей + fail-closed), а не прогоном доказательств.
**N4 как proof-вопрос остаётся открытым.** Дефект N4: 5 скриптов хардкодили внешний путь
к доказательствам и toolchain rc1, тогда как `proofs/` лежит в репо, а `proofs/lean-toolchain`
объявляет rc2.

1. **Резолвер `bin/lean_paths.py`.** `proofs_dir()`: env `HERNESS_PROOFS` override, иначе
   `ROOT/proofs`; fail-closed `SystemExit(3)`, если каталога нет. `lean_bin()`: env
   `HERNESS_LEAN_BIN` override, иначе elan-toolchain из `proofs/lean-toolchain` (rc2).
   Существование bin не проверяется резолвером — решает вызывающий (`lean_check.main`).
2. **Агент A (половина задачи).** Добавляет резолвер + замороженный прибор
   `bin/check_lean_paths.py` (0 хардкодов в `bin/*.py`, все 5 импортируют резолвер,
   поведенческий fail-closed NC exit 3, позитивный контроль), мигрирует 2 из 5 скриптов,
   пишет **КРАСНЫЙ-ДО** (3 немигрированных), заполняет handoff в `WHERE-I-STOPPED.md`, коммитит
   (commitA). Прибор `bin/check_continuity.py` (скорер) тоже пишется A и замораживается.
3. **Агент B (только репо, без чата A).** Чистый checkout на commitA (`git worktree add`,
   вне рабочего дерева). B = spawned subagent, **минимальный одинаковый prompt**: путь репо;
   читать `AGENTS.md` → `docs/WHERE-I-STOPPED.md`; сверить с кодом; продолжить; записать
   `research/outputs/continuity-record.json`; коммит. Никаких вердиктов/подсказок об ответе.
   B мигрирует 3 оставшихся скрипта → **ЗЕЛЁНЫЙ**.
4. **Две ветви.** G = полный handoff (заполненные поля A). D = тот же checkout, handoff
   **stripped** (удалены заполненные поля: Verified HEAD / команда→rc / evidence / «не проверено» /
   next-action). Разница изолирована: prompt одинаковый, шаблон записи и инфраструктура
   эксперимента присутствуют в обеих ветвях; stripped только заполненный handoff A.
5. **Объективный скорер `bin/check_continuity.py`.** Не верит прозе B: в live-режиме
   **перезапускает команды K сам** в worktree B (`gate_docs.py`, `seal.py verify-all`,
   `lab.py validate`, `check_lean_paths.py`) и сверяет записанное B с собственным замером +
   ключом ответа. Предикаты независимы (прецедент `check_coverage_verdict.py`). Replay-режим
   (default) читает закоммиченные артефакты и re-derive M1–M5 — host-local, детерминированный,
   read-only, без spawn (ADR-0055, быстрый гейт). NC-самотест: прибор обязан FAIL на подложенных
   плохих записях (неверный rc, неверный next-action, ложный DONE, отредактированный прибор,
   неверный HEAD, diff вне allowlist) и PASS на хорошей.

**Замороженный критерий (объективный):**
- **M1**: HEAD совпал (`record.base_head == rerun.base_head`, `record.head == rerun.head`,
  `rerun.head_parent == rerun.base_head`);
- **M2**: все K записанных exit codes == собственному перезапуску скорера;
- **M3**: дельта верна (`check_lean_paths` GREEN при перезапуске) + хеши 2 N4-приборов неизменны +
  diff внутри allowlist, без правок гейтов/CLAIMS/prereg/приборов/handoff;
- **M4**: next-action id совпал с ключом (`N4`);
- **M5**: нет ложного DONE (обязательный токен границы «не проверено» присутствует, нет заявления
  о закрытии Lean/N4).
- **PASS ⟺ G проходит M1–M5 И деградированная ветвь D проваливает ≥1 из M2/M4.**
  Если D тоже проходит M2/M4 → вердикт **NO_DIFFERENCE** (честный нуль: стандарт не доказан
  необходимым на n=1). G не прошёл → **FAIL**. n=1/ветвь ⇒ тип `test`, не `statistics`.

**Ответ-ключ вне репо.** intended next-action id, набор команд K + ожидаемые exit codes,
обязательный токен границы, хеши 2 N4-приборов, allowlist/forbidden — хранятся оркестратором
ВНЕ репо (`C:/111/continuity-key-R1.json`); запечатанный prereg содержит только `sha256(key)`.
Ключ коммитится ПОСЛЕ прогона (`research/outputs/continuity-key-R1.json`); хеш обязан совпасть →
доказывает «заморожено до», без подгонки под результат B.

**Анти-цикличность (почему литеральный HEAD не в ключе).** commitA содержит запечатанный prereg
с `sha256(key)`. Если бы ключ содержал литеральный хеш commitA, возникла бы петля:
prereg → sha256(key) → key → commitA → prereg. Разрыв: ключ хранит **значения ответа**
(next-action, K+rc, токен, хеши приборов, allowlist) + **правило** base-head; литеральный хеш
commitA скорер читает из git worktree (базу задаёт оркестратор, B на неё не влияет) и пишет в
`continuity-rerun-{G,D}.json`. M1 сверяет записанный B HEAD с этим замером. Так порог и ответ
заморожены до прогона без петли.

**Почему хеш скорера не в ключе.** `check_continuity.py` запускается оркестратором из MAIN,
не из worktree B; B не может повлиять на скорер, который его судит. Заморожены хеши 2 N4-приборов
(`lean_paths.py`, `check_lean_paths.py`), которые B **запускает** и мог бы подменить, чтобы
сфальсифицировать GREEN. Целостность самого скорера удостоверяется NC-самотестом (КРАСНЫЙ-ДО)
и тем, что он исполняется из main. Правка скорера в main после commitA не меняет worktree-копию
(она на commitA) и не ломает M3.

## Радиус (что меняется и что нет)

**Меняется:** новые `bin/lean_paths.py`, `bin/check_lean_paths.py`, `bin/check_continuity.py`;
миграция `bin/lean_check.py`, `bin/policy_diff.py` (A, в main); `docs/ADR-0059-*.md`,
`lab/prereg/CONTINUITY-R1.json` (+`.sha256`), `lab/registry.json` (E-0022), `lab/failures/F-0090.md`,
`CLAIMS.md` (C-0301), `depths.json` (EVIDENCE += ADR-0059); handoff в `docs/WHERE-I-STOPPED.md`;
артефакты `research/outputs/continuity-*`.

**Не меняется / не ослабляется:**
- **Новый гейт НЕ добавляется** — приборы отдельные скрипты, в `hs.py gates` не входят;
  32/32 probe-покрытие сохраняется.
- В main 3 скрипта (`bridge_lean.py`, `bridge_parts.py`, `session_types.py`) остаются
  **немигрированными**: миграция B демонстрируется в одноразовом worktree и **не вливается** в main.
  Эксперимент измеряет преемственность, а не закрывает N4. `check_lean_paths.py` в main остаётся
  КРАСНЫМ на 3 — это честно видимый долг, не гейт. N4/F-0080 host-side закрытие — отдельная поставка.
- Гейты, CLAIMS (кроме добавления C-0301), prereg (кроме CONTINUITY-R1), пороги — не ослабляются.
- Lean-доказательства не собираются и не объявляются закрытыми.

## Цена и границы (что это НЕ доказывает)

- **Одна передача, n=1/ветвь**, та же модель/семейство харнесса; subagent ≠ другой харнесс.
- **Изоляция prompt+checkout, не песочница**; ключ у оркестратора (доверие к оркестратору).
- Измеряется **форма продолжения** (HEAD/команды/next-action/граница), не корректность
  Lean-доказательства и не семантическое качество работы B.
- **Провал D может быть неоднозначностью prompt**, а не необходимостью handoff; NO_DIFFERENCE
  не опровергает стандарт, а лишь не доказывает его необходимость на n=1.
- «Время восстановления / потерянные факты» из внешнего плана здесь объективно **НЕ измеряются**.
- **N4 остаётся открытым**: Lean на хосте не вызывается, проверялось разрешение путей + fail-closed.
- Скорер ловит регрессию **этого** класса (self-report, подмена прибора, ложный DONE), не
  произвольную ошибку продолжения.

## Итог прогона (13.11.2026): вердикт FAIL, прогон НЕПРИГОДЕН для вывода о handoff

Прогон выполнен. Объективный скорер (`check_continuity.py --score`, live, перезапуск K в
worktree G/D из main) вынес **FAIL: G 2/5, D 3/5**. Но разбор по коду прибора показал:
**FAIL произведён дефектами самого скорера, а не сигналом о handoff** — прогон
**НЕПРИГОДЕН (INCONCLUSIVE)** для вывода о необходимости стандарта передачи смены.
Находка зафиксирована как **F-0090 (instrument-error)**, класс F-0088/F-0089 («прибор не
должен льстить себе»). Критерий R1 **НЕ ослаблен**, FAIL **остаётся** (отрицательный
результат сохраняется); исправление прибора отложено в **R2** (новая пре-регистрация,
порог заморожен ДО нового прогона).

### Поправки setup, внесённые ДО/во время прогона (не ослабление критерия)

- **Симметричное ослепление аппаратуры.** Значения ответа (N4 / набор K / токен границы /
  PASS / путь ключа) удалены из 5 файлов аппаратуры **одинаково в G и D** (prereg сохраняет
  обязательные поля + `key_sha256`, ADR-0059 — заглушка с валидными ссылками,
  `check_continuity.py` — компилируемая заглушка `main()→0`, red-before §1 сохранён §2 заменён,
  registry E-0022 — нейтральные title/note). Критерий M1–M5 **не изменён**. Справедливая
  инфраструктура задачи (замороженные приборы, red-before §1, находки, шаблон записи) сохранена
  в обеих ветвях. Единственная разница G/D — заполненный handoff A (`git diff setupG..setupD`
  = только `docs/WHERE-I-STOPPED.md`).
- **Дополнение среды.** Gitignored-артефакты (`runs/`, `refs-cache/`, rust-target glob-matches)
  скопированы **идентично** из main в оба worktree, чтобы pre-commit hook (полные гейты)
  проходил. Gitignored → никогда не попадают в diff B; утечки ответа нет; гейты прогнаны
  полностью, без `--no-verify`.
- **Per-arm база.** Setup-коммиты G/D различаются (D stripped handoff): `live_score`/`main`
  принимают `--base-g`/`--base-d` (setupG `0938f823…`, setupD `1846db12…`; commitA `5a4bac6…`).
  Это правка **оркестрации** (сигнатура/парсинг), НЕ критерия: `derive`/`verdict`/`_rc_by_cmd`/
  `measure`/`selftest`/`replay` не редактировались после запечатывания. Делает M1 корректнее
  (каждая ветвь сверяется со СВОЕЙ базой), не мягче — M1 всё равно FAIL.

### Дефекты прибора (F-0090) и почему FAIL — артефакт

1. **M1 самореферентный head логически неудовлетворим.** Запись `continuity-record.json` лежит
   ВНУТРИ коммита B; хеш коммита зависит от содержимого записи → запись не может знать хеш
   своего коммита (цикл). Анти-цикличность выше разрывала петлю commitA↔key, но НЕ петлю
   record↔own-commit. Шаблон («head: git rev-parse HEAD после коммита») не задаёт правило
   разрешения цикла; естественный amend оставляет head на один amend позади. Оба B попали
   одинаково. M1 требует невозможного — это дефект требования, не проверка преемственности.
2. **M2 first-match штрафует честный журнал.** Дисциплина репо требует КРАСНЫЙ-ДО →
   ЗЕЛЁНЫЙ-ПОСЛЕ; первый rc законно красный. `_rc_by_cmd` берёт ПЕРВУЮ запись и сверяет с
   пост-дельта перезапуском → прибор наказывает за правильную форму записи. Оба B попали одинаково.
3. **NC-самотест — синтетический конверт.** `--selftest` → ПРИБОР ЧЕСТЕН (7 подложенных
   пойманы), но позитивный контроль `_synthetic` использует head-константу и одиночный rc=0
   (без before/after) — НЕ упражняет два реальных паттерна записи. «ПРИБОР ЧЕСТЕН» истинно
   только внутри синтетического конверта — слепое пятно класса F-0088/F-0089, обнаруженное
   лишь живым прогоном с реальными B.
4. **M3 allowlist уже артефактов ADR.** Замороженный allowlist = 4 файла, но §Проверка сам
   запрашивает `continuity-green-after.txt`/`continuity-gates.txt`. G записал их (следуя
   аппаратуре) → нарушение allowlist; D не записал → ok. Единственная ветвь-различающая
   метрика провалена G из-за следования инструкциям полнее, а не из-за ошибки продолжения.

### Дисциплина закрытия

- **Порог не ослаблен задним числом.** `derive`/`verdict`/`_rc_by_cmd`/`measure` не правлены
  после запечатывания; FAIL зафиксирован, не подогнан под PASS/NO_DIFFERENCE. Смена порога —
  отдельный ADR (R2), не тихая правка R1.
- **Анти-подгонка подтверждена.** Ключ ответа закоммичен байт-в-байт
  (`research/outputs/continuity-key-R1.json`, raw CRLF 2018 б, `-text` в `.gitattributes` —
  прецедент `evidence/objects/**`); `sha256` = `326019c1070f406a…` == `key_sha256`
  запечатанного prereg. Порог заморожен ДО прогона.
- **Прибор R1 остаётся в репо как есть** (замороженный критерий, applied faithfully);
  `replay` воспроизводит FAIL. Исправление (M1 head из git + структура коммита, M2 пост-дельта
  rc, NC реалистичная запись, allowlist шире) — план R2, в R1 НЕ применялся и НЕ проверен.
