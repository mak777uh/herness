# ADR-0013 — Резервные сети, onion и P2P: каталог и порядок внедрения

Дата: 29.10.2026. Статус: рассмотрено, внедряется частично. Дополняет ADR-0008.

## Три задачи, которые нельзя смешивать

| задача | что нужно | чем не решается |
|---|---|---|
| **Доступность** | связь при падении основного канала | скрытие адреса не помогает, если сервер за NAT |
| **Скрытие адреса** | узел не раскрывает IP | не спасает от блокировки по классу трафика |
| **Обход блокировки** | трафик проходит при фильтрации | не даёт анонимности |

Один транспорт редко закрывает все три. Поэтому нужен **набор** с независимыми режимами отказа.

## Каталог

| транспорт | доступность | скрывает адрес | обход блокировки | латентность | цена | роль у нас |
|---|---|---|---|---|---|---|
| прямой HTTPS | зависит от сети | нет | нет | низкая | нет | базовый |
| релей у владельца | да | клиента — да, свой — нет | по IP-географии | низкая | сервер | T0, сейчас |
| VLESS/Reality | да | нет | сильная | низкая | средняя | T0b, при блокировке |
| QUIC (Hysteria/TUIC) | да | нет | средняя | низкая | средняя | T0b |
| **Tor onion-сервис** | **да, без проброса портов** | **да** | средняя (нужны мосты) | высокая (секунды) | низкая | **T1** |
| I2P | да | да | средняя | высокая | средняя | T2, если Tor не годится |
| Snowflake/WebRTC | да | да | да | очень высокая | зависит от волонтёров | T3, крайний |
| **P2P-оверлей (VecDHT)** | да | частично | сильная | средняя (сотни мс на resolve) | сложность | **T2**, рендеву уже есть |
| libp2p / BEP44 | да | частично | сильная | средняя | сложность | T2, альтернатива |
| Nostr-релеи | да, store-and-forward | нет | слабая | средняя | низкая | T2, обмен сообщениями |
| Matrix-федерация | да | нет | слабая | средняя | высокая | не берём |
| флешка / QR | да | да | **полная** | ручная | ручная | T4, аварийный |

## Что берём сейчас

**T0 — релей + HTTPS.** Уже описано в ADR-0007: один канал с политикой и журналом.

**T1 — onion-сервис.** Причина не в цензуре, а в **NAT**: сервер за NAT/CGNAT не примет входящее
соединение без проброса портов, а onion-адрес даёт входящий канал без портов и без публичного IP.
Это дешёво (tor + один сервис), обратимо и не требует менять остальное.

**T2 — P2P-рендеву через VecDHT**, когда он выйдет из «85 % готовности». Роль строго одна: найти
пира и его актуальный адрес. Передача сообщений — по выбранному транспорту, не через DHT.

**T3/T4 — Snowflake и физический носитель.** Только как записанный резерв, внедрение по факту
необходимости.

## Инварианты (те же, что в ADR-0008)

1. **Конверт один для всех транспортов**: подпись, id сообщения, run_id, seq, lease.
2. **Маршрут фиксируется на прогон.** Смена транспорта посреди прогона = другой прогон.
3. **Никакого молчаливого переключения** (E4): падение маршрута — ошибка с кодом, а не «пошли
   напрямую».
4. **Дедупликация по id сообщения**, а не по транспорту: одно сообщение может прийти двумя путями.
5. **Офлайн-режим существует**: если все пути мертвы, работа продолжается локально и досылает потом.

## Порядок и критерии

| этап | что | критерий готовности |
|---|---|---|
| T0 | релей + политика | внешний запрос идёт только через релей, журнал полон |
| T1 | onion-сервис | клиент подключается к серверу за NAT без проброса портов; латентность измерена |
| T2 | рендеву VecDHT | пир найден по смыслу; адрес получен; сообщение доставлено другим транспортом |
| T3 | Snowflake | подключение работает, латентность и надёжность измерены |
| T4 | носитель | сообщение доставлено без сети, подпись проверена |

## Риски

- **Tor блокируется и в РФ, и в других странах**; без мостов он не панацея. Утверждение требует
  проверки (P8), а не веры.
- **Onion-латентность в секундах** — не годится для интерактива, годится для фоновой синхронизации.
- **P2P-оверлей без пиров бесполезен**: сеть из одного узла не обходит ничего (NC-013).
- **Каждый транспорт — отдельная поверхность атаки и отдельная строка эксплуатации.**

## Что это не доказывает

Что onion-сервис доступен из нашей сети. Что VecDHT выйдет из беты в обозримом времени. Что
резервный путь не окажется медленнее, чем отсутствие связи.
