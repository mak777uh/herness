# ADR-0058. Покрытие различает «якорено» и «строго проверяемо»; вердикт не льстит себе

Дата: 12.11.2026. Статус: принято. Меняет измерение покрытия утверждений в `bin/coverage.py`
(вердикт, JSON, stdout), `bin/audit.py` (строка отчёта + WARN), `bin/hs.py` (`gate_coverage` —
drift-поля), `bin/readme_numbers.py` (строка «строгое покрытие»), `tests/test_coverage.py`
(усиление). Смежное: `bin/claims_audit.py` переводится на общий модуль предикатов
`bin/claim_strength.py`; новый прибор-проверщик `bin/check_coverage_verdict.py`. Порог объявлен
до кода — `lab/prereg/COVERAGE-VERDICT-R1.json`. Продолжение класса F-0088 (прибор льстит себе).

## Дефект

`coverage.py` — прибор флагманского числа репо («покрытие 1.00, `CHECKED_ANCHORED`»). Запись
считается закрытой (`closed`), если у неё есть команда, артефакт (не `—`), непустое ожидание, и
артефакт-путь разрешается — **но только если в артефакте есть «/»** (`coverage.py:61`). Прибор
меряет НАЛИЧИЕ ПОЛЕЙ, а не проверяемость:

1. **Слабые ожидания не различаются.** Ожидание «ок», «done», «итог: PASS», «ПРИБОР ЧЕСТЕН» —
   слово, которое подтверждает себя собой (`claims_audit.py` зовёт это `слабым`). `coverage.py`
   проверяет лишь непустоту ожидания, не его falsifiable-форму (число/путь/код). Таких — **108**.
2. **Артефакты-описания не проверяются.** «вывод команды, 08.11.2026» не содержит «/», поэтому
   `coverage.py:61` не проверяет его существование — файла нет, а запись «закрыта». Таких — **23**.

Замер командой (не на веру), 299 строк, 3 отозвано, 296 активных:

| мера | значение | что значит |
|---|---|---|
| anchored (`coverage.py` сейчас) | 296/296 = **1.00** | поля заполнены, путь-артефакт разрешается |
| strict (исполняемая команда + артефакт-файл существует + ожидание-число/путь/код) | 172/296 = **0.58** | то, что нельзя придумать и можно сверить |
| слабых ожиданий | 108 | слово, не число/путь/код |
| артефактов-описаний | 23 | не путь, файла нет |

Прибор льстит себе: headline `1.00 CHECKED_ANCHORED` не различает «якорено» и «строго проверяемо».
`claims_audit.py` сообщает 108 слабых, но всегда `return 0` — мера **advisory, не enforced**: билд
остаётся зелёным. `tests/test_coverage.py` case 2 закрепляет лесть: утверждение со слабым ожиданием
`ok` даёт `CHECKED_ANCHORED`. Это тот же класс, что F-0088: измеритель выдаёт удобное число.

## Решение

1. **Две меры, не одна.** `coverage.py` считает и `anchored` (как сейчас: поля + путь), и `strict`
   (исполняемая команда + артефакт-файл существует + falsifiable ожидание). Обе — в stdout и JSON
   (`strict_closed`, `strict_coverage`, `weak_expects`, `descriptive_artifacts`). Поле `coverage`
   остаётся anchored (инвариант аудита `coverage>=1.0` и `readme_numbers` не ломаются).
2. **Вердикт понижается на слабом ожидании.** Тиры lexspec (ADR-0034 §9) сохранены, добавлен один:
   - anchored < 0.8 → `REFUSED`;
   - 0.8 ≤ anchored < 1.0 → `CHECKED`;
   - anchored = 1.0 **и** strict = 1.0 → `CHECKED_ANCHORED`;
   - anchored = 1.0 **и** strict < 1.0 → **`ANCHORED_WEAK`** (новый: якорено, но не строго проверено).
   Реальный репо: anchored 1.00, strict 0.58 → вердикт `ANCHORED_WEAK` (понижен с `CHECKED_ANCHORED`).
3. **Общий модуль предикатов** `bin/claim_strength.py`: `looks_checkable(expect)`, `is_runnable(cmd)`,
   `artifact_resolves(artifact, root)`. `coverage.py` и `claims_audit.py` импортируют его — одна
   реализация, без расхождения (как `policy_sync`). `claims_audit` перестаёт быть advisory: его мера
   (слабые ожидания) теперь в вердикте покрытия и drift-полях `gate_coverage`.
4. **`gate_coverage` усилен (не ослаблен).** Drift-сверка stored↔fresh расширяется с
   `total/closed/malformed/verdict` до `+strict_coverage/weak_expects/descriptive_artifacts`.
   Подложенное слабое ожидание меняет эти поля → гейт ловит рассинхрон, если артефакт не перегенерирован.
5. **Тест усилен.** `test_coverage.py` case 2 переводится на СТРОГОЕ ожидание (полное закрытие +
   strict → `CHECKED_ANCHORED`, инвариант сохранён); добавлены case «слабое ожидание → `ANCHORED_WEAK`»
   и case «артефакт-описание → не strict». Отрицательный контроль: прибор обязан различать.
6. **Отчёт несёт обе меры рядом.** `audit.py`: «покрытие: 1.0 (якорено) · строгое: 0.58 · вердикт:
   ANCHORED_WEAK» + WARN «слабых ожиданий: 108, артефактов-описаний: 23». `readme_numbers` добавляет
   строку «строгое покрытие». Headline больше не показывается без оговорки.

## Радиус (что меняется и что нет)

**Меняется:** `bin/coverage.py` (strict-мера, вердикт-тир `ANCHORED_WEAK`, JSON-поля, stdout);
`bin/claim_strength.py` (новый, общие предикаты); `bin/claims_audit.py` (импорт общего модуля);
`bin/hs.py` (`gate_coverage` +3 drift-поля); `bin/audit.py` (строка отчёта + WARN);
`bin/readme_numbers.py` (строка «строгое покрытие»); `tests/test_coverage.py` (усиление);
`bin/check_coverage_verdict.py` (новый, прибор-проверщик); README (числа + граница); `depths.json`
(ADR-0058 в классе EVIDENCE).

**Не меняется / не ослабляется:**
- anchored-порог `coverage>=1.0 → rc 0` сохранён; инвариант аудита `coverage<1.0 → FAIL` не тронут;
  билд остаётся зелёным (strict — мера и вердикт, не rc-порог).
- Тиры lexspec `REFUSED/CHECKED/CHECKED_ANCHORED` сохранены; `ANCHORED_WEAK` — добавка, не замена.
- `test_coverage.py` case 1 (битая строка в знаменателе) и case 3 (незакрытая → `REFUSED`) не тронуты;
  case 2 сохранён для строгих записей. Тест усилен, не ослаблен.
- C-0069 («`CHECKED_ANCHORED` только при полном закрытии») остаётся истинным: полное закрытие —
  необходимое условие вердикта (теперь ещё и strict). Expect C-0069 — `провалов: 0` (тест проходит).
- `verify_claims.py` не меняется: он и так грепает ожидание в выводе исполняемой команды (строка 108)
  и фейлит неисполняемую с ожиданием (104–107). Дефект — в мере покрытия, не в прогонe.

## Цена и границы (что это НЕ доказывает)

- **strict 0.58 — не «42% утверждений ложны».** Это доля записей без машинно-проверяемого ожидания
  по СТРОГОМУ правилу формы (число/путь/код). Часть слабых ожиданий («итог: PASS», «ПРИБОР ЧЕСТЕН»)
  всё же falsifiable — `verify_claims` их грепает; правило формы их переоценивает как слабые. Прибор
  различает форму, не смысл.
- **anchored 1.00 по-прежнему не «утверждения истинны».** Сверяется наличие команды/артефакта и
  (теперь) форма ожидания, не содержание. Истина — за `verify_claims` и смыслом, не за покрытием.
- **Прибор проверяет прибор, не истину.** `check_coverage_verdict.py` сверяет сообщённое покрытие с
  независимым ground-truth; ловит регрессию ЭТОГО дефекта (честность вердикта), не произвольную ошибку.
- **Общий модуль предикатов — одна реализация, не доказательство.** `looks_checkable` — эвристика
  формы (цифра/путь/код), не семантический анализ; её можно улучшить отдельным ADR.
- Не доказывает, что найденные долги — все, и что 108 слабых ожиданий можно усилить без живых прогонов.

## Проверка

Красный ДО — `research/outputs/coverage-verdict-red-before.txt`: `bin/check_coverage_verdict.py` на
текущем `coverage.py` → FAIL «ПРИБОР ЛЬСТИТ» (сообщает 1.00 `CHECKED_ANCHORED`, strict-меры нет;
ground-truth strict 0.58, 108 слабых, 23 описания; подложенное слабое ожидание вердикт не меняет).
Зелёный ПОСЛЕ — `research/outputs/coverage-verdict-green-after.txt`: после фикса → PASS «ПРИБОР ЧЕСТЕН»
(вердикт `ANCHORED_WEAK`, strict 0.58 и counts совпадают с ground-truth; подложенное слабое ожидание
понижает strict/вердикт — прибор различает).

- `bin/check_coverage_verdict.py` — независимая сверка; красный до, зелёный после (негативный контроль).
- `python bin/coverage.py CLAIMS.md` → anchored 1.00, strict 0.58, вердикт `ANCHORED_WEAK`. Замер
  дефекта — 299 строк (296 активных), counts 108/23, strict 0.581; после добавления C-0300 (утверждение
  цикла с ожиданием-токеном «ПРИБОР ЧЕСТЕН» слабой формы, как C-0299) — 300 строк (297 активных),
  counts 109/23, strict 0.579. Вердикт остаётся `ANCHORED_WEAK`; прибор честно считает своё новое
  утверждение слабым, а не прячет его.
- `python tests/test_coverage.py` → `провалов: 0`, 5/5 (case 2 строгий + новые case на понижение).
- `python bin/audit.py` → FAIL «- нет», строка «покрытие: 1.0 (якорено) · строгое: 0.579», WARN слабых/описаний.
- `python bin/readme_numbers.py` → [ok] (строгое покрытие в README — 0.58, с 2 знаками: число 579 не
  имеет владельца в CLAIMS.md, `gate_readme_numbers`); `python bin/hs.py gates` → 32 гейта + пробы зелёные.
