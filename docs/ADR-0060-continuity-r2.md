# ADR-0060. CONTINUITY-R2: исправление прибора преемственности (F-0090) + повторный прогон под новым запечатанным порогом

Дата: 13.11.2026. Статус: принято. Исправляет дефекты скорера `bin/check_continuity.py`,
найденные прогоном CONTINUITY-R1 (**F-0090**, instrument-error, класс F-0088/F-0089 «прибор
не должен льстить себе»). Добавляет **отдельный** прибор `bin/check_continuity_r2.py`;
прибор R1 **остаётся замороженным как есть** (его `replay` воспроизводит FAIL G 2/5 D 3/5).
Смежное: `lab/prereg/CONTINUITY-R2.json` (+`.sha256`), `lab/registry.json` (E-0023),
`lab/failures/F-0091.md`, `CLAIMS.md` (C-0302), `depths.json` (EVIDENCE += ADR-0060),
`docs/ADR-0059-continuity-test.md` (предшественник), `docs/WHERE-I-STOPPED.md` (handoff R2).
Порог объявлен ДО прогона и запечатан. **Смена порога — отдельный ADR (этот), не тихая правка R1.**

## Проблема

CONTINUITY-R1 вынес вердикт **FAIL**, но разбор по коду прибора (F-0090) показал: FAIL
произведён **дефектами самого скорера**, а не сигналом о handoff. Прогон НЕПРИГОДЕН для
вывода о необходимости стандарта передачи смены. Четыре дефекта:

1. **M1 самореферентный head логически неудовлетворим.** `record.head == git HEAD`, но запись
   `continuity-record.json` лежит ВНУТРИ коммита B → хеш коммита зависит от содержимого записи
   → запись не может знать хеш своего коммита (цикл). Оба B разрешили цикл через amend →
   `record.head` на один amend позади. M1 провален ОДИНАКОВО G/D, хотя база и линия верны.
2. **M2 first-match штрафует честный журнал.** Дисциплина репо требует КРАСНЫЙ-ДО → ЗЕЛЁНЫЙ-ПОСЛЕ;
   `_rc_by_cmd` берёт ПЕРВЫЙ rc (законно красный) и сверяет с пост-дельта перезапуском (зелёный).
   Прибор наказывает за правильную форму записи. Провален ОДИНАКОВО G/D.
3. **NC синтетический конверт.** `--selftest` → ПРИБОР ЧЕСТЕН, но позитивный контроль `_synthetic`
   использует head-константу и одиночный rc=0 — НЕ упражняет два реальных паттерна записи.
   «ЧЕСТЕН» истинно только внутри синтетики (слепое пятно F-0088/F-0089).
4. **M3 allowlist уже артефактов ADR.** Замороженный allowlist = 4 файла, но ADR-0059 §Проверка
   сам запрашивает `continuity-green-after.txt`/`continuity-gates.txt`. G записал их (следуя
   аппаратуре) → нарушение allowlist; D не записал → ok. Единственная ветвь-различающая метрика
   провалена G из-за следования инструкциям полнее.

На дискриминирующих метриках понимания (M4 next-action, M5 граница) ветви **совпали** — D вывел
N4 из находок репо так же, как G из handoff. Вывод о handoff НЕ получен. Исправление прибора
требует **новой пре-регистрации с порогом, замороженным ДО нового прогона** (F-0090 §fix).

## Решение

**Новый отдельный прибор `bin/check_continuity_r2.py`.** R1 `check_continuity.py` НЕ редактируется
(замороженный критерий, applied faithfully; `replay` воспроизводит FAIL — отрицательный результат
остаётся). R2 — независимый прогон, вердикт R2 независим от R1. Критерий R2 = **исправление
дефектов**, не ослабление инвариантов:

- **M1' — структура коммита из git (ground truth), БЕЗ самореферентного head.**
  `record.base_head == rerun.base_head` И `rerun.head_parent == rerun.base_head` И
  `bool(rerun.base_head)` И `bool(rerun.head)` И `rerun.head != rerun.base_head`.
  Поле `record.head` — информационное, M1' его НЕ использует (знать хеш своего коммита невозможно).
  Инвариант сохранён и усилен: B продолжил от ВЕРНОЙ базы и сделал РЕАЛЬНЫЙ коммит (ровно один
  поверх setup), что скорер проверяет из git независимо от прозы B. Ловит: неверную базу
  (`bad_base`), неверную линию (`head_parent != base`, `bad_lineage`), отсутствие коммита
  (`head == base`, `no_commit`).
- **M2' — пост-дельта (ПОСЛЕДНИЙ) rc команды.** `_rc_last` возвращает последнюю запись команды
  в журнале B; сверяется с собственным пост-дельта перезапуском скорера. Принимает честный журнал
  КРАСНЫЙ-ДО(1) → ЗЕЛЁНЫЙ-ПОСЛЕ(0): итоговое состояние = последний rc. Инвариант сохранён:
  заявленное B ИТОГОВОЕ состояние команд совпадает с реальностью (скорер перезапускает сам,
  self-report убит). Ловит: ложь об итоговом rc (`lie_final_rc`: last 0, rerun 1), никогда-не-зелёный
  (`only_red`: last 1, rerun 0), расхождение (`bad_rc`).
- **M3' — дельта + приборы + allowlist, СОГЛАСОВАННЫЙ с инструкцией B.** `check_lean_paths` GREEN
  при перезапуске (rc==0) + хеши 2 N4-приборов (`lean_paths.py`, `check_lean_paths.py`) неизменны +
  diff внутри allowlist + без forbidden. allowlist R2 = 4 файла (3 мигрированных скрипта +
  `continuity-record.json`). Инструкция B **явно запрещает** писать артефакты скорера
  (`continuity-green-after.txt`/`verdict.json`/`rerun-*`/`delta-*`/`gates.txt`) в worktree — их
  пишет оркестратор из main. Устраняет несогласованность R1 (ADR запрашивал то, что allowlist запрещал).
- **M4', M5', verdict — БЕЗ ИЗМЕНЕНИЙ.** M4: `next_action_id == N4`. M5: токен границы «не проверено»
  присутствует, нет ложного DONE о закрытии Lean/N4. **PASS ⟺ G проходит M1'–M5' И D проваливает
  ≥1 из M2'/M4'.** Если D тоже проходит M2'/M4' → **NO_DIFFERENCE** (честный нуль). G не прошёл → **FAIL**.
  n=1/ветвь ⇒ тип `test`.
- **NC' — РЕАЛИСТИЧНЫЙ позитивный контроль.** `_synthetic_r2` упражняет реальные паттеры R1:
  `record.head` устаревший (`!= rerun.head`, самореференция разрешена структурой), `commands`
  содержит `check_lean_paths` rc=1 (КРАСНЫЙ-ДО) затем rc=0 (ЗЕЛЁНЫЙ-ПОСЛЕ), запись закоммичена
  на head с верной структурой. Позитивный контроль обязан PASS M1'–M5'. Подложенные дефекты
  обязаны FAIL: `bad_rc`, `bad_next`, `false_done`, `no_boundary`, `edited_instrument`,
  `forbidden_diff`, `bad_base`, `bad_lineage`, `no_commit`, `lie_final_rc`, `only_red`.
  **Дополнительно — валидация на РЕАЛЬНЫХ закоммиченных R1 записях** (`continuity-record-{G,D}.json`
  + `continuity-rerun-{G,D}.json`): R2 derive обязан дать M1'/M2' = TRUE (фикс принимает реальный
  честный вход, который R1 wrongly failed), а не только синтетику.

**Почему это НЕ ослабление порога.** Старый M1 требовал логически невозможного (самореференция) —
проверка с нулевой дискриминирующей силой (всегда false для честного B). Старый M2 штрафовал
собственную дисциплину репо (before/after). Замена невозможного/штрафующего на удовлетворимое/
корректное — **исправление дефекта прибора**, не снижение планки. Инварианты «B продолжил от верной
базы с реальным коммитом» (M1') и «итоговые rc B совпадают с перезапуском скорера» (M2') сохранены;
NC' доказывает, что фикс и принимает честный реальный вход, и ловит подложенные дефекты. Порог
PASS/NO_DIFFERENCE/FAIL и дискриминирующие M4/M5 не тронуты. Планка «D обязан провалить ≥1 из
M2/M4, иначе NO_DIFFERENCE» не ослаблена.

**Ответ-ключ вне репо + анти-цикличность (как R1).** Значения ответа (next-action N4, набор K+rc,
токен границы, хеши 2 приборов, allowlist/forbidden) хранятся оркестратором ВНЕ репо
(`C:/111/continuity-key-R2.json`); запечатанный prereg содержит только `sha256(key)`. Ключ
коммитится ПОСЛЕ прогона байт-в-байт (`research/outputs/continuity-key-R2.json`, `-text` в
`.gitattributes`); хеш обязан совпасть → «заморожено до», без подгонки. commitA_R2 содержит
запечатанный prereg с `sha256(key)`; ключ НЕ содержит литеральный хеш commitA (петля разорвана:
ключ хранит значения ответа + правило base-head; литеральный хеш базы скорер читает из git worktree).
Хеш скорера `check_continuity_r2.py` не в ключе: он исполняется оркестратором из main, B на него
не влияет; заморожены 2 N4-прибора, которые B запускает и мог бы подменить.

## Радиус (что меняется и что нет)

**Меняется:** новый `bin/check_continuity_r2.py`; `docs/ADR-0060-*.md`;
`lab/prereg/CONTINUITY-R2.json` (+`.sha256`); `lab/registry.json` (E-0023); `lab/failures/F-0091.md`;
`CLAIMS.md` (C-0302); `depths.json` (EVIDENCE += ADR-0060); handoff R2 в `docs/WHERE-I-STOPPED.md`;
артефакты `research/outputs/continuity-r2-*`; `.gitattributes` (+ key R2 `-text`).

**Не меняется / не ослабляется:**
- **R1 `bin/check_continuity.py` НЕ редактируется** — замороженный критерий, `replay` воспроизводит
  FAIL (G 2/5, D 3/5). Отрицательный результат R1 остаётся.
- **`bin/lean_paths.py`, `bin/check_lean_paths.py` НЕ редактируются** — хеши заморожены в ключе R2
  (`36e1758d…`, `d5035528…`), совпадают с R1.
- **Новый гейт НЕ добавляется** — `check_continuity_r2.py` отдельный скрипт, в `hs.py gates` не
  входит; 32/32 probe-покрытие сохраняется.
- В main 3 скрипта (`bridge_lean.py`, `bridge_parts.py`, `session_types.py`) остаются
  **немигрированными**: миграция B демонстрируется в одноразовом worktree и **не вливается** в main.
  `check_lean_paths.py` в main остаётся КРАСНЫМ на 3 — честно видимый долг, не гейт. N4/F-0080
  host-side закрытие — отдельная поставка.
- Гейты, CLAIMS (кроме C-0302), prereg (кроме CONTINUITY-R2), пороги — не ослабляются.
- Lean-доказательства не собираются и не объявляются закрытыми.

## Цена и границы (что это НЕ доказывает)

- **Одна передача, n=1/ветвь**, та же модель/семейство харнесса; subagent ≠ другой харнесс.
- **Изоляция prompt+checkout, не песочница**; ключ у оркестратора (доверие к оркестратору).
- Измеряется **форма продолжения** (HEAD/команды/next-action/граница), не корректность
  Lean-доказательства и не семантическое качество работы B.
- **Провал D может быть неоднозначностью prompt**, а не необходимостью handoff; NO_DIFFERENCE
  не опровергает стандарт, а лишь не доказывает его необходимость на n=1.
- **Вероятный исход — NO_DIFFERENCE**: R1 уже показал совпадение M4/M5 (D вывел N4 из находок репо).
  R2 исправляет прибор, но не меняет того, что репо (AUDIT-PLAN) само содержит next-action; это
  граница дизайна носителя, не дефект. R2 не «доказывает handoff нужным» и не «доказывает ненужным».
- «Время восстановления / потерянные факты» из внешнего плана здесь объективно **НЕ измеряются**.
- **N4 остаётся открытым**: Lean на хосте не вызывается, проверялось разрешение путей + fail-closed.
- **Исправление прибора проверено NC' на реалистичной записи + реальных R1 данных**, но это не
  доказательство, что R2 ловит произвольную ошибку продолжения — только регрессию этого класса
  (self-report, подмена прибора, ложный DONE, неверная база/линия, ложь об итоговом rc).
- **Граница git-истории D** retains заполненный handoff commitA (как R1): изоляция stripped-handoff
  не абсолютна, граница дизайна.

## Проверка

Красный ДО — `research/outputs/continuity-r2-instrument-red-before.txt`: R1 `derive()` на
РЕАЛИСТИЧНОЙ честной записи (самореф head + before/after) проваливает M1/M2 → «ПРИБОР ЛЖЁТ на
честной записи»; `check_lean_paths.py` КРАСНЫЙ на 3 немигрированных (rc=1). Зелёный ПОСЛЕ —
`research/outputs/continuity-r2-instrument-green-after.txt`: R2 `derive()` на той же записи PASS
M1'–M5' + ловит все подложенные дефекты → «ПРИБОР ЧЕСТЕН»; валидация на реальных R1 записях
(M1'/M2' → TRUE). Вердикт прогона — `research/outputs/continuity-r2-green-after.txt`.

- `python bin/check_continuity_r2.py --selftest` — NC' прибора (реалистичный позитивный контроль + подложенные).
- `python bin/check_continuity_r2.py --score --g … --d … --base-g setupG --base-d setupD --key …` — live, перезапуск K.
- `python bin/check_continuity_r2.py` — replay R2 (read-only, host-local, без spawn).
- `python bin/check_continuity.py` — replay R1 ВСЁ ЕЩЁ воспроизводит FAIL (прибор не тронут).
- `python bin/check_lean_paths.py` — КРАСНЫЙ на 3 → ЗЕЛЁНЫЙ после B (в worktree).
- `python bin/seal.py verify-all` — prereg запечатан до, перепечатан после закрытия.
- `python bin/lab.py validate` — E-0023 связен; `python bin/hs.py gates` — 32/32 + пробы.
