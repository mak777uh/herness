# ADR-0016 — Свой язык? Два разных «своего»: GPL и DSL

Дата: 29.10.2026. Статус: GPL отброшен, DSL — гипотеза. Применяет принцип P24.

## Вопрос по первому принципу

Мы выбираем, на чём писать. По P24 обязаны рассмотреть «сделать своё» наравне с Rust, Python,
TypeScript и Go. И здесь первое, что надо разделить: **«свой язык» — это два разных проекта.**

| | универсальный язык (GPL) | доменный язык (DSL) |
|---|---|---|
| что это | свой синтаксис, компилятор, рантайм, стандартная библиотека | описание границ, утверждений, политик в узкой нотации + проверяльщик |
| цена | годы, экосистема, инструменты, обучение, отладка | недели, парсер и проверяльщик |
| что даёт | полный контроль | однозначность там, где сейчас проза |
| примеры | Rust, Go, Zig | Cedar, Rego, Datalog, SQL, JSON Schema |

## GPL: отброшено, с ценой

Свой универсальный язык для харнесса — это:

- компилятор или интерпретатор, отладчик, пакеты, редакторская поддержка;
- отсутствие экосистемы: ни SSE-клиентов, ни тестовых фреймворков, ни библиотек;
- найм и обучение: язык знает один человек;
- вечная поддержка совместимости.

Всё это ради того, что уже даёт Rust или Python. Это не «проверка предпосылки», а смена темы: мы
писали бы язык вместо харнесса. Отбрасываем — но **фиксируем причину**, чтобы не возвращаться
каждый месяц.

**Что бы это оживило:** если бы выяснилось, что ни один существующий язык не выражает границы и
свидетельства без потери смысла. Пока таких свидетельств нет.

## DSL: гипотеза, которую надо проверить

Другое дело — **нотация для границ**. Сейчас границы живут в тексте, коде и пользовательских
соглашениях, и проверяются людьми. Мы уже начали делать DSL, не называя его так:

- `Boundary` в контрактах — структура с `allow`, `deny`, `not_claimed`, якорем и сроком;
- LexSpec — спецификация + схема + проверяльщик для утверждений о нормах;
- коды отказа, покрытие, вердикт относительно редакции.

Вопрос: нужна ли этому **отдельная нотация**, или хватит схемы (JSON/YAML) плюс существующего языка
политик?

### Критерии, по которым это решается

| критерий | вопрос |
|---|---|
| выразительность | можно ли записать реальную границу, не изобретая обходной путь |
| однозначность | прочитают ли два человека одно и то же одинаково |
| проверяемость | может ли гейт решить «в рамках / вне рамок» без человека |
| стоимость авторинга | сколько времени занять написание одной границы |
| отсутствие нового тулчейна | не нужен ли компилятор, IDE, сборка |
| диагностика | понятно ли, **почему** отказ |

### Что убьёт DSL

Если на трёх реальных границах связка «схема + существующий язык политик» даёт тот же результат
по однозначности и проверяемости при меньшей цене — DSL не нужен. Это объявленный заранее
фальсификатор, а не «посмотрим».

## Порядок

1. Взять три настоящие границы (например: обмен артефактами, публикация, трата).
2. Записать каждую тремя способами: схема + код, существующий язык политик (Cedar/Rego), мини-DSL.
3. Замерить: время, число неоднозначностей у второго читателя, решаемость гейтом, цену тулчейна.
4. Решение — по критериям выше, артефакт — в `lab/experiments/E-0004`.

## Что это не доказывает

Что DSL не понадобится на пятом типе границ. Что существующие языки политик подходят к нашим
границам (они про доступ, а не про взаимные обязательства). Что цена GPL посчитана точно — она
посчитана по порядку величины.
