# PRINCIPLES — свод принципов портфеля

Источник: `VecDHT/AGENTS.md`, `lexspec/AGENTS.md`, `flowguard-spec/interop/COORDINATION.md`,
`lexspec/interop/README.md`, устав владельца от 29.10.2026.

Каждый принцип записан тремя полями: **что запрещает**, **чем принуждается в харнессе**,
**как проверить, что принуждение работает** (негативный тест). Принцип без третьего поля — декорация.

## A. Истина и свидетельство

| id | принцип | запрещает | механизм | негативный тест |
|---|---|---|---|---|
| P1 | Число без команды, окружения и коммита — не результат | цифры из головы и из README | журнал прогона фиксирует команду, окружение и коммит рядом с числом | убрать команду из записи → публикация падает |
| P2 | Истина — в коде, тестах и воспроизводимом прогоне; доки — карта, не территория | «в README же написано» | любое утверждение ссылается на артефакт прогона, а не на текст | удалить артефакт → утверждение теряет тип |
| P3 | Формулировка не сильнее типа свидетельства | «доказано» при `observation` | схема типа + линтер формулировок | посадить «доказано» при `observation` → отказ |
| P4 | `observed` и `inferred` различаются полем, а не прозой | «нашлось прогоном» вместо поля | поле `origin` у каждого утверждения | запись без `origin` → отказ |
| P5 | Вердикт без `not_claimed` — другое утверждение | отчёт, читаемый как обещание | отчёт не создаётся без границы | отчёт без раздела → не публикуется |
| P6 | Вердикт относителен | «корректно», «безопасно», «соответствует» | закрытый словарь формулировок: «проверено в X против Y в редакции R, покрытие N %» | слово «безопасно» → отказ линтера |
| P7 | Отрицательный результат публикуется; записи append-only | удаление неудобного, переписывание истории | журнал не перезаписывается, только дописывается | попытка правки прошлой записи → отказ |
| P8 | Anchor or refuse | утверждение без однозначного якоря | утверждение требует span/дайджест; неоднозначный якорь = отказ | якорь, встречающийся дважды → отказ |

## B. Гейты

| id | принцип | запрещает | механизм | негативный тест |
|---|---|---|---|---|
| P9 | Гейт не ослабляется, чтобы стало зелёным | «временно» понизить порог | порог в конфиге + ADR на изменение | понижение порога без ADR → отказ |
| P10 | Гейт без падающего случая — декорация | проверки, которые всегда зелёные | у каждого гейта обязательный негативный тест | посадить нарушение → гейт обязан упасть |
| P11 | Локально зелёное ≠ проверено | «у меня работает» | гейт входит в одну команду и в CI | гейт, не входящий в CI, помечается «не проверялся здесь» |
| P12 | Новый код отказа — новый дефект | коды «на всякий случай» | дефект + пример + документ + тест, иначе отказ | код без теста → отказ |

## C. Процесс

| id | принцип | запрещает | механизм | негативный тест |
|---|---|---|---|---|
| P13 | Один вопрос — одно изменение | правки «по пути» | шаг цикла = один инструмент = один вопрос | два инструмента в шаге → отказ |
| P14 | Спека — конституция | сначала код, потом «догоним документ» | контракт в схеме; код следует за ней | код с полем вне схемы → отказ |
| P15 | Один писатель на область | параллельная правка одного файла | блокировка области прогона | второй прогон по той же области → очередь |
| P16 | Не выдавай сгенерированное за проверенное | модель «доказала» теорему | `origin: model` + обязательная проверка внешним гейтом | утверждение от модели без гейта → `judgment` |
| P17 | Сомневаешься — гипотеза, а не код | код «на пробу» | бюджет и гипотеза в `lab/` до изменения | задача без гипотезы → предупреждение |
| P24 | Первый принцип: предпосылки проверяются наравне с решениями; «а не сделать ли своё?» — обязательный кандидат | принимает умолчания («так принято», «все так делают») за решение | решение о технологии перечисляет кандидата «своё» с ценой; иначе помечается как непроверенное | ADR о выборе технологии без кандидата «своё» → отметка «предпосылка не проверена» |

## D. Семья репозиториев (interop)

| id | принцип | запрещает | механизм | негативный тест |
|---|---|---|---|---|
| P18 | Ничей вердикт не свидетельство о предмете другой стороны | «flowguard подтвердил безопасность» | вердикт привязан к предмету; перенос вердикта = отказ | сослаться на чужой вердикт как на свой → отказ |
| P19 | Заметка: один файл, не правится, шапка с обоими коммитами | правка опубликованной заметки | журнал заметок append-only, шапка обязательна | заметка без коммитов → не публикуется |
| P20 | Молчание — долг, не согласие; состояние читается скриптом | «они вроде согласны» | `refs ledger` читает репозитории, а не память | заметка без ответа исчезла из долгов → отказ |
| P21 | Граница файлами, не зависимостями | встроить чужой код в свой | в чужой репо едут только файлы в `interop/` | зависимость на чужой репо → отказ |

## E. Безопасность и деньги

| id | принцип | запрещает | механизм | негативный тест |
|---|---|---|---|---|
| P22 | Секреты не в контекст и не в git | значение ключа в промпте | в контекст едут имя и отпечаток | ключ в артефакте → гейт падает |
| P23 | Ничего наружу и никаких трат без «да» | автопубликация, автоплата | публикация и транзакции — отдельный инструмент с подтверждением | попытка публикации без подтверждения → отказ |

## Как это ложится на харнесс

- A и B — это и есть ядро: журнал, артефакты, типы, границы, гейты.
- C — ограничения на цикл: один инструмент за шаг, бюджет, гипотеза до изменения.
- D — механизм справочника: репозитории читаются как первоисточник, а находки возвращаются заметками.
- E — политика инструментов, а не пожелание.

Правило приоритета: при конфликте принципов выигрывает тот, что защищает **публикацию**
(P1–P8), а не тот, что ускоряет работу.
