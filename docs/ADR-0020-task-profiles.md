# ADR-0020 — Профили задач: раскладка запроса, уровни вмешательства, сборка окружения

Дата: 29.10.2026. Статус: предложено. Опирается на E-0007, BARE-MODE, ADR-0014.

## Идея

Не искать универсальный харнесс. Вместо этого:

```
запрос человека → семантическая раскладка на фрагменты → типы задач
→ для каждого типа свой профиль (среда, инструменты, уровень вмешательства)
→ сборка окружения под задачу → исполнение → свидетельства → оценка → правка профилей
```

Профили — это данные, а не код. Уровень вмешательства выбирается **по типу задачи**, и для части
типов правильный ответ — «ничего не подключать».

## Уровни вмешательства

| уровень | что подключено | когда уместен | цена |
|---|---|---|---|
| **L0** ничего | модель и сама задача | малое, отменяемое, без внешних утверждений | ноль обвязки, ноль свидетельств |
| **L1** инструменты | оболочка, файлы, сеть | почти всё, где нужен факт о мире | низкая |
| **L2** инструменты + протокол | плюс журнал, артефакты, отчёт, границы | где результат переживёт разговор: аудит, отчёты, публикации | средняя |
| **L3** полный | плюс сервер, lease, мультиагентность | долгие задачи, передача между узлами, деньги | высокая |

Данные E-0007 намекают на правило: **L1 бьёт L0** там, где нужен факт, а **L2 дороже L1** на простых
задачах. Значит уровень — не «чем больше, тем лучше», а минимально достаточный.

## Схема типа задачи

| поле | что содержит |
|---|---|
| `id` | `T-<NNNN>` |
| `признаки` | по чему распознаётся фрагмент: глаголы, объекты, требуемое свидетельство |
| `требуемое свидетельство` | `нет` / `прогон` / `артефакт + границы` |
| `риск` | цена ошибки: отменяемо / дорого / необратимо |
| `уровень по умолчанию` | L0…L3 |
| `инструменты` | список того, что включается |
| `бюджеты` | шаги, время, объём |
| `границы` | что этот тип не доказывает по своей природе |
| `замер` | сколько раз проверяли и с каким исходом |

## Как выбирается уровень

```
1. Разложить запрос на фрагменты (REQUEST-PROTOCOL).
2. Каждому фрагменту — тип задачи по признакам.
3. Тип не распознан → уровень L1 + пометка «тип неизвестен, нужна проба».
4. Взять минимальный уровень из профиля, который покрывает требуемое свидетельство.
5. Если риск «необратимо» — повысить уровень, даже если свидетельство не требуется.
6. Если исполнение провалилось — повысить уровень и записать это в профиль как наблюдение.
```

Правило: **уровень повышается по провалу, а не по привычке.** Понижение — по замеру: если тип N раз
успешно закрылся на L1, L2 для него — лишняя цена.

## Почему это не «ещё один харнесс»

Профили не добавляют универсальную логику. Они **отображают** «тип → среда». Ядро остаётся одним:
журнал, инструменты, границы. Меняются только состав и строгость.

## Где это ломается (трезво)

1. **Классификатор — слабое звено.** Раскладка запроса может ошибиться, и задача уедет в профиль с
   неверными инструментами. Хуже, чем L1 по умолчанию. Поэтому: неизвестный тип → L1, а не догадка.
2. **Взрыв таксономии.** Типов станет больше, чем задач. Ограничение: начинать с 5–7 типов из
   реальных журналов, новый тип заводить только после трёх задач, не влезших в существующие.
3. **Переобучение на прошлом.** Профили, настроенные на историю, провалятся на новых задачах.
   Поэтому в каждом профиле хранится дата и число проверок, а не только «оптимально».
4. **Самоисполняющееся пророчество.** Агент выбирает инструменты, которые делают его отчёт красивее.
   Лечится только внешней оценкой (человек/ревьюер) и замороженным снимком.
5. **Цена замера.** Мерить каждый тип дорого. Поэтому замер — не на каждой задаче, а по выборке и
   только при изменении профиля.

## Что делаем первым

| шаг | что | критерий |
|---|---|---|
| P1 | выписать 5–7 типов из 244 сессий журналов | каждый тип встречается ≥5 раз и описан признаками |
| P2 | для каждого — уровень по умолчанию и инструменты | профиль покрывает свой тип без ручной правки |
| P3 | замер: тип × уровень (A0/A/B) | у каждого типа есть ряд «уровень → исход» |
| P4 | сборка окружения по профилю | одна команда поднимает среду под тип |

## Связь с LexSpec

Раскладка запроса — та же операция, что и разбор правовых утверждений: **семантика → формальные
единицы с якорем**. Разница в предмете: там норма, здесь намерение. Поэтому формат фрагмента
(что сказано, чем подтверждается, чего не покрывает) стоит взять у LexSpec, а не изобретать.

## Что это не доказывает

Что типы из истории покрывают будущие задачи. Что классификация по признакам надёжна. Что профили
не окажутся дороже, чем польза: это ещё не мерили.
