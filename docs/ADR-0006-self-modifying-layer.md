# ADR-0006 — Расширенный замысел: самоизменяемый слой управления

Дата: 29.10.2026. Статус: принято владельцем (A10, A15, A6, A13). Дополняет ADR-0003…0005.

## Что изменилось

Ответы A10 и A15 переводят проект в другой класс. Требуется не «харнесс», а **слой управления
агентом и его средой**:

1. харнесс умеет **менять собственный код на ходу** (A10);
2. умеет **менять ОС под себя** (A10);
3. в перспективе — **управлять устройствами и железом** (A10);
4. выдерживает **вложенную параллельность**: сабагенты создают сабагентов (A6);
5. работает **на любой системе**, с опциональным сервером (A13);
6. при обрыве связи сервер продолжает, а локальные агенты **возвращаются в новый контекст** (A15).

Пункт 1 — единственный, который меняет архитектуру до основания. Остальные ложатся на уже
принятые решения (журнал событий, ядро/оболочки, квоты).

## Главный вывод: без поколений самоизменение — это самоуничтожение

Агент, который правит свой код и свою ОС, за один неудачный шаг делает систему невосстановимой.
Поэтому самоизменение допустимо **только как транзакция с обратимым результатом** — тем же
принципом, что у NixOS (поколения), A/B-разделов и снапшотов файловой системы.

Минимальный механизм:

```
предложить изменение
   → построить новое поколение (образ/каталог/снапшот) в стороне
   → прогнать гейты: тесты, health-check, smoke-сценарий
   → активировать (переключение указателя, не правка на месте)
   → при провале — переключить указатель назад
```

Никакой правки «на живой системе». Только сборка нового поколения и переключение.

## Инварианты

| id | инвариант | цена нарушения |
|---|---|---|
| S1 | Ядро неизменно во время прогона; правка — только новым поколением | агент, меняющий код под собой, теряет воспроизводимость |
| S2 | Каждое изменение среды имеет откат и «чек» (что именно изменено) | ошибка становится необратимой |
| S3 | Один писатель на прогон (lease); второй узел не пишет в тот же журнал | журнал начинает врать |
| S4 | Разделение привилегий: ядро без прав на ОС, привилегированный помощник — с узким API | компрометация ядра = компрометация машины |
| S5 | Холодный старт: система поднимается и восстанавливается без агента | агент ломает себя и не может починиться |
| S6 | Каждое самоизменение проходит гейт; провал гейта = автоматический откат | «почти работает» становится новой нормой |

## Архитектура с учётом расширения

```
оболочки (без прав)          приложение · аварийный веб · CLI
        │
слой сессий                  журнал, lease, передача между узлами
        │
ядро (без прав на ОС)        цикл, инструменты, политика, бюджеты, гейты
        │
супервизор                   квоты, дерево процессов, лимит тяжёлых задач
        │
привилегированный помощник   узкий API: пакеты, сервисы, снапшоты, поколения
        │
среда                        поколения ОС, откат, A/B
```

Ключевое: **ядро не имеет прав менять ОС**. Оно просит помощника. Помощник умеет только
перечисленные операции, каждую — с чеком и откатом.

## ОС: вывод, а не симпатия (A5)

Требование «менять ОС под себя» и «вложенная параллельность» указывают на Linux как целевой
мощный режим: поколения и снапшоты (btrfs/ZFS/Nix), квоты (cgroups), изоляция (namespaces,
landlock), управление сервисами (systemd), пакеты без перезагрузки.

Windows и macOS остаются **клиентом** и режимом ограниченного исполнения: там управление ОС
недостижимо без виртуализации, и обещать его было бы ложью.

Портируемость ядра (A13) обеспечивается тем, что ядро на Python и работает через абстракцию
возможностей: `capabilities.detect()` → доступные операции; отсутствующие отключаются, а не падают.

## Порядок

| этап | что | когда имеет смысл |
|---|---|---|
| M7 | параллельность и квоты | после M2 |
| M8 | флот и вложенные сабагенты | после M7 |
| M9 | передача сессии между узлами | после M5 (журнал и lease) |
| M10 | самоизменение (поколения) | после M8 + стабильных гейтов |
| M11 | управление ОС и железом | после M10 |
| M12 | миграция | последним |

Порядок не случаен: каждый следующий этап опирается на инварианты предыдущего. Самоизменение до
гейтов — это способ потерять систему в первый же день.

## Что это не доказывает

- Что откат сработает при повреждении загрузчика (нужен внешний путь восстановления).
- Что агент сможет осмысленно менять ОС, а не просто ломать её быстрее.
- Что «импакт» вообще измерим — метрики нет, есть только направление.
- Что вложенная параллельность не упрётся в железо раньше, чем в софт.
