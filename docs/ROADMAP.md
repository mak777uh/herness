# ROADMAP — порядок сборки

Темп: долго и аккуратно (A7). Порядок обратный привычному: сначала контракты и тесты, потом
функциональность. Каждый этап закрывается тремя вещами: **прогон**, **негативный тест**,
**раздел «что это не доказывает»**. Нет любой из трёх — этап не закрыт.

Цель (A1): импакт на единицу времени, при нуле ложных утверждений наружу.

## M0. Контракты — закрыт

Схемы: артефакт, событие, утверждение, отчёт. Без исполнения.

- готово: 10 тестов, все на посаженных нарушениях;
- негативный тест: «доказано» при `observation` → отказ;
- не доказывает: что схемы покрывают будущие случаи.

## M1. Ядро без модели

Цикл с mock-провайдером, один инструмент (`shell`), журнал, артефакты.

- готово: артефакт на диске **раньше**, чем ответ модели записан;
- негативный тест: убить процесс между вызовом и записью → результат не потерян;
- не доказывает: что с живым провайдером тайминги те же.

## M2. Провайдеры и бюджеты

SSE-стриминг, выбор модели, бюджеты (шаги, время, байты), остановка с отчётом.

- готово: прогон на живой модели, журнал и артефакты сходятся;
- негативный тест: бюджет исчерпан → корректная остановка, не зависание.

## M3. Минимальный веб (оболочка A)

Читает журнал, показывает прогон, работает в safe-mode.

- готово: поднимается при битом конфиге, без node/npm;
- негативный тест: битый конфиг → safe-mode, а не отказ стартовать.

## M4. Гейты и отчёт

Типы утверждений, линтер формулировок, `NOT-CLAIMED`, публикация только после гейтов.

- готово: посаженное нарушение отбивается; отчёт без границы не создаётся;
- негативный тест: сильная формулировка при слабом типе → отказ.

## M5. Песочница и супервизия

Изоляция исполнения, гарантированное убийство дерева процессов, лимит тяжёлых задач.

- готово: две тяжёлые сборки одновременно не ломают друг друга;
- негативный тест: убить родителя → дети не остаются сиротами.

## Параллельный трек H — режим хоста (ADR-0009)

Идёт параллельно M5–M8: системный слой не блокирует ядро и наоборот.

| этап | что | критерий готовности |
|---|---|---|
| H0 | один spec → четыре артефакта (dir, tar, qcow2, raw) | образ собирается во всех формах; WSL импортируется из tar; `hs doctor` внутри зелёный |
| H0b | конфиг ядра под профиль железа (`hwprofile`) | ядро+модули ≤250 МБ; загрузка ≤3 с; `lean`/`forge`/`python` работают; новый модуль добавляется без пересборки всего |
| H1 | харнесс запускает сервисы на минимальной базе | две службы под супервизором, падение одной не роняет другую |
| H2 | квоты через cgroups v2 | десять процессов не превышают общий лимит |
| H3 | поколения: снапшот, переключение, откат | неудачное поколение откатывается само |
| H4 | менеджер среды: тулчейны по объявлению | чистая машина → `lean` и `forge` работают одной командой |
| H5 | харнесс как init в своём образе | машина грузится в харнесс и принимает задачу |

Негативные тесты: убить супервизор → службы не остаются без надзора; активировать поколение с
падающим health-check → откат; два источника версий (свой менеджер + apt) → конфликт виден, а не
замаскирован.

## M6. Приложение (оболочка B)

Полноценный UI поверх API ядра; правится на ходу, падает отдельно.

- готово: падение приложения не влияет на идущий прогон;
- негативный тест: убить UI посреди прогона → журнал дописан полностью.

## M7. Параллельность и квоты (A6)

Иерархия бюджетов: агент → сабагент → сабагент. Наследование и потолок.

- готово: десять параллельных прогонов не превышают общий лимит ресурсов;
- негативный тест: сабагент просит больше родительской квоты → отказ, а не тихое превышение;
- не доказывает: что квоты справедливы (приоритеты — отдельная задача).

## M8. Флот и вложенные сабагенты

Роли, реестр агентов, общий журнал, распределение работы.

- готово: два агента пишут в один журнал без гонок;
- негативный тест: одновременная запись в одну область → очередь, а не порча.

## M9. Передача сессии между узлами (A15)

Lease на прогон, сервер продолжает при обрыве, локальный агент возвращается в контекст.

- готово: обрыв связи посреди прогона → сервер доводит, локальный при возврате видит дельту;
- негативный тест: два узла пытаются писать один прогон → второй получает отказ по lease;
- не доказывает: что восстановление контекста не искажает решения.

## M10. Самоизменение (A10)

Поколения: построить → прогнать гейты → активировать → откатить.

- готово: агент меняет свой модуль, гейт проваливается, система сама откатывается;
- негативный тест: активировать поколение с падающим health-check → автоматический откат;
- не доказывает: что откат спасёт при повреждении загрузчика.

## M11. Управление ОС и железом (A10)

Привилегированный помощник с узким API: пакеты, сервисы, снапшоты, устройства.

- готово: помощник умеет ровно перечисленное и отказывает во всём остальном;
- негативный тест: запрос вне API → отказ с кодом, а не «попытка сделать похожее»;
- не доказывает: что агент будет менять ОС осмысленно.

## M12. Миграция (A11)

Перенос не сессий, а онбординга: для каждого агента — инструкция «кто ты, где ты, с чего продолжить».

- готово: новый харнесс поднимает роль по инструкции и продолжает работу;
- негативный тест: инструкция без «с чего продолжить» → роль не стартует.

---

## Порядок и причины

| этап | опирается на | если переставить раньше |
|---|---|---|
| M7 | M2 | квоты без бюджета нечего ограничивать |
| M8 | M7 | флот без квот съедает машину |
| M9 | M5 | передача без журнала и lease = два писателя |
| M10 | M8 + M4 | самоизменение без гейтов = потеря системы |
| M11 | M10 | управление ОС без отката = кирпич |

## Что не входит

- Красота UI до M6.
- Сетевые протоколы (ACP/MCP) до M9.
- Управление железом до M11.
