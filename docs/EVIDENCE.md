# evidence/ — как внешний факт становится перепроверяемым

## Зачем это

Замер 31.10.2026: **38 из 127 утверждений (29,9 %)** были подтверждены собственной прозой. Команда
`check_artifacts.py C-XXXX` с артефактом `research/*.md` проверяет, что мы так написали, а не что так
есть. Именно поэтому ошибка «каталог `tests/` пуст» жила неделю: у неё было «доказательство».

Здесь факт привязывается к телу ответа: URL, время, код, sha256. Тогда проверка — это повторный
запрос, а не чтение своего текста.

## Формат записи

`evidence/index.jsonl` — по строке на попытку (append-only, `fsync` после каждой):

| поле | что значит |
|---|---|
| `id` | `ev-…`, идентификатор попытки |
| `url`, `final_url` | что просили и куда пришли редиректы |
| `fetched_at` | UTC ISO-время |
| `status` | HTTP-код; `0` — сеть не ответила |
| `sha256`, `bytes` | отпечаток и размер тела |
| `content_type`, `etag`, `last_modified` | заголовки, если были |
| `kind` | `ok` \| `absence` (404/410) \| `http_error` \| `error` |
| `body_stored` | тело сохранено в `evidence/objects/<sha256>` (только 2xx и ≤ 256 КиБ) |
| `note` | зачем загружали (свободный текст) |
| `version` | версия схемы записи |

Тело больше 256 КиБ **не сохраняется**, но хеш и размер пишутся: «слишком большое» — это факт, а не
повод молчать.

## Команды

```
python bin/evidence.py fetch <url> [--note TEXT]   # 0 — 2xx; 1 — не 2xx (запись всё равно есть)
python bin/evidence.py verify <id|url>            # см. четыре исхода ниже
python bin/evidence.py list [--limit N]
```

`verify` возвращает **не 0**, если ответ не совпал:

| исход | что значит | код |
|---|---|---|
| `FRESH` | тот же байт-в-байт ответ | 0 |
| `CHANGED` | источник отдаёт другое тело: утверждение **устарело**, но не ложно | 1 |
| `GONE` | 404/410: это **отсутствие**, а не опровержение | 2 |
| `UNREACHABLE` | не достучались: «не проверял», а не «нет» | 2 |
| `NO_BODY` | в записи нет хеша — сравнивать нечего | 2 |

Разделение `CHANGED` / `GONE` / `UNREACHABLE` — не педантизм. Слить их в одно «плохо» значит потерять
ровно ту информацию, из-за которой появился этот механизм.

## Как перевести утверждение на evidence

1. `python bin/evidence.py fetch <url> --note "чем это утверждение подтверждается"` — получить `id`.
2. В `CLAIMS.md` заменить команду на `python bin/evidence.py verify <id>`, артефакт — на
   `evidence/index.jsonl`, ожидание — на `FRESH`.
3. Убрать `id` из `evidence/selfref-baseline.json` (гейт сам потребует, если забыть).

## Храповик

`python bin/selfref.py` считает утверждения, подтверждённые своим текстом, и сверяет с
`evidence/selfref-baseline.json`:

- новый самоссылочный случай → гейт `самоссылка` красный (долг не растёт);
- запись в базе, которая больше не самоссылочная → тоже красный (база обязана убывать).

Список виден и посчитан: на 31.10.2026 — 37 записей (было 41 до конвертации четырёх).

## Границы

- Запись доказывает, что **мы получили такой ответ по такому URL в такое время**. Она не доказывает,
  что источник говорит правду, и не заменяет аргумент.
- Тело хранится только для 2xx и ≤ 256 КиБ; для остальных есть хеш, но не тело.
- `CHANGED` — повод перечитать утверждение, а не автоматически «ложь». Решение принимает человек.
- Источники, которые отвечают по-разному на разные запросы (динамические страницы), будут вечно
  `CHANGED`; это ограничение метода, а не дефект записи.
