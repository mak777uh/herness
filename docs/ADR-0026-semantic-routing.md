# ADR-0026 — Семантическая маршрутизация и классы, которые собираются сами

Дата: 29.10.2026. Статус: предложено. Дополняет ADR-0020 (профили) и ADR-0025 (перенос).

## Идея

Задача не обязана попадать в один класс. Она **раскладывается по смыслу**: если фрагмент близок к
нескольким классам, к нему подтягиваются инструменты из соседних — не всей группой, а те, что
семантически коррелируют.

И обратное движение: если инструмент в новом классе **дал результат**, он там регистрируется. Если
таких задач накопилось достаточно и они не влезают в существующие классы — **появляется новый класс**.

```
задача → семантика → ближайшие классы → инструменты соседей → результат
                                                            │
                               успех → запись в learning.jsonl
                                                            │
                        ≥N задач вне классов → предложение нового класса
```

## Как считается (офлайн, без эмбеддингов)

| шаг | как |
|---|---|
| представление текста | TF-IDF по словам, грубая нормализация: первые 5 символов (иначе «опубликуй» и «опубликовать» — разные слова) |
| профиль класса | название + описание + его действия |
| близость | косинус между задачей и профилем |
| инструменты | берутся из `tools.json` для классов, прошедших порог |

Проверено на живых фразах:

```
"проверь, не врёт ли README про размеры"  → T-0002 аудит (0.064), инструмент hs step
"опубликуй изменения"                     → T-0005 публикация
"посчитай сколько раз встречается слово"  → T-0006 анализ журналов
```

Пороги низкие (0.06–0.26) — TF-IDF даёт маленькие числа. Это не «уверенность», а порядок.

## Правила

| правило | формулировка |
|---|---|
| S1 | задача может тянуть инструменты из нескольких классов — это нормально |
| S2 | инструмент попадает в новый класс как `trial`, а не `active` |
| S3 | основание для регистрации — **записанный результат**, а не самоотчёт |
| S4 | новый класс предлагается только при ≥3 успешных задачах вне известных классов |
| S5 | новый класс получает имя, действия и владельца; иначе это не класс, а свалка |
| S6 | предложение класса — не создание: создание проходит через ADR |

## Чего это не заменяет

- **Смысл не проверяется.** TF-IDF ловит совпадение слов, а не сходство задач: «найди расхождения»
  и «найди расхождения в законе» окажутся рядом, хотя первое — код, второе — право.
- **Русская морфология грубая.** Обрезка до 5 символов склеивает лишнее.
- **Эмбеддинги не используются** — сети для них нет, а локальная модель не выбрана (ADR-0021).

## Как это станет лучше

1. Эмбеддинги локальной моделью (ADR-0021, когда появится корпус и модель).
2. Обратная связь по результату, а не по совпадению слов: сейчас `learn` пишет факт, но не качество.
3. Кластерный анализ накопленных задач вместо ручных порогов.

## Риски

1. **Ложная близость** — самое опасное: слова совпали, задача другая.
2. **Разрастание классов** — каждый новый класс уменьшает шанс, что задача найдёт родной.
3. **Самоисполняющееся пророчество**: если инструмент регистрируется по факту использования, он
   закрепляется там, где случайно сработал.

## Что это не доказывает

Что TF-IDF достаточно для раскладки. Что 3 задач хватает для нового класса. Что класс, собравшийся
сам, лучше спроектированного руками.
