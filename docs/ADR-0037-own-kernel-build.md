# ADR-0037. Ядро — своя минимальная сборка 6.18.60

**Статус:** принято по замеру 31.10.2026. Заменяет выбор готовой сборки из ADR-0036 (версия и линия —
те же: Linux 6.18 LTS).

## Контекст

ADR-0036 выбрал Linux 6.18 LTS, но из **готовых сборок Alpine**. Аудит показал, что это выбор версии,
а не ядра: не проверялись другие вендоры, mainline и собственная сборка. Провели опыт: собрали своё
ядро из `6.18.60` с `tinyconfig` + минимальный набор опций и сравнили с Alpine на одном initramfs.

## Замер (QEMU, `-smp 1`, один и тот же образ)

| метрика | Alpine 6.18.58 | Своя 6.18.60 |
|---|---:|---:|
| размер | 13,93 МБ | **0,97 МБ** |
| до старта init | 3,17 с | **0,62–1,29 с** |
| Landlock ABI | 7 | 7 |
| успешных загрузок | 1 из 2 | **4 из 4** |

## Решение

**Ядро — своя сборка Linux 6.18.60 с минимальным конфигом.**

Причины: в 14 раз меньше, в 3 раза быстрее до старта, стабильно загружается на этой машине (у Alpine
SMP+IO-APIC даёт панику через раз), песочница не пострадала (ABI 7).

## Следствия

1. Конфиг версионируется: `core-rs/kernel/config-6.18.60-minimal`.
2. Сборка воспроизводима скриптом `core-rs/build-own-kernel.sh`; артефакт `vmlinuz-own-6.18.60`
   (в git не кладём, но фиксируем SHA-256).
3. `build.ps1` по умолчанию берёт своё ядро; Alpine остаётся аварийным вариантом.
4. Появляется обязанность: **следить за конфигом** как за кодом — изменение опций = изменение
   поведения, и это должно быть видно в diff.

## Риски

- Конфиг минимальный «на глаз»: аудит включённых опций не проводился. Лечение — отдельный проход
  «что включено и зачем», с удалением лишнего.
- Воспроизводимость зависит от версии тулчейна (gcc, binutils, flex, bison). Пока не фиксировались.
- Своё ядро надо обновлять вручную при выходе патчей LTS; автопроверки нет.
