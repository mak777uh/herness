# ADR-0014 — VecDHT, LexSpec и Morphogenesis как подсистемы харнесса

Дата: 29.10.2026. Статус: принято владельцем. Дополняет ADR-0003, ADR-0008, ADR-0013.

## Что сказано

Три репозитория — VecDHT, Project Morphogenesis (`-`) и LexSpec — будут **частью харнесса**, а не
соседями. Значит их надо предусмотреть в архитектуре сейчас, даже если подключение позже.

## Что каждый из себя представляет (по их собственным документам)

| проект | предмет | что уже даёт |
|---|---|---|
| **VecDHT** | p2p семантическая рендеву: канонический байт, шарды, подпись, PoW, denylist | адресация записей и поиск пира по смыслу; 85 % готовности, p95 117–257 мс на стенде |
| **LexSpec** | юридические утверждения, которые можно проверить: позиции Хохфельда, якоря на точный span в закреплённой редакции, закрытый словарь отказов | вердикт над тройкой `(statement, encoding, corpus@revision)` + `not_claimed`; правило «anchor or refuse» |
| **Morphogenesis** | исследовательский стенд NCA: минимальный цифровой мир, вопрос о сохранении линии | пре-регистрация экспериментов, артефакт под каждым числом, `docs/eliminations.md`, Lean-доказательства гейта |

## Рамка: три вида истины

Это не три инструмента, а три ответа на три разных вопроса:

| вопрос | вид истины | кто отвечает |
|---|---|---|
| это те же самые байты? | **идентичность** | VecDHT (канонический байт, sha, подпись) |
| так ли написано в норме? | **нормативная** | LexSpec (span, якорь, покрытие) |
| это следует из прогона? | **эмпирическая** | Morphogenesis (пре-регистрация, артефакт) |

Харнесс — это плоскость, где все три сходятся. Поэтому интеграция не «добавить три пакета», а
**взять у каждого его правило проверки** и применять ко всем артефактам харнесса.

## Что берём конкретно

| из | правило | где в харнессе |
|---|---|---|
| VecDHT | канонический байт: два независимых кодировщика дают одинаковый id | адресация артефактов (sha256 уже есть) + канонизация схем событий |
| VecDHT | admission-политика: квота, PoW, denylist, отзыв ключей | приём внешних записей и отзыв скомпрометированных |
| LexSpec | **anchor or refuse**: нет однозначного якоря — не утверждение, а другой продукт | каждое правило политики (allowlist, траты, публикация) обязано иметь якорь |
| LexSpec | закрытый словарь отказов: новый код = новый дефект | коды ошибок харнесса перестают быть строками, становятся реестром |
| LexSpec | вердикт относителен: «проверено против X в редакции R, покрытие N %» | формат вердикта прогона (уже в `core/contracts.verdict`) |
| Morphogenesis | пре-регистрация до прогона: порог нельзя придумать после | `lab/hypotheses`, `lab/experiments` (уже принято) |
| Morphogenesis | у каждого числа — артефакт и команда | гейты и отчёты (уже принято) |
| Morphogenesis | отрицательный результат — первоклассный документ | `docs/eliminations.md` (уже принято) |

## Контракт встраивания

1. **Только через процесс и контракт.** Никакого вендоринга кода: `subprocess` + версионированный
   CLI/API. Это P21: граница файлами, а не зависимостями.
2. **Версия пинится коммитом.** В записи прогона фиксируется не «lexspec», а `lexspec@<sha>`.
3. **Отказ подсистемы не роняет харнесс.** Нет LexSpec — политика работает в режиме `unchecked` с
   явной пометкой; нет VecDHT — рендеву отключено, а не «падает».
4. **Данные ходят файлами.** Артефакты, реестры, манифесты — файлы с дайджестами, не RPC-потоки.

## Куда встаёт по слоям

```
L1 помощник (Rust)      — без изменений
L2 цикл и журнал        — берёт канонизацию и коды отказов
L3 инструменты и гейты  — LexSpec: политика как проверяемые утверждения
L4 оболочки             — без изменений
    рендеву             — VecDHT (ADR-0008), отдельный путь
    эволюция            — Morphogenesis как стенд самоизменения (M10)
```

## Порядок и критерии

| этап | что | критерий готовности |
|---|---|---|
| I1 | канонизация схемы события: одинаковый вход → одинаковый id | два кодировщика (Python/Rust) дают один sha |
| I2 | реестр кодов отказа с тестом на каждый | новый код без теста → гейт падает |
| I3 | политика как утверждения с якорем | правило без якоря → отказ публикации |
| I4 | рендеву VecDHT (T2 из ADR-0013) | пир найден, адрес получен, сообщение доставлено другим путём |
| I5 | стенд эволюции: вариант харнесса → прогон → вердикт | вариант без пре-регистрации не запускается |

## Риски

1. **Три незрелых проекта тянут каждый своё.** VecDHT не выпущен, LexSpec в v0.1, Morphogenesis —
   стенд. Встраивание может замедлить харнесс сильнее, чем ускорить.
2. **Разъезд словарей.** У LexSpec коды `S2_*`, у нас свои; нужно сопоставление, а не копирование.
3. **Соблазн объединить репозитории.** Тогда исчезнут независимые границы и возможность
   проверить одно другим. Границы сохраняем.
4. **Правило «anchor or refuse» строже, чем нам удобно.** Оно потребует якорей там, где мы привыкли
   писать прозу — это цена, и её надо принять сознательно.

## Что это не доказывает

Что все три подсистемы доживут до v1. Что интеграция через процесс не окажется медленной. Что
LexSpec-якоря применимы к техническим политикам (allowlist), а не только к правовым текстам.
