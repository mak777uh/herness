# Аудит совместимости: общий контракт записи

Этот файл — не предложение переписать репозиторий. Это перечень того, что **уже** совпадает по смыслу и
расходится по форме, и что нужно согласовать, чтобы один валидатор читал артефакты всех шести репозиториев.

## Зачем

Шесть репозиториев одного владельца ведут одну дисциплину: артефакт важнее прозы, отрицательный результат
публикуется, отказ имеет код, результат закрывается записью, а не памятью. Формы при этом разные: `refutes`
и `not confirmed` и `withdrawn` — один смысл в трёх написаниях. Пока это так, кросс-репозиторное чтение
делается глазами, а автоматическая проверка невозможна.

## Что лежит рядом

- `portfolio-0.1.json` — пять форм: `evidence_type`, `refusal_code`, `case`, `metric_row`, `elimination`.
- Схема намеренно узкая: она описывает **запись результата**, а не предмет. Вердикты замыкания, якорения,
  стоимости атаки и научные гипотезы остаются у каждого свои.

## Что нужно решить всем шести

1. **Три вердикта кейса.** `confirmed` / `not confirmed` / `could not tell` — принимаются как общие.
   Локальные словари (`refutes`, `withdrawn`, `killed`, `REFUSED`) остаются, но обязаны отображаться в эти три.
2. **Статус строки метрики.** `logged` (есть дайджест), `no_log` (прогон был, лог не сохранён), `not_run_here`
   (в этой среде гейт не запускался). Третий статус — самое важное: без него «зелёно» и «не проверялось»
   выглядят одинаково.
3. **Код отказа с ремедием.** `code/means/remedy`, код — `^[A-Z][A-Z0-9_]{2,31}$`. У lexspec это уже почти
   так; остальным — привести.
4. **Элиминация с условием возврата.** Гипотеза + артефакт + что её вернёт. Без третьего поля это не
   элиминация, а мнение.
5. **Авторство кейса.** `third_party: true|false` — иначе «сторонний прогон» отличается от авторского только
   прозой.

## Этот репозиторий

У вас пять типов результата и правило закрытия, проверяемое машинно (`bin/lab.py validate`), плюс `refs` — механизм чтения первоисточника с дайджестом.

**Что согласовать:** словарь статусов (`retro`, `case`, `withdrawn`, `killed`) — привести к общему `case.verdict` + полю `closure` (каким из пяти типов закрыто). Ваше различение `observation`/`measurement` — это ровно `metric_row.status = not_run_here`, только названо иначе.

**Что взять у вас остальным:** правило «у каждого принципа есть негативный тест» — этого нет ни у кого, кроме вас.

## Порядок

Этот файл и схема — предложение, а не правка чужих правил. Принятие: заменить локальную форму на общую там, где они совпадают по смыслу, и оставить предметные различия. Валидатор появится в flowguard-spec и будет читать `audit/portfolio-0.1.json` из любого репозитория.
